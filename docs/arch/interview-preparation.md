# 面试准备、AI 会话与面经研究

当前实现以 [034 规格](../../specs/034-ai-sessions-and-projects/spec.md) 为准。个人面经保留结构化整理与审核；项目练习统一为 AI 会话，不再维护项目档案、快照、回答修订、项目知识项或上传材料。

## 模块与执行职责

user 负责画像、会话、项目关联、面经及研究用例；common 提供模型客户端、调用账本、通用文件存储和中央任务运行时。CLI/Web 仅提供入口和依赖装配。AI 回复和系统研究通过中央任务服务执行，页面离开不会终止任务。

## 项目与画像

profile_versions 的明确一级属性分别存列，集合按各自 JSON 列保存。projects 中的 id 为稳定身份，local_path 仅关联用户已有项目的位置；编辑和排序保留身份，重新提取由系统匹配项目并保留路径，模型不能赋予路径。

记录路径不上传、复制、索引或自动读取项目文件。路径不存在不会阻断对话。删除项目或画像清除 ai_session_metadata 中失效关联，保留已有会话及消息；后续对话继续使用消息历史。

再次提取画像创建候选，用户预览并选择一级字段确认；确认时核对当前版本，不自动覆盖人工修改。不保留 extracted_json、effective_json、locked_paths_json 整图副本或字段锁。

## 会话与消息

- ai_sessions：id、type（interview/chat）、title、created_at、updated_at；一个会话就是一次模拟或日常对话，不设置暂停、完成或截止状态。
- ai_messages：独立用户/助手消息、顺序、当前内容及生成状态。用户编辑覆盖原内容，已有后续回复不自动改写。
- ai_session_metadata：独立 id、session_id、name/value 及时间；可选 profile_id/project_id 保存在此，session_id/name 唯一。没有 context_json 或消息 metadata_json。
- model_requests.ai_message_id：可空指向助手消息；一次回复的协商与模型请求可关联同一消息，删除消息只解除关联，不删除计费与诊断账本。

发送消息在短事务内保存用户消息、创建助手占位及发布 ai.reply。每个会话只允许一个待生成回复；模型调用在事务外。提交时重新计算当前消息与项目事实的指纹，拒绝编辑、取消或关联变更后迟到的回复。失败消息可以重试，新一轮对话会撤销旧失败回复，避免旧任务随后插入内容。

## 个人面经

个人面经继续支持文本或文档整理、草稿编辑、审核接受与删除。interview_experiences 与 interview_question_entries 保存最终业务内容；这与项目文件管理是不同场景，用户上传的个人面经不用于自动读取本地项目。

## 网友面经研究

创建 Brief 后生成 interview.experience-research 父任务，保存冻结输入及导入检查点。父任务等待外部交付时不占执行器，也不轮询文件。用户可复制 Prompt/Schema，交给系统之外的 Agent；结果位置固定为数据根目录下 research-results/<taskId>/result.json。

系统执行时发布关联的 interview.experience-research.execute 子任务。配置模型模式由系统受限采集公开网页再提供证据给模型；Codex/Claude 本地执行器使用其隔离研究流程。执行结果由适配器原子写入指定文件，然后进入与用户“检查结果文件”相同的校验和导入用例。系统模型不会获得数据库或整个数据目录的写权限。

文件必须是非空普通文件、UTF-8 JSON 且不超过 2 MiB；拒绝符号链接、目录逃逸、错误 Schema/Brief 指纹、不符合约束的公开来源。输入文件读取、模型调用和通用文件写入不放入业务事务，最终事务核对修订、导入声明及任务执行权。重复检查相同内容返回原候选，不重置审核或新增问题。

导入成功即完成父任务，候选审核单独保存在面经记录。已接受候选不能被后续研究静默覆盖；全部拒绝后可以再次执行。模型执行子任务可取消或重试；导入事务已提交但执行器崩溃时，重试复用提交结果。

研究过程不再建 experience_research_requests 表。interview_experiences.research_task_id 为 tasks 的可空外键，删除任务不删除面经、来源、问题和审核结果。任务工作台通过“查看研究流程”进入业务操作，用户无需理解阶段私有状态。

## 当前模型上下文边界

AI 回复每次装配会话类型、当前可选项目事实和目标回复之前已完成的消息。项目事实仅含名称、角色、描述与日期；不包含本地路径、项目文件、独立知识条目或自动检索的面经。用户和助手历史作为有角色的数据输入，系统提示词要求将其视为数据。

目前采用完整历史输入，没有滚动窗口、摘要记忆、检索增强或跨会话记忆。ai.reply 的预算为输入估算 24,000 tokens、输出 4,000 tokens、90 秒、单次执行一步。超出输入预算时明确失败，不会偷偷截断或生成摘要；更完整的上下文策略需要另行设计。

对话 Agent 禁用结果缓存和额外输出副本；任务输入只保存 sessionId/messageId。模型账本保存诊断、用量及消息关联，不另存历史用户回答正文。研究上下文则使用冻结 Brief、来源策略和采集到的公开网页证据，不自动将研究结果注入 AI 会话。
