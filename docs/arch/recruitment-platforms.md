## 1. 统一事实，分开获取流程

猎聘复用既有一次 CDP 初始化和独立 HTTP 机制：当前支持学生首页推荐模板，首次 LOGIN、续批 UP；CLI／Web／Worker 和统一职位页已装配。外部 Chrome 原生 CDP 的真实限量验收通过：首批 39 条中 24 条有效职位全部补齐详情并入隔离库，15 条缺少公司 ID 排除计数；同会话续批返回有效末批，26 次独立 HTTP 最小间隔 5000ms。首批经过真实 CLI、生产 Worker 和 Web 应用查询，续批直接调用同一生产会话；不等同于线上 Web UI、多轮非空分页或长期稳定验收。内置浏览器现已暴露完整 CDP，但猎聘页面检测命中后主动跳转 about:blank，其兼容问题仍未解决；外部 Chrome 是用户明确允许的替代路径，不禁用官网检测。详见 028 的 PLT-T022，平台保持 experimental。

BOSS 按 [ADR-0031](../adr/0031-boss-explicit-browser-assisted-transport.md) 增加显式 browser 模式：官网正常操作维护会话并产生 JSON，Worker 观察所选页响应，复用协议校验及批次入库，不导出 Cookie 或重复发独立 HTTP。该模式保留页面监听；首次列表来自连接后的正常筛选，详情仅操作当前批次职位链接，至少间隔五秒，不刷新或后台翻页。原 HTTP 默认行为保留，失败不自动切换。CLI 先提供选择；整批实测通过前不开放 Web 选项、不宣称稳定。

按 [ADR-0030](../adr/0030-platform-batch-ingestion-and-job-list.md)，一次显式批次获取自动串行补齐所有候选的必需详情，完整职位逐条入库；异常停止后续请求，已提交数据保留。统一“职位”页按来源类型及 provider 查询，默认官网；平台默认全部招聘类别。来源页仅保留连接、批次动作和结果摘要，不再承担另一套职位列表。无需迁移，网络与短事务边界、平台缺失不下架、原清理策略均不变。

前程无忧使用 [ADR-0029](../adr/0029-job51-observed-batch-session.md) 的官网辅助模式：所选页面持续只读监听，用户实际翻页提供原始签名模板，显式读取时独立 HTTP；不修改签名或自动翻页。完整列表正文可直接供详情入库，持久化仍走通用应用和仓储。该例外不改变其他平台初始化后 detach 的机制。

智联连接采用 [ADR-0028](../adr/0028-zhilian-observed-request-template.md)：按所选目标页固定校园推荐或主站搜索。校园监听正常分类切换的 POST；主站监听正常搜索及详情双模板，通过边界校验即停止监听；后续列表和详情均独立 HTTP、至少间隔 5 秒、失败冻结。Worker、CLI 和 Web 复用既有 provider 隔离与来源身份，不新增数据库或浏览器进程；查询变更须显式重新连接。

多平台隔离及可见详情交互采用 [ADR-0027](../adr/0027-platform-isolation-and-view-activity.md)：provider 绑定连接、任务和身份命名空间；Web 仅通过应用端口同步记录短本地交互，自动清理仍由 Worker 执行。后续范围为智联、前程无忧和猎聘，未实现连接器不暴露可用能力。

官网：计划触发 → 完整或部分同步 → 统一职位写入 → 仅完整覆盖时允许缺失判断。

招聘平台：用户请求 → Worker 读取一页 → 串行补齐该页必需详情 → 逐条统一职位写入。列表已有完整正文时复用已校验事实，不依赖点击详情或收藏。切换查询、取消或失败后不继续请求，不自动翻页。

正式职位均复用 jobs、job_revisions、job_observations、匹配及求职业务，不建立平台临时职位表。摘要仅是尚未达到质量要求的请求工作集，不能向匹配层伪装成完整职位。前端显示任务执行、成功批次入库计数和失败状态，职位内容统一通过职位页读取；失败和取消保留已提交数据。

## 2. 模块与依赖

| 模块                         | 所有权                                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| packages/platform-core       | 平台元数据、能力、候选、分页结果、错误与传输契约；不依赖数据库或浏览器                                |
| packages/platform-connectors | boss、zhaopin 协议和边界 Schema；session 中的内存凭据与 CDP 实现；transport 中的受限 HTTP／浏览器实现 |
| packages/application         | 连接、浏览、详情、正式写入和清理用例；声明会话、浏览工作集和仓储端口                                  |
| packages/domain              | 来源类别、职位身份和纯生命周期规则，不包含会话令牌                                                    |
| packages/db                  | 来源迁移、统一职位仓储、观察与清理事务                                                                |
| apps/worker                  | 装配上述端口、执行短任务、管理取消与退出                                                              |
| apps/web                     | 提交请求、展示进度和持久职位，不持有 Cookie 或执行平台网络请求                                        |

基础设施实现应用端口，应用不得反向导入平台实现。跨包只能使用公开入口；避免为复用而将官网私有浏览器代码导入平台包。首版直接在 Worker 使用已有 Node/Playwright 能力，不复制 BossHunter 的独立通用 HTTP-CDP 代理，不新增微服务。

## 3. 身份与数据所有权

- 提供方是 BOSS／智联；物理来源例如 boss 推荐入口，不是招聘公司。
- 公司来自职位字段；平台公司 ID 在提供方命名空间内映射到 companies。同名不自动合并官网公司；缺少可靠身份时允许隔离待解析，不凭名字猜测关联。
- 职位业务去重键为物理 source_id + 稳定 external_job_id，不能使用 securityId、追踪参数或标题作为身份。相同职位可在不同查询中出现，数据库已有不代表从浏览结果隐藏。
- 个人连接是会话与推荐上下文的隔离单位，不是每次搜索的新来源；首版本机单用户，每个平台一个活动连接，不引入账号池。
- 同一条职位被不同来源发布时保持独立事实，后续可以关联，不在首版强合并。

目标迁移细节见 [028 设计](../../specs/028-recruitment-platforms/design.md)。官网稳定 ID、三渠道目录和多物理映射不变。

## 4. 最小会话借用

连接必须由用户发起并选择浏览器实例；禁止扫描后自动连接第一个可用配置。CDP 仅连接已核验的本机回环端点，按允许域名选择页面和 Cookie；不读取其他网站、完整 LocalStorage 或浏览器磁盘 Cookie 数据库。必要数据由逐平台协议实验确定，不将目前 11 个 Cookie 宣称为最小集合。

会话凭据保存在 Worker 内存，由 sessionRef 与 sessionGeneration 引用；不写任务 payload/result、SQLite、事件、日志、异常、备份或模型输入。持久配置仅含非敏感连接选项和脱敏状态。请求中的个性化期望标识与职位访问参数也留在有界内存工作集中，原始 URL 的敏感查询参数不得作为来源链接保存。

认证会话、查询上下文与单职位访问参数三者分离。按 [ADR-0026](../adr/0026-platform-cdp-session-lifetime.md)，浏览器提供必要认证与初始化上下文后 detach 页面，保留本次授权的空闲 CDP WebSocket，直到显式断开、替换或 Worker 退出。HTTP 使用列表实际返回的访问参数读取详情，不默认复用旧页面参数；HTTP 失败冻结请求，不自动重连。浏览器退出或连接异常使当前会话失效、清除 HTTP 凭据，但不等于平台账号已登出；不保证浏览器登出后 Cookie 立即撤销。显式断开使 generation 失效、取消在途请求、清除工作集和凭据；迟到结果提交前必须再次核对 generation。已经正式保存的职位不随断开删除。

连接状态为 disconnected、available、login_required、verification_required、cooldown、unavailable。浏览器控制是否可用是独立诊断。状态来源于实际响应，不能把 Cookie 存在当成认证成功，也不能把网络失败或未知业务码归为未登录。

明确认证失效时最多重新同步一次必要会话；浏览器提示或验证交给用户。限流、验证和访问拒绝停止相关操作；禁止签名伪造、指纹修改或切换传输规避限制。进程重启后内存会话失效，任务提示重新连接，不无限重试。

## 5. 浏览与详情短任务

能力按 search、recommend、next、detail 独立验证和记录 supported 状态；supported 是协议能力，不是当前账号状态。BOSS 首版从 recommend 开始，智联后续验证；不得由搜索成功推断推荐可用。

持久任务只包含 connectionId、generation、browseId、queryVersion、步骤和不透明候选引用。敏感游标及请求模板由 Worker 内存管理；浏览结果中的完整职位以 jobId 引用，待详情摘要按允许字段作有界进度投影且随任务保留规则清理，不成为第二职位库。Web 复用任务进度读取机制。首版单 Worker，重启后工作集丢失，旧浏览任务明确结束为需要重新开始，不恢复私有游标。

每次请求最多一批；同一 browseId 的下一批串行、重复请求合并，平台连接共享限流预算。平台实际返回的新增稳定 ID 用于判断前进；hasMore 与空结果冲突、重复批次、未知格式均不得冒充末页。查询版本变更后停止旧请求，旧响应不覆盖当前列表。显式取消之后不发起后续详情或翻页。

HTTP 请求有超时、响应大小上限和严格域名允许列表，不自动跟随携带凭据的重定向。Cookie 保留域、路径、Secure、过期等匹配语义，不将实验用拼接 Cookie Header 直接产品化。浏览器读取只允许预定义平台操作，不对 Web 或模型暴露任意脚本执行。

## 6. 正式职位、状态和修订

归一化网络处理在事务外；短事务原子 upsert 职位、必要修订、观察与状态事件。标准化内容不变不新增修订。保留既有职位正文与身份门槛，禁止把摘要或错误文本写成 JD。单条详情失败不阻断已成功记录入库，也不删除其旧正式版本；显示失败原因与可用旧版本的核验时间。

平台按需请求永远不声明覆盖整个来源，不写官网 sync_seen_jobs，也不推进 missing_count。明确关闭响应可以更新旧职位；没有再次推荐、列表排序变化、详情超时或未分类错误不能关闭职位。陈旧是时间派生的核验提示，不新增或伪造上游 closed 状态。

匹配只读取合格的正式事实，沿用简历版本、职位修订和规则版本隔离；不因保存一页职位自动启动无限模型评分。求职操作在原站由用户完成，首版无自动发送、投递、聊天与简历上传。

## 7. 正常保留清理，不是缓存淘汰

平台职位与官网职位都是正式记录。平台使用独立的保留时长和检查频率，但复用运维清理入口、dry-run 和引用保护；更频繁检查不能替代更短保留期限。建议首版策略候选为每 6 小时检查、连续 30 天无有效核验且无用户交互的无保护职位可清理；这只是可配置建议，自动删除默认关闭，用户确认并启用后执行，既有官网规则不变。

活跃基准取最近成功核验、用户明确浏览／操作和创建时间的最大值；后台失败、清理扫描和自动评分不延长保留。收藏、投递跟踪、面试准备、用户笔记及当前任务引用优先保护。删除计划列出保留原因、可删数量和估算空间，执行短事务内重检引用及活跃时间，防止计划生成后新增收藏被误删。

按外键与推导关系清理匹配、允许删除的修订、观察和职位；受保护历史引用不级联损坏。记录 cleanup 原因与脱敏计数，不生成平台下架事件。以后再次获取可重新建档，不无限保留完整被删快照。SQLite 删除后空闲页可复用；物理缩小仍按 ADR-0020 备份、互斥与阈值维护，不每轮 VACUUM。

## 8. 验证边界

离线验证覆盖迁移、幂等、正文门槛、代次隔离、取消、异常分类和清理竞态。在线只做两至三批列表和少量详情；动态推荐不具备稳定末页时不套用官网首尾页门禁。需要详情能使用本次 HTTP 列表参数闭环，并核验身份与正文；业务码 37 未分类前不能将 BOSS detail 晋级 supported。
