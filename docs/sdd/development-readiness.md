- 用户确认的 TypeScript、模块化单体、SQLite、独立 Worker、插件式官网适配器和 SDD。

- 10 家目标企业官方招聘来源。
- 简历画像、职位匹配、建议 Agent、可视化管理台与个人本地运维。
- 总体架构、专题架构、ADR、规格三件套和来源调研证据。

## 5. 来源调研风险

调研证明了来源风险，但不构成设计阻塞：

- 腾讯、拼多多可作为两种参考适配器。
- 字节、美团、小红书、京东有公开入口和页面结构，但需要开发 Spike 确认稳定请求及覆盖度。
- 阿里、百度、得物、华为在当前环境存在空内容、路由不确定、连接关闭或客户端拦截。

规格已经定义：只有通过匿名公开访问、稳定 ID、分页完整性、官方 URL 和固定样本门禁的来源才能标记 supported；外部阻断必须标记 blocked，禁止通过规避访问控制来“完成”任务。blocked 仅记录现实状态，不等价于交付完成；若 R1 无法支持该来源，必须先批准范围例外并明确调整 R1 范围。因此可以开始开发公共契约与参考来源，同时保留对全部 10 家的真实交付目标。

当前阿里巴巴、百度和华为的证据及重新进入条件已记录在 [首批来源范围例外记录](../../specs/006-first-party-sources/scope-exceptions.md)；该记录尚未改变 R1 范围，因此 Gate 4 仍不视为通过。

## 6. 正式开发顺序与阶段门禁

### Gate 0：工程可运行

通过：根 `check`、包边界、普通离线测试，以及 Windows PowerShell 和 Git Bash POSIX 实跑均通过。

### Gate 1：数据内核可验证

通过：001–005 的实现、集成测试和 FakeAdapter 端到端路径已存在并通过。

### Gate 2：参考数据可用

部分通过：腾讯和美团已通过 supported 门禁并注册默认 Registry；拼多多的公开列表请求依赖不可伪造的 `anti_content`，保持 experimental，Gate 2 不宣称完成。

### Gate 3：Agent 匹配闭环

通过：007–010 及 012 的确定性路径、FakeModel 集成测试和配置模型 Provider 已通过；`.env` 别名的最小线上结构化 Smoke 也已通过。

### Gate 4：首批来源完成

未通过：腾讯、美团已 supported；京东因重复 ID 保持 partial/experimental；拼多多、字节、小红书、得物仍 experimental；阿里、百度、华为有范围例外并 blocked。范围例外未改变 R1，因此 Gate 4 不视为通过。

### Gate 5：Web 可用

通过：011 的 loopback、核心 Playwright E2E、响应式/键盘/语义和 axe 门禁已通过；耗时动作只入队。

## 7. 当前实现后的推进顺序

基础实现已经完成，后续变更应继续按 SDD 的局部闭环推进：

1. 仅在取得合法、可复现的匿名公开证据后推进 006 中的 experimental 来源；遇到验证码、登录、风控参数或客户端阻断时记录 evidence 并安全降级。
2. 对已 supported 来源维持低频在线 Smoke，并在官网变化时优先更新来源局部规格、固定样本和契约测试。
3. 任何改变依赖方向、数据所有权、进程职责或核心技术选型的变更，先补 ADR/架构，再实现代码。

不得为了清空 tasks.md 而把 experimental、blocked 或 partial 误标为完成。

## 8. 当前判定

工程实现已经达到可验证的主链路状态：整体边界、数据库、Worker、Agent、匹配、CLI、Web 和运维能力均有代码与测试证据。首批来源 Gate 4 仍未完成，因此不能将整体项目标记为完成；当前状态应保持 `Implementation in progress`。

开发中的局部发现可以按 SDD 变更流程更新 design/tasks；若改变架构、数据所有权或可观察行为，必须先更新 ADR/架构或 spec，再修改实现。
