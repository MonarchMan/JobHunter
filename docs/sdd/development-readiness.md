## 5. 来源调研风险

调研证明了来源风险，但不构成设计阻塞：

- 腾讯、拼多多可作为两种参考适配器。
- 字节、美团、小红书、京东有公开入口和页面结构，但需要开发 Spike 确认稳定请求及覆盖度。
- 阿里、百度、得物、华为在当前环境存在空内容、路由不确定、连接关闭或客户端拦截。

规格已经定义：只有通过匿名公开访问、稳定 ID、分页完整性、官方 URL 和固定样本门禁的来源才能标记 supported；外部阻断必须标记 blocked，禁止通过规避访问控制来“完成”任务。blocked 仅记录现实状态，不等价于交付完成；若 R1 无法支持该来源，必须先批准范围例外并明确调整 R1 范围。因此可以开始开发公共契约与参考来源，同时保留对全部 10 家的真实交付目标。

## 6. 正式开发顺序与阶段门禁

### Gate 0：工程可运行

完成 000。根 `check` 通过，包边界检查生效，普通测试完全离线。

### Gate 1：数据内核可验证

完成 001–005。FakeAdapter 可以端到端证明新增、重放、修订、partial、关闭与恢复。

### Gate 2：参考数据可用

完成腾讯和拼多多来源门禁。通过受控在线 Smoke，并能用 CLI 查询标准化职位。

### Gate 3：Agent 匹配闭环

完成 007–010 及 012 必需部分。导入脱敏测试简历后，可离线 FakeModel 端到端匹配，并在有模型配置时生成有效建议。

### Gate 4：首批来源完成

完成 006 全部公司任务，且当前 R1 范围内每家都必须有证据地通过 supported 门禁。blocked 来源的实现任务保持未完成；只有先批准范围例外并同步修改 R1 范围后，才可在不包含该来源的基线上重新评估 Gate 4。

### Gate 5：Web 可用

完成 011。所有耗时动作只入队，核心 Playwright E2E、loopback 和无障碍门禁通过。

## 7. 第一批开发任务

正式开发从 `ENG-T001` 开始，建议第一批变更只包含：

1. `ENG-T001` 根 package、workspace、Node/pnpm 约束和锁文件。
2. `ENG-T002` 严格 TypeScript 与包模板。
3. `ENG-T003` 格式、lint、类型和测试命令。
4. `ENG-T004` 依赖边界检查。
5. `ENG-T005` 测试分层与 testkit 基础。
6. `ENG-T006` ignore、环境示例和秘密扫描。
7. `ENG-T007` 将本次人工文档审计自动化，包括动态发现 `specs/` 下的编号规格目录。

Gate 0 通过前不应并行铺开公司适配器或 Web 代码。

## 8. 最终判定

文档基线已经达到正式开发条件：整体边界、首期范围、表结构、核心算法、外部风险、验收条件和实施任务均有权威落点，且没有需要产品选择才能继续的未决问题。

开发中的局部发现可以按 SDD 变更流程更新 design/tasks；若改变架构、数据所有权或可观察行为，必须先更新 ADR/架构或 spec，再修改实现。
