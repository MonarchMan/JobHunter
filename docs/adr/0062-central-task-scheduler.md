# ADR-0062：CLI 与 Web 共用中央任务调度服务

- 状态：Accepted
- 日期：2026-11-05
- 实施：中央服务、多进程执行、扫描阶段任务和维护门控已实现；实际数据迁移仍遵循三阶段实施顺序，验收见 specs/003-task-worker/tasks.md。

## 背景

目前 CLI 和 Web 分别装配公共任务运行时，每个运行时都可以启动调度与领取循环。复用实现不能保证同一数据目录只有一个调度者。两个入口应共享执行服务，由一个中央调度者管理多个执行进程。

## 决策

1. 以规范化后的本地数据目录为服务实例边界，启动一个独立于 CLI/Web 生命周期的中央任务服务。入口通过 common 客户端连接服务，并使用统一任务应用端口提交、查询、取消、重试及等待，不再启动任务领取循环。业务事务可以直接通过仓储端口持久化发布任务，保证业务记录与入队原子提交；轻量外部客户端也可使用 IPC 命令。
2. common 提供服务发现、启动协调、本机 IPC、调度、执行进程管理和恢复机制；业务模块提供处理器及周期配置查询契约。apps 保留组合根，通过内部启动模式装配四模块，不恢复 apps/worker 包或公开 worker 命令，common 不导入业务实现。
3. 首次连接时使用跨进程启动锁，持锁后再次探测服务再决定启动；服务全生命周期持有单实例所有权。不能只凭 PID 文件或心跳超时认定旧调度者已经退出。Windows 与 Unix 通过平台适配器提供等价锁和本机 IPC。
4. 中央调度者统一队列、并发键、定时触发、退避、超时与取消；多个执行进程仅接受分派，不直接领取数据库任务或生成周期任务。任务类型的慢任务不得阻塞其他类型分派。
5. 每次分派生成唯一凭证，检查点和业务结果提交必须验证当前服务代次及分派凭证。执行超时后撤销旧凭证并取消旧执行，再按策略分派。业务结果与检查点可在同一 SQLite 事务提交时必须原子提交；仅拒绝旧执行者更新 tasks 不足以保护业务结果。
6. 服务重启取得排他所有权后撤销旧分派，从已提交检查点恢复未完成任务。旧执行进程在控制连接断开后停止工作；即使随后返回结果，提交门控仍拒绝。外部调用不能承诺恰好一次，继续依赖业务幂等与输入有效性校验。
7. 定时触发由中央调度者专用循环读取来源、邮箱和系统设置中的周期配置，每个 occurrence 创建独立任务；周期配置已经迁入 application_settings，去除 schedules 专表及 tasks.schedule_id。时间解释、最近一次错过周期补执行及 occurrence 幂等语义保留。
8. sync_runs 合并为 tasks 中的 source.scan 阶段任务，parent_task_id 关联主任务；全量重扫创建新阶段，主任务终结或撤销时取消未完成阶段。输入、恢复状态和结果分别按任务类型组织，保留覆盖判断和扫描身份；从头重扫更换扫描身份，重试评分复用已完成采集。同步 version/hash/cursor 冗余列不机械搬入状态 JSON。
9. 任务目标存储采用 type/status、public_state/private_state、幂等与并发标识及必要时间字段。恢复由任务 ID、处理器类型和检查点完成；不凭名称新增 recovery_key。原每任务数据库租约列是否被分派凭证替换，在实现提交门控与崩溃恢复协议时确定，不能先删除执行权保护。

## 影响与验收

覆盖 ADR-0003 的多运行时领取与 Web 拉起 Worker 生命周期，以及 032 规格中入口内嵌执行循环的部分。ADR-0061 的同步分阶段业务语义保持，执行权改由中央分派管理。现有数据库和实现不因本决策文件改变。

验收包括：CLI/Web 并发冷启动仅一个服务；CLI 退出和 Web 重启不终止后台任务；任务按类型独立并发；调度者或执行进程退出后正确恢复；旧分派不能写业务结果；定时重启不重复触发；不同数据目录相互隔离；配置或协议不兼容不能静默启动第二套服务。
