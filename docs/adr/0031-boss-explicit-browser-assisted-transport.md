# ADR-0031：BOSS 显式浏览器辅助传输

- 状态：Accepted
- 日期：2026-09-20
- 关联：ADR-0026、ADR-0030、specs/028-recruitment-platforms

## 背景

BOSS 独立 HTTP 可以取得成功响应，但整批仍可能返回 SECURITY_CHECK（37）。同轮对照确认：官网正常请求后安全令牌更新，独立 HTTP 收到检查参数后浏览器令牌不会自动更新。重复读取浏览器 Cookie 不能替代官网对响应的处理。具体服务端风险规则不公开，不承诺消除所有 37。

## 决策

增加显式 `browser` 传输模式，原 `http` 模式保留为默认兼容行为。连接代次固定模式，不允许收到 37 后切换模式重试。浏览器辅助模式由官网正常页面操作发出请求并维护安全状态，Worker 只观察选定页面两个职位 JSON 端点的实际响应，复用现有严格解析与统一批次入库逻辑，不再以 Node HTTP 重复请求。

连接后，首次批次须来自一次正常官网筛选操作；不通过刷新、重新打开页面或读取私有框架状态补历史响应。只消费已观察的新页，不后台翻页。详情允许按本批稳定职位 ID 点击页面中对应的职位链接，不点击沟通、收藏、投递或验证控件；操作串行且至少间隔五秒。外部页面变化、跨域、身份不符、验证、限流、取消或超时均停止，已保存职位保留。浏览器辅助不会改变官网自身附带请求的频率。

同一授权 Socket 保持到显式断开，额外页面 session 与监听由会话清理；只观察固定端点，不导出 Cookie，不执行安全脚本，不改写原生能力，不转交独立 HTTP 的检查参数。协议解析不依赖浏览器；浏览器传输不进入应用或领域层。

## 验收与后果

先验证同轮一页全部有效候选 → 详情 → Worker → 隔离 SQLite → 统一查询；再验证限量前部新页和取消／部分失败。真实整批通过后才启动 12 小时、每 3 小时一次观察；缺失窗口或失败不算稳定通过。模式依赖已登录的所选页面和可用职位链接，后台静默纯 HTTP 不再是 BOSS 辅助模式的承诺。CLI 先显式提供模式，Web 权限说明与模式选择在该能力验收后开放，不暗改旧连接。
