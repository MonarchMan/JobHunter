# ADR-0032：BOSS 当前进程内显式恢复未完成批次

- 状态：Accepted
- 恢复次数上限由 ADR-0033 部分替代，其余上下文与身份边界保留。
- 日期：2026-09-21
- 部分替代：ADR-0030 中失败后只能重新开始的行为；保留失败即停、正式职位质量和 HTTP 默认。

## 背景

37 是安全检查响应，单条成功不证明整批稳定。已保存记录应保留；重新抓整页会重复访问成功详情。历史失败结果只有数量，无法定位失败职位，也不能从当前列表推断原顺序。

## 决策

1. 任务只持久化当前稳定职位 ID；成功事务原子清除。候选集合、securityId/lid、认证绑定继续由原 Worker 的原会话内存持有，不创建第二职位库。
2. 仅 BOSS HTTP 的批次详情 37 可保留最多十分钟的未完成集合。默认 next/detail 仍冻结；取消、断线、换代、重启、其他错误或超时不恢复。
3. 用户确认官网正常后，通过显式 resume 动作引用同代次原失败任务。连接器仅读取现有浏览器上下文：wt2、bst、token 必须存在，wt2/token 必须与失败时一致，安全 Cookie 必须已更新；bst 属于会随正常浏览轮换的请求认证，不作为固定绑定，但必须使用官网当前值。不把 Cookie 存在或更新当成服务端成功证明；稳定绑定不一致时拒绝，不能跨账号沿用候选。
4. 守卫通过后最多开启一次恢复尝试，使用同一 HTTP 传输，从未提交职位开始，不重抓列表、已保存详情或下一页。再次 37 即终止，不自动循环。未更新上下文时不发 HTTP，原批次保持冻结直至过期。
5. 原失败任务保持失败，恢复产生新任务及观察；结果只计本次剩余候选，并引用原失败任务。重试同一幂等令牌不重复执行。
6. 恢复诊断只持久化固定原因码：context_read_failed、auth_context_missing、auth_binding_changed、context_unchanged、resume_expired；不持久化上下文原值或未知异常原文。取消优先记录 cancelled。

## 边界与验收

这是恢复能力，不是风控绕过或“37 已修复”。不生成安全令牌、不回灌挑战 Cookie、不操作验证控件、不更换传输。先提供 CLI 与现有 Web 应用命令入口，不在未验证时加入 UI 自动恢复按钮。离线覆盖守卫、代次、过期、取消、断线和再次失败；线上恢复后仍须验证剩余批次及连续两批，才可声称整批闭环通过。
