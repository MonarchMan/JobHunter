# ADR-0030：平台批次自动补齐详情并统一职位列表

- 状态：Accepted
- 日期：2026-09-20
- 部分替代：ADR-0025 的摘要展示与单条详情触发入库交互；其余连接、安全和保留策略不变。

## 背景

平台在来源页展示摘要，点击详情才入库，与官网职位管理割裂。用户选择保持同一质量门槛和入库行为，而非引入摘要职位或待补全生命周期。

## 决策

1. 每次显式读取当前一页／一批，Worker 串行取得该批每个候选的必需详情并自动保存正式职位，不遍历全部页。获取前固定受支持的搜索条件与排序，推荐流不冒充搜索能力；未来连续采集须明确前 N 页及职位数上限，本次不新增连续采集。若列表 JSON 已包含经验证的完整正文，复用该正文，不增加形式上的详情 HTTP。
2. 网络在事务外；每条完整职位独立短事务提交，保留代次、取消、租约复核。任一详情失败立即停止余下请求，保留已提交职位，不写占位正文、不自动重试或自动读取下一批。沿用连接器请求节流。
3. “职位”页是唯一职位列表入口，默认 `source=official`，可切换 `source=platform` 并按 provider 筛选。官网默认实习；平台默认全部招聘类别，包括未知类别。列表、计数、分页和返回路径使用同一来源筛选。
4. 来源页保留连接及显式批次获取操作，仅展示任务、批次入库数量和统一职位页链接，不再展示另一套摘要列表或要求点击保存。旧 CLI 单条 detail 命令保留兼容，不再是入库前提。
5. 不迁移身份、不增加临时库或数据库表。平台缺失不推进 missing_count；已有清理规则和保护引用保持不变。列表刷新、切换筛选不访问上游。

## 取舍与验收

一次批次可能产生更多详情请求，耗时更长；界面必须明确自动补齐、串行执行及失败保留已入库结果。取消并非回滚已提交数据。历史任务没有入库计数时不得伪造成功数量。

验证自动保存、部分失败停止、取消与旧代次阻止写入；验证官网／平台及各 provider 的查询、计数与分页隔离，平台未知招聘类别可见。离线门禁与真实平台稳定性证据分开报告，不因交互统一而晋级 supported。
