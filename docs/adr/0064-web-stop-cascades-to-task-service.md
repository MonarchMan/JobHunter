# ADR-0064：Web 停止级联停止中央任务服务

- 状态：Superseded（运行生命周期与进程执行由 [ADR-0065](0065-single-host-dynamic-thread-pool.md) 替代；提交门控等规则保留）
- 日期：2026-11-06
- 关联：[ADR-0062](0062-central-task-scheduler.md)、[003 规格](../../specs/003-task-worker/spec.md) WRK-009/WRK-024

## 背景

ADR-0062 将任务执行隔离为独立生命周期的中央服务：CLI/Web 退出只断开客户端，任务继续后台执行。实际使用中用户以 Web 为系统唯一常驻入口——关闭 Web 后服务与执行进程继续调度任务并调用模型，产生不可感知的费用与网络流量；进程池按任务组重建执行进程还伴随 Windows 控制台弹窗（已由 windowsHide 修复缓解）。用户明确反馈"终止系统后仍有任务运行"不可接受，要求"我终止的入口就是系统的全部"。

曾评估将执行进程池改为 worker_threads 线程池：不解决根因（服务本身仍是独立守护进程，入口退出后照常运行），且失去进程级硬杀（45 秒 SIGKILL 心跳超时）与原生模块崩溃隔离（better-sqlite3、Playwright 段错误会连带调度者），故不采纳。

## 决策

1. Web 宿主收到退出信号（SIGINT/SIGTERM/IPC shutdown/Next 退出）时，在既有 stop 流程中追加调用 stopTaskService：向中央服务发送 shutdown 协议命令并等待其优雅关闭（停止分派、通知执行进程、等待安全点、释放数据库），默认上限 30 秒；超时记录日志后放行退出，残留执行权由下次启动的租约回收处理。
2. CLI 保持 ADR-0062 语义不变：命令退出只断开客户端，不级联停止服务。CLI 与 Web 对同一数据目录仍是同一服务实例；谁最后拉起不影响级联规则——Web 退出总是尝试停止服务。
3. Web 重启即服务重启：未完成任务在下次 Web 启动时由租约恢复与已提交检查点续跑，不依赖服务跨重启常驻。执行进程池保持多进程模型。
4. 显式管理命令 `task service status/stop/restart` 保留，作为强杀 Web 后回收服务的兜底。

## 影响

- Web 停止后系统完全静默：无任务执行、无模型调用、无后台进程；符合用户对"终止"的心智模型。
- 长任务（如模型评分批处理）在 Web 重启窗口中断，恢复依赖检查点与租约；任务幂等性（WRK-003 分派凭证门控）保证不重复消费。中断窗口内已发出的模型请求无法撤回，属既有语义。
- Web 频繁重启会放大任务恢复开销；后续如需要可再评估空闲自动退出（idle shutdown）作为补充。
- WRK-009 语义修订、WRK-024 新增，详见 003 规格与设计。
