# ADR-0010：面试准备数据与外部 Agent 边界

> 状态：Accepted
> 日期：2026-08-29

## 背景

JobHunter 计划增加简历项目拷打、个人面经导入和网友面经研究。该能力需要读取候选人画像中的项目、保存持续问答和项目资料，并可能调用 Codex、Claude Code 等本地外部 Agent 搜集公开资料。

如果直接把这些数据写回 CandidateProfile，用户回答、模型推导和网友陈述会失去来源边界；如果把外部 Agent 当作现有 Agent Core 的普通工具，它将获得与内部结构化模型调用不相称的文件、进程和网络能力。生成 Markdown 问答文档还会引入数据库与文件的双写权威风险。

## 决策

1. 面试准备作为独立业务边界，拥有 `ProjectDossier`、`DrillSession`、`InterviewExperience` 和 `ExperienceResearchRequest` 等对象。它只引用不可变 CandidateProfile/项目快照，不在拷打流程中直接修改画像。
2. 用户原始回答、用户提供资料、外部陈述、模型推导和运行记录分层保存。推导结果和网友陈述不得覆盖用户回答或简历事实。
3. SQLite 保存结构化权威状态；项目准备 Markdown 是由已提交数据生成的可重建投影。外部编辑只能通过显式导入和差异确认回到系统。
4. 深度拷打只读取用户显式选择并生成不可变内容快照的 Markdown 资料。内部拷打 Agent 不获得项目目录、源码、Git、Shell、任意文件或任意网络能力。
5. 外部 Agent 通过应用层 `ExternalResearchExecutor` 端口和 Worker 调用，由基础设施适配器封装供应商 CLI、SDK、认证和事件格式。外部 Agent 只能在受控临时目录产生待审核 Artifact，不能直接访问或写入业务数据库。
6. 公开面经研究的首个闭环是结构化 Brief/Prompt 导出和 ResearchBundle 导入。自动执行器是可选后续能力，不能成为项目拷打和个人面经导入的前置依赖。
7. 业务级 ResearchRequest 与单次持久化 Task 分离；内部 AgentRun 与外部进程执行记录分离。两类运行都必须保留版本、权限摘要、错误分类和结果引用。
8. 项目 Markdown 和已接受面经首期使用确定性分块与 SQLite FTS5 检索，不引入向量数据库或通用 Agent 编排框架；只有评测证明召回质量不足时再重新决策。

## 影响

- 需要新增面试准备领域模型、应用用例、仓储、Artifact 类型和 Worker Handler，但不改变现有职位同步、匹配和画像所有权。
- 用户可以获得可读 Markdown 文档，同时避免数据库和可编辑文件互相覆盖。
- Codex、Claude Code 等实现可以独立更换，供应商类型不会进入领域层或应用用例。
- 自动研究必须多经过一次 Schema 校验和人工审核，牺牲少量速度以换取来源、隐私和本地执行安全。
- 个人面经和网友面经可以共享查询投影，但必须保留不同审核、删除和保留策略。
- 本 ADR 已获产品确认；各能力仍须在对应 SDD 规格达到 Ready 后再创建数据库迁移或实现代码。

## 备选方案

- **把问答和项目补充直接写回 CandidateProfile**：实现较少，但会混淆简历事实、面试准备记录和模型推导，拒绝。
- **以 Markdown 作为唯一权威并直接解析用户编辑**：本地可读性最好，但并发、证据关系、审核状态和幂等难以可靠维护，拒绝。
- **把外部 Agent 注册为 Agent Core 的高权限 Tool**：可以复用模型—工具循环，但会突破现有只读、最小权限和结构化调用边界，拒绝。
- **首期直接实现 Codex/Claude 自动委派**：体验更自动化，但会把认证、进程隔离和供应商兼容阻塞在核心功能之前，暂缓。
- **为深度拷打直接引入向量数据库和 RAG 框架**：相近项目常采用该路线，但个人显式 Markdown 集合规模尚未证明需要额外基础设施，暂缓。
