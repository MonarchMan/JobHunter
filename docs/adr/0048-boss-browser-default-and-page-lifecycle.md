# ADR-0048：BOSS 默认浏览器辅助传输与页面生命周期

- 状态：Accepted
- 日期：2026-09-28
- 关联规格：[028 招聘平台来源](../../specs/028-recruitment-platforms/spec.md)

## 传输与采集

BOSS 未指定模式时，CLI、Web、Worker 一致选择 `browser`；显式 `http` 仅保留独立诊断与验证，两者在同一连接代次内不自动切换。默认模式由官网页面正常发起列表与详情请求并维护安全状态，Worker 只观察固定职位 JSON 端点的真实响应，复用严格解析、身份校验及逐条入库；不另发 Node HTTP，不读取或导出 Cookie，不使用 DOM 摘要充当职位事实，也不执行官网私有安全函数或验证操作。

Worker 专用页安装监听后才首次导航固定官网入口。首批消费前允许有界的同源初始化导航、临时空白与页面就绪等待；文档 epoch 变化立即清空旧观察，迟到正文不得跨文档提交。须同时具备稳定正常页面与真实列表响应才消费；连续风险复核用于辨别登录、验证、拦截、未就绪与响应超时。首批消费后主框架导航冻结当前批次，跨站导航始终拒绝，不靠刷新或切前台继续。

详情仅按本批稳定职位 ID 操作页面中对应的普通职位链接；不点击沟通、收藏、投递或验证码。后续获取先检查已预取／在途列表；无新页时，在用户明确的获取动作中将专用页滚动到顶部再到底部，派发一次普通 `scroll` 事件，观察官网实际产生的下一页 JSON。不调用私有分页接口、不用 DOM 抽取职位、不遍历全量页。后台独立窗口不主动 `bringToFront`；如页面确实不能在后台加载，记录失败而不伪称无干扰。请求节奏遵循现行可配置策略，不再把旧实验五秒写为固定规则。

`BossPageLifecycle` 仅共用页面就绪、风险复核、文档代次、取消与断线规则，不持有 Cookie、响应正文或职位。browser 正文观察引用 epoch；显式 HTTP 在认证读取前后与响应交付时检查 epoch，但继续使用自己的请求和恢复预算。页面就绪不等于 HTTP 安全检查必然通过。browser 出现验证、37 或结构错误时停止、保留已存职位，不自动退回 HTTP；默认 browser 不使用 HTTP 的 37 恢复链。

## 验收边界

分别报告 browser 整批与显式 HTTP 对照，不以一个模式的成功推断另一个稳定。诊断仅保存固定状态／原因码，不保存 DOM、地址、检查参数或凭据。初始化有界等待及后续导航冻结都需要测试；真实两批成功也不代表长期稳定。
