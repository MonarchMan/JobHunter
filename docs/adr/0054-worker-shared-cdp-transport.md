# ADR-0054：Worker 共享浏览器 CDP 传输

状态：已接受（2026-09-30）

## 背景

同一 Chrome 内的四个平台及多个意向关键词分别创建 WebSocket，重复申请授权。平台业务会话必须隔离，但这不要求独占浏览器级传输连接。

## 决策

1. Worker 显式创建并拥有一个 CDP 连接管理器，注入四个平台提供器；按已校验的本机浏览器 WebSocket 端点复用连接，并合并并发初始化。不同 Worker、浏览器实例或端点不共用连接，不引入全局单例或代理进程。
2. 每个平台、每个关键词仍拥有独立后台页面、页面 sessionId、认证上下文、游标及失败状态。共享层只负责命令 ID、响应匹配、按 sessionId 分发事件和连接生命周期，不读取或持久化职位与认证内容。
3. 单会话取消、超时、初始化失败、断开或替换只清理自身命令、监听及自建页；借用页只 detach，不关闭。底层已授权连接即使暂时空闲也保留至 Worker 退出或连接真实断开；尚未授权且所有等待者均取消时关闭未完成连接。
4. 真正的 Socket 断线使所有依赖会话失效并清除各自认证。单个页面或协议错误不关闭其他会话；不自动重连、重试职位或伪装连续稳定。后续明确连接动作才可建立新连接，浏览器重启后仍可能需要授权。
5. 独立诊断中未注入管理器的提供器保持独占连接的原有释放语义。BOSS 默认 browser、其他平台 HTTP 的选择与节流、权限、持久化边界均不改变。

## 验证

使用合成 CDP 验证并发只建一条 Socket、多页面请求与事件不串流、取消一个授权等待者不影响另一个、单会话失败／断开不影响其他平台、空闲复用、真实断线通知所有会话、不同端点隔离及 Worker 关闭释放。线上授权和整批职位成功独立记录，不以协议替身测试宣称四个平台线上通过。

本决策覆盖 ADR-0046 中“每个平台独占并释放 Socket”的生命周期细节，保留其页面所有权、安全边界和业务代次规则。
