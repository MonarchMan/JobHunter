# ADR-0045：招聘平台职位生命周期与任务

- 状态：Accepted
- 日期：2026-09-28
- 关联规格：[028 招聘平台来源](../../specs/028-recruitment-platforms/spec.md)、[003 任务与 Worker](../../specs/003-task-worker/spec.md)

## 背景与决策

招聘平台跨公司、依赖个人登录与查询条件，返回的批次不是职位全集。因此它与官网共享正式职位库、修订、观察、匹配和业务关联，但不伪装为某公司的官网来源、不参与逻辑渠道覆盖，也不依据“本批未出现”增加 `missing_count` 或推断下架。平台招聘公司通过 provider 与外部公司身份映射；平台职位有独立的、可配置的保留清理策略，引用保护、dry-run 和短事务仍适用。可见详情页的同源 CSRF POST 记录真实浏览活动；GET、预取和后台采集不更新交互时间，后台核验只更新 `last_seen_at`。

每次用户明确获取只消费当前一页／一批。Worker 按候选顺序取得必需详情并逐条短事务保存；已验证列表 JSON 包含完整正文时直接复用，不为形式完整性重复请求详情。网络调用在事务外，提交前复核任务租约、取消和连接代次。某条失败即停止余下候选，已保存职位保留，不写占位正文、不自动读取全量页。批次上限、搜索条件和排序需先固定；推荐流不冒充搜索能力。

“职位”页是唯一正式列表：默认官网来源，可切换招聘平台与 provider；平台默认展示全部招聘类别。来源筛选同时作用于列表、计数、分页和返回路径，筛选或刷新本地列表不访问上游。来源页仅提供连接、显式批次获取、任务进度、实际保存数量和职位页入口，不再维护摘要列表或“点击详情才保存”的第二套生命周期。

手动重试原子地把原失败任务重新入队，保留任务 ID、创建时间、幂等键与业务关联；同一事务将上轮失败分类、脱敏摘要、尝试次数和时间写入 `task_retry_logs`，操作令牌去重，并发键冲突不得覆盖其他任务。自动重试策略不变，手动重试开启新一轮 Handler 尝试预算；历史 `retry_of_task_id` 链不迁移。部分入库时由 Handler 的 `retryPayload` 传递必要恢复输入，不重抓已提交事实。BOSS browser 的再次获取可正常加载下一批；显式手动重试冻结的 acquire 才能重新连接，不原样重放必败命令。

## 边界与验收

不建立临时职位库、账号池或收藏后转正流程；不因本 ADR 启用自动删除。取消不回滚已经提交的职位，旧任务缺少入库计数时不伪造成功数量。验证来源和 provider 隔离、逐条入库与部分失败、查询计数分页、浏览活动时间、原任务身份重试和幂等边界；离线通过不等于上游长期稳定。
