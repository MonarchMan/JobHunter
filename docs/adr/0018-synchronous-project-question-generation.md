# ADR-0018：项目拷打问题由 Web 同步生成

> 状态：Accepted
> 日期：2026-09-04
> 部分取代：ADR-0013 的第 10 项

## 背景

项目拷打每次只生成一个较短的问题。此前 Web 先发布 `interview.project-question` Task，再由 Worker 调用模型，用户需要等待轮询，交互链路和失败恢复都比一次即时提问更重。产品现要求问题生成改为同步，并希望后续支持流式输出。

当前 `ModelClient` 只提供完整结构化输出的 `complete()`。问题在展示前还必须校验证据引用、覆盖维度、档位资料约束和禁止代答规则；直接展示未完成、未校验的模型 token 可能泄露最终应被拒绝的内容。

## 决策

1. 新的问题请求由 Web 在当前 HTTP 请求内调用内部问题 Agent，不再创建或关联 Worker Task。
2. Web 只在短事务中创建 `question_pending` 占位和提交最终问题；模型调用与数据库事务严格分离。
3. 请求断开或失败时取消模型调用并删除无任务引用的占位回合，用户可直接重试；取消后的新请求可以替换尚未清理的无任务占位，旧请求迟到结果由 CAS 拒绝，既有问答不受影响。
4. 问题执行逻辑抽取为应用层可复用生成器，Web 同步调用与遗留 Worker Handler 共用相同的上下文、证据和输出校验。
5. 回答摘要、Markdown 投影和网友面经研究仍由 Worker 执行，不随本决策同步化。
6. 同步接口使用 SSE 流发送由服务端真实执行点驱动的阶段事件：准备上下文、生成问题、校验问题和保存问题。阶段事件不包含模型正文；成功后仍一次呈现完整且已校验的问题。真正的逐字输出仍需模型端口提供增量事件，并在任何正文展示前具备结构化增量校验与安全截断。

## 结果

用户无需等待任务调度和轮询即可获得下一问，并能看到真实阶段进展；问题生成错误直接回到当前操作并可重试。代价是 Web 请求会在模型调用期间保持流连接，Web 进程必须装配模型客户端并承担超时、断线和取消。历史队列中的问题 Task 仍可由 Worker Handler 完成，但新请求不再产生该任务。

## 备选方案

- **继续使用 Worker 并缩短轮询周期**：仍保留调度延迟和额外任务状态，拒绝。
- **把完整 JSON token 直接流到页面**：可能暴露未通过证据与安全校验的内容，拒绝。
- **模型完成后人为逐字播放**：不减少等待时间且会制造伪流式体验，拒绝。
