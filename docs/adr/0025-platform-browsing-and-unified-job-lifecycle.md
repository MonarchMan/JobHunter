# ADR-0025：招聘平台按需读取与统一职位生命周期

- 状态：Accepted
- 部分替代：摘要展示与单条详情触发入库交互由 [ADR-0030](./0030-platform-batch-ingestion-and-job-list.md) 取代；其他决策不变。
- 日期：2026-09-19
- 关联规格：[028 招聘平台来源](../../specs/028-recruitment-platforms/spec.md)

## 背景

官网按公司、逻辑渠道和物理来源定时同步。招聘平台跨公司，推荐结果依赖个人会话且不是职位全集，不能套用完整同步的缺失下架规则。用户决定平台职位同样正式入库，采用更积极的正常清理策略，而非临时职位缓存或收藏后转正。

本次 BOSS 小实验在取得站点 Cookie 和观察到的请求模板后断开 CDP：独立 HTTP 两页分别返回 15 条且无重复，一条详情成功并核对身份和标题，另一条返回业务码 37。实验支持 HTTP 优先方向，但不能证明最小 Cookie 集合、会话长期有效、第二条详情失败原因或平台授权范围。

## 决策

第 3 项的 CDP 立即断开策略已由 [ADR-0026](./0026-platform-cdp-session-lifetime.md) 替代，改为用户活动会话内复用一次授权的连接，其余约束不变。

1. 保留官网同步，新增用户驱动的平台浏览流程。统一使用 jobs、修订、观察、匹配和业务关联；不建立长期临时职位库，不以收藏作为正式入库条件。
2. 保留现有公司逻辑渠道到多个物理官网来源的映射；平台物理来源跨公司，不伪造平台所属公司或三渠道，不进入官网覆盖聚合。来源身份、招聘公司、个人连接分别建模。
3. 浏览器负责用户登录。经用户明确连接后，Worker 基础设施通过本机 CDP 按需取得指定站点必要会话与上下文，内存持有凭据并尽快断开；不维持账号池，不读取浏览器磁盘凭据、不导出完整存储、不自动保活。HTTP 优先，浏览器回退仅用于独立验证并显式启用的能力，不能用于继续被验证或限流阻断的请求。
4. 列表、详情与匹配分阶段执行。保留 ADR-0024 的正文质量底线：缺少必需正文的摘要只是本次请求的有界展示数据，取得详情后自动进入正式职位库；失败不写占位正文。已满足质量要求的列表记录直接入库。
5. 平台未再出现不增加 missing_count，不证明下架。明确关闭证据才能推进关闭状态；本地陈旧程度与上游在招状态分开。正常保留清理可删除长期无业务关联的平台职位，不伪造关闭事件。
6. 清理复用运维计划、dry-run、引用保护、短事务和 ADR-0020 的物理维护。平台保留期限及检查频率独立配置；首次启用自动删除需确认策略，不因本 ADR 直接删除任何数据。

## 替代方案

- 临时数据库或内存岗位池、收藏后转正：否决，违背统一生命周期的产品决策，增加双套查询和迁移流程。
- 把平台作为普通公司官网来源：否决，污染公司归属、逻辑渠道覆盖和缺失下架。
- 常驻浏览器批量抓取或 Cookie 磁盘复制：否决，增加权限、兼容与运行成本，不满足最小会话依赖目标。
- 完全不保存平台职位：否决，重复详情与评分请求成本高，无法复用现有业务能力。

## 后果

需迁移来源类型与观察归属约束、引入平台连接和公司外部身份映射，但保留所有既有官网 ID 和行为。新增契约与基础设施包，应用层通过端口编排，不依赖 CDP 实现。单本机单 Worker 首版无需新服务或消息中间件。

本决策扩展来源范围，不放宽官网匿名访问约束或面经研究的无登录浏览器约束，也不改变 ADR-0024 的入库质量要求。架构接受不等于平台能力已 supported；BOSS 详情业务码 37 仍是实现前协议验证门槛。
