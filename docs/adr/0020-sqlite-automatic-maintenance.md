# ADR-0020：SQLite 阈值维护与跨进程写入保护

- 状态：Accepted
- 日期：2026-09-05

## 决策

SQLite auto_vacuum 保持 NONE。应用维护服务按持久化时间和阈值检查，Worker 调度循环驱动独立维护子进程，避免 VACUUM 阻塞任务事件循环。

单例维护状态记录持有进程 PID。标准数据库连接安装 TEMP 写保护触发器，检查到维护进程存活时拒绝业务写入。专用维护连接在短 BEGIN IMMEDIATE 中检查任务及调度并建立标记，在事务外备份、checkpoint 与 VACUUM；完成或失败均释放标记。进程退出后标记自然失效，后续维护检查补记中断结果。

## 影响

维护周期由独立异步循环驱动，与普通调度循环分离。引擎的生命周期信号直接传给维护子进程；停止时先取消维护，再等待循环退出，避免等到进程 close 才发送取消造成退出依赖循环。

新增基础设施写入协调职责；应用层通过维护端口编排，Web 统一将写保护异常或写锁超时转换为 503。读取仍可进行，长读事务阻止 checkpoint 时延后。临时触发器需随每次连接建立，新增持久表在下次打开连接时纳入保护；升级时先停止旧 Web 和 Worker，再启动新版本，不能让未安装保护的旧连接与新维护进程混用。支持同一本机进程间互斥，不提供跨主机 PID 协调。

自动维护备份仅保存数据库，保留最近两份已验证备份，手工备份不受影响。失败时不自动覆盖当前数据库，保留备份供诊断。
