# ADR-0066：招聘邮件识别并入邮箱同步任务

- 状态：Accepted
- 日期：2026-11-09

## 背景

招聘邮件识别最初拆分为两条任务：`mailbox.sync@v1` 每天发现引用并入队，`mail.classify@v1` 逐封正文读取与分类。实际运行中，单封分类任务把同一邮箱的一次同步切成了大量记录；任务页被刷出大量短任务；而 `mailbox.sync@v1` 的全局并发键把跨邮箱同步也串行化，与"每封邮件独立并发"的初衷不符。评估过的替代方案：

- 保留单封 `mail.classify@v1` 任务并让同步任务等待子任务完成：任务引擎没有"等待子任务"的正常流转，且会放大任务数量，否决。
- 同步任务内请求子线程并行分类：执行线程的租约绑定在任务本身，子线程没有独立租约，崩溃与取消边界反而变差，否决。

## 决策

1. 邮件分类并入 `mailbox.sync@v1` 作为第二阶段，删除 `mail.classify@v1` 任务类型。每个已启用邮箱对应一条每日 03:00（`Asia/Shanghai`）计划；触发时投递的 payload 只携带 `mailboxKey`，并发键为 `mailbox-sync:{mailboxKey}`，同一邮箱同时至多一条，不同邮箱可以并行。
2. 单条任务内阶段一先发现引用并入库（`processing_status=discovered`），阶段二对当前页引用串行获取正文、规则筛选、调用模型并提交结论；每页完成后写一次页检查点，Worker 心跳在整段执行期间续租，重试时按检查点跳过已完成页。
3. 单封邮件的重放身份沿用（邮件引用、内容版本、分类策略版本）；分类失败或不可达的引用保留最小身份，在后续同步任务中重放，不随单次失败丢弃。
4. 发布新版本时迁移把未完成的 `mail.classify@v1` 任务标为 `cancelled`，同步删除其 Handler 注册与入站路径，已终态历史记录保留。

## 影响

- 任务数量显著下降，任务页只出现按邮箱粒度的同步任务；单个邮箱的当日进度可在一条任务检查点中查看。
- 跨邮箱恢复并行能力；同一邮箱内的分类从并发变为串行，但由页检查点保证崩溃恢复不重复已提交邮件。
- `recruitment-mail.classify` Agent 与策略版本语义不变，只改变其被调用的任务边界。
