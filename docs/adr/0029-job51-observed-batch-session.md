# ADR-0029：前程无忧按官网已观察批次执行独立 HTTP

- 状态：Accepted
- 日期：2026-09-20
- 关联规格：[028 招聘平台来源](../../specs/028-recruitment-platforms/spec.md)

## 背景

51job 原始搜索请求已在研究中成功独立 HTTP 获取 JSON 及完整正文，但包含签名和动态访问参数，尚无跨页生成与长期稳定证据。不能将修改页码的猜测作为生产分页能力。

## 决策

新增明确标识的官网辅助模式：用户同意后，Worker 持有同一 CDP 连接与所选搜索页的只读 Network 监听，只保留固定搜索端点最新成功请求模板。用户在官网正常搜索或翻页后，在 CLI／Web 显式读取；此时用原样模板执行 HTTP，不自动操作网页、生成签名、重试或回退。监听不读取简历、账号接口或响应正文，认证值仅 Worker 有界内存；任务和 Web 只见安全投影。

这是 ADR-0028 初始化后 detach 规则的 provider 专属例外，不改变 BOSS／智联行为。断线、页面关闭、主动断开或 Worker 退出释放模板和工作集；失败冻结时保留授权连接直至显式关闭，不自动重连。新批次等待有超时，重复页与查询变化拒绝，未就绪不能伪装末页。

列表 JSON 中完整正文作为本次获取的详情事实，选中后经既有应用与仓储入库，不额外请求同一正文。公司身份、provider 隔离、交互与清理规则保持不变，不需要数据库迁移。

## 后果

前端明确“先官网翻页，再读取官网批次”，不宣传纯 HTTP 自动翻页。离线完整装配、真实单批、跨批和长期稳定性分别记录；网络失败不能被历史重放掩盖。生产仍为 experimental。
