# ADR-0050：前程无忧自建页以正常分页产生下一批签名模板

- 状态：Accepted
- 日期：2026-09-29
- 关联规格：[028 招聘平台来源](../../specs/028-recruitment-platforms/spec.md)

## 背景

前程无忧每批独立 HTTP 都需要官网自然生成的签名请求模板。原方案只被动监听：首批成功后，Worker 自建后台页无人翻页，下一轮等待 90 秒仍无模板，以 `session_unavailable` 冻结；这不是 HTTP 被拒绝。自建页已由 Worker 拥有，但旧决策禁止其执行下一页动作，形成日常获取与连续观察的缺口。

## 决策

仅 Worker 自建的同源搜索页，在上一批成功且非末页、没有预取新模板时，由一次显式 `next` 驱动官网可见分页控件执行一次正常点击。点击前核对当前页码、唯一控件和可用状态；监听器只接收因此自然产生的固定端点成功请求，校验查询不变和页码前进。独立 Node HTTP 原样使用该模板获取列表与完整正文，浏览器响应不作为职位事实。借用用户页继续被动监听，由用户自行翻页。

不生成或修改 `decode__1048`、签名、时间戳、请求 ID，不刷新、循环导航、重复点击、处理验证或使用旧模板。控件不可用或等待超时报告固定 `template_required`，不伪装成网络故障或末页；上游结构未知仍冻结。任务及持久库不存签名、Cookie 或原始响应。

## 后果

前程无忧仍不是纯 HTTP：每个新批次需要一次官网普通页面动作来产生模板。浏览器负责签名模板与会话，HTTP 负责职位事实；自建页和借用页的行为不同，CLI／Web 须按连接所有权表达。只在有限在线批次成功后认定可用，不把本决策当作长期稳定证明。
