# ADR-0008：官网列表同步与职位详情补全解耦

> 状态：Accepted
> 日期：2026-08-26

## 背景

腾讯、腾讯实习和美团社招曾在列表同步中逐条请求详情。详情请求发生在地域与求职意向过滤之前，导致大量无关岗位产生额外网络请求；任意详情失败又会把完整列表运行降为 partial，并累计来源失败。浏览器分页漂移、单条标准化失败和详情失败还共用同一个健康计数，无法表达真实故障边界。

## 决策

1. `source.sync` 只负责职位列表 JSON 的完整发现、列表字段归一化、地域/意向过滤和基础职位持久化。
2. 来源详情能力分为 `inline` 与 `deferred`。`deferred` 来源必须能仅凭列表记录生成合法基础职位；详情通过独立 `source.job-detail` Worker 任务补全。
3. 详情任务仅为已通过 intake 的职位创建，使用来源、职位和列表内容哈希组成幂等键；详情失败不得改变列表覆盖度或来源健康。
4. 同步健康以列表可用性和覆盖度为主。少量、可归属的单条隔离仅记数据质量警告；分页不完整和运行级失败才累计来源失败。
5. 浏览器仅初始化匿名会话并捕获首个列表 JSON 请求，后续在同会话直接请求 JSON 页；单页超时和整轮采集超时独立。
6. SyncRun 持久化分页覆盖证据，单条隔离持久化阶段、分类和安全摘要。健康探测与同步健康分别保存，不再用探测结果覆盖同步失败计数。

## 影响

- `packages/source-core` 扩展详情能力和覆盖诊断契约。
- `packages/application` 新增详情补全用例和任务类型，调整同步健康与重试语义。
- `packages/db` 新增详情缓存、隔离诊断和 SyncRun 覆盖证据。
- `apps/worker` 注册独立详情队列，并修复浏览器采集超时与 Promise 生命周期。
- 腾讯、腾讯实习和美团社招改为列表优先；下一次完整列表同步自然恢复来源健康，不直接伪造健康状态。

## 备选方案

- 继续同步内请求详情：请求规模和单点失败放大问题无法消除，拒绝。
- 完全删除详情能力：会损失按需评分需要的完整 JD，拒绝。
- 仅提高失败阈值：只能掩盖错误耦合，不能减少无效详情请求，拒绝。
