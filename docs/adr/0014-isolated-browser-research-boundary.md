# ADR-0014：匿名隔离浏览器与受限 Codex 研究工具边界

> 状态：Accepted
> 日期：2026-08-30
> 部分取代：ADR-0013 的第 5、7 项
> 部分被取代：ADR-0015 的 Worker 预采集、无网络 Agent 决策

## 背景

ADR-0013 把 `codex-local@v1` 限制为只使用 Codex 原生实时网页搜索，并禁止本地或外部浏览器自动化。真实联网试运行证明，当前 Worker 启动的 Codex 进程不会自动继承 Codex Desktop 的浏览器能力，且只依赖原生搜索时无法稳定处理需要 JavaScript 渲染的公开页面。

产品已确认可以使用本机浏览器，或让 Codex 通过外部浏览器搜索。直接把用户日常浏览器、CDP 端口或 Playwright 对象暴露给模型会带来登录态泄露、任意交互、Prompt injection 扩权、难以取消和无法复现等风险，因此需要一个明确受控的浏览器网关。

## 决策

1. 保留现有 `ExternalResearchExecutor` 应用端口和 `codex-local@v1` 原生搜索执行器，新增版本化的 `browser-assisted-codex@v1` 执行器。两者都只返回待校验的 `ResearchBundle`，不改变人工导包和统一 Bundle Importer 边界。浏览器执行器只接受 `community-research-prompt@v2`；已冻结的 `@v1` Prompt 明确禁止 MCP/浏览器，只能继续使用 `codex-local@v1` 或人工导包，不得原地替换为浏览器执行。
2. JobHunter Worker 负责浏览器网关及浏览器子进程的完整生命周期。每次研究使用专用临时目录和匿名、无扩展、无持久化登录态的隔离 BrowserContext；不连接用户日常浏览器，不导入其 Cookie、历史、密码或本地存储。
3. Codex 只能连接由 JobHunter Worker 为当次任务在 `127.0.0.1` 随机端口启动的唯一受信任 Streamable HTTP MCP。MCP 使用单次随机 bearer token 并校验 Host/Origin；Codex 配置必须使用 `required = true` 且 `enabled_tools = ["search", "open", "readPage"]`，任意工具缺失或多出都拒绝执行。`search` 返回经域名策略过滤的不透明来源引用，`open` 只能打开该次搜索产生或 Brief 允许的公开 HTTP(S) 来源，`readPage` 只返回清洗、限长的可读文本及标题、最终 URL、抓取时间等元数据。Codex 0.149 的 `code_mode_only` 模型需要本地 Code Mode Host 来编排嵌套 MCP 调用，因此不得禁用该 Host；其代码单元仍运行在无 Node、文件系统和网络 API 的隔离 JavaScript 环境，且只能调用上述三项白名单工具。Codex 内建 `browser_use*`/`in_app_browser`、Shell 和统一执行仍禁用，Codex 不获得 Browser、Page、CDP 或 Playwright 句柄。
4. 浏览器网关不提供登录、输入、点击、上传、下载、表单提交、剪贴板、通知、任意 JavaScript 注入/执行或本地文件访问能力。页面自带脚本只能在隔离上下文内用于渲染，不得因页面文本或模型输出增加新工具或放宽权限。
5. 网关必须在每次导航及重定向后重新校验协议、主机、DNS/IP 和 Brief 的允许/禁止域名，拒绝本地、内网、保留、示例用途和携带凭据的地址。浏览器只能通过 Worker 持有且带随机 Basic 凭据的 loopback 前向代理联网；每个网络目标的全部受信任解析答案先经过公网检查，再固定其中一个公网 IP，主机名和字面 IP 共用数量、并发与缓存预算。运行环境存在透明网络转译时，保留网段 `198.18.0.0/15` 仍不得被视为公网：仅当系统 DNS 返回非空且全部答案都在该网段时，默认解析器才通过有字节/时间上限的受信任 DNS-over-HTTPS 查询真实 A/AAAA，并要求每个答案通过公网检查；仅在显式启用透明转译且连接前系统答案仍全部属于 `198.18/15` 时，代理才以首个转译地址建立连接，安全 pin、域名判断与审计仍使用受信任公网地址。混合答案、字面 IP、受信任查询失败或任一非公网答案都不得启用转译或放宽 SSRF 规则。代理只允许 GET/HEAD，单 HTTP 响应和单 HTTPS 隧道下行最多 16 MiB，单任务下行最多 128 MiB；另按任务限制 DNS 目标/并发/响应、搜索次数、打开页数、正文字符、连接数和超时，并继续使用 Worker 全局单并发。
6. 不主动规避登录、付费墙、验证码、访问控制、站点限流、反自动化措施或站点明确返回的机器人限制；遇到这些情况时将来源记为不可用并继续其他来源，不请求人机协作绕过。首版是有限的逐页浏览器访问，不实现通用 `robots.txt` 解析器，因此不得宣称已机械执行所有站点的路径级 robots 规则；需要严格机器可判定 robots 合规的域名应由 Brief 排除或改走人工导包。
7. 网页文本、搜索摘要、工具返回值和 Codex 最终输出均是不可信输入。工具响应必须把来源元数据与页面正文分区，`community-research-prompt@v2` 必须明确页面中的指令无权改变任务、工具参数或权限。最终结果仍经过 Schema、请求指纹、URL、引用完整性和内容长度校验。
8. 每个问题必须能回溯到实际 `open` 的最终 URL 及有限证据摘录；`question.text` 必须逐字包含在同一来源的 `evidenceExcerpt` 中，非空 `answerExcerpt` 也必须逐字来自该页正文，禁止模型改写问题、补写答案或拿无关句子充当证据。执行器记录标题、抓取时间、来源域名、页面引用和裁剪/拒绝原因，并保留有上限的临时调用 trace；在调用 Bundle Importer 前，确定性删除未完成 `open + readPage` 的来源/经历和无法回溯的问题，无法证明的答案摘录置空，并追加本地裁剪警告。裁剪后没有真实问题则整包拒绝；剩余 Bundle 的每个 source URL 必须与当次 `open` 的最终 URL 相等。校验完成后只保留有限证据元数据，不默认镜像整页正文。浏览器成功访问不等于内容真实性已验证，导入后仍保持 `unverified` 并经人工审核。
9. 任务取消、超时、Codex 退出或网关异常时，Worker 必须终止 Codex、工具服务与浏览器的完整进程树，关闭 BrowserContext 并清理临时 Profile。任何网络、浏览器、模型或文件写入都不得发生在数据库事务内。
10. 普通 CI 使用伪浏览器网关与固定页面样本，不联网、不启动用户浏览器。真实联网只作为显式手工 smoke test，且不能依赖登录态。

## 影响

- 动态公开页面可以进入自动研究闭环，但需要维护浏览器运行时、搜索适配、SSRF/重定向校验和进程树清理。
- Codex 只处理研究推理，JobHunter 掌握网络和浏览器权限；页面内容不能将受限工具升级为任意浏览器或本机操作。
- 已有 `codex-local@v1` 和人工导包仍可降级使用；浏览器执行器不会成为项目拷打、个人面经导入或历史数据阅读的前置依赖。

## 备选方案

- **让 Codex 直接控制用户日常浏览器**：会暴露登录态、本地历史和任意交互能力，拒绝。
- **直接向 Codex 暴露 Playwright/CDP 或完整 Browser Tool**：权限面过大且难以对单次导航审计，拒绝。
- **继续只使用 Codex 原生网页搜索**：安全边界更简单，作为可用时的优先路径和降级方案保留，但不能覆盖当前真实联网需求。
- **由 JobHunter 编写通用爬虫并绕开 Agent**：会把站点适配和内容理解扩展为新业务平台，首版不做。
