# ADR-0068：日志文件单写入者与跨线程诊断

- 状态：Accepted
- 日期：2026-11-10

## 背景

单宿主动态线程池中，每个线程独立打开并滚动同一日志文件会继续向旧 inode 写入并产生轮转竞争。线程异常只传公开摘要、Web 错误只输出名称，不能支撑排障；文件与控制台共用级别造成噪声和诊断损失。

## 决策

1、common 保持通用日志契约和实现，业务模块只输出事件；apps 负责装配与生命周期。宿主持有唯一任务文件写入者，线程通过有界、确认式专用 MessagePort 提交脱敏事件，业务控制协议与日志流量隔离。
2、Next 请求进程采用每进程独立日志文件与全局单例，避免多个进程竞争轮转。查询入口合并文件时间线，禁止把原始子进程输出直接作为可信日志。
3、内部诊断保留安全堆栈、错误码和 cause，公开摘要维持原安全边界。关联身份自动随任务执行传递，并复用 Agent/模型账本身份，不新增业务状态存储。
4、文件保留结构化事件，控制台独立级别和渲染。日志失败不改变业务结果，有界缓冲溢出与文件故障必须有受控告警。查询及导出重新脱敏，限制扫描资源。
5、错误诊断保留有界 AggregateError 分支与安全 Schema 路径；字段超出 32 KiB 时先移除普通附加信息，再缩减错误树，保留关联身份和根因摘要。账本写入失败即使带有 SQLite 锁忙原因，仍按既有不可重试语义终止，不能因诊断增强重复消费模型调用。

## 影响

复审补充：诊断 cause 不得推翻不可重试 Agent 分类，此约束同时覆盖工具错误及账本错误。公开摘要不复制未知解析错误原文；日志与持久化摘要复用文本凭据脱敏规则，失败收尾采用聚合原因而非覆盖原始异常。

不引入远程日志服务、不新增数据库表、不修改旧运行数据。新增日志协议和配置需要同步任务宿主、Web 与 CLI。进程硬退出可能损失尚未确认事件，优雅关闭需排空；文件保留有限，查询必须如实报告截断。
