# JobHunter Web UI/UX 审计报告

- 审计日期：2026-08-22
- 审计入口：`http://127.0.0.1:3210`
- 覆盖视口：桌面默认视口、移动端 `390 × 844`
- 审计范围：工作台、职位列表、职位详情、个人资料、招聘来源、招聘平台空状态、任务与 Agent 运行、错误及 404 状态
- 结论：视觉基础较好，但高密度管理页的信息架构、轮询实现、移动端数据展示和状态反馈还没有达到“简洁、流畅、可长期使用”的标准。

## 1. 总体评价

当前界面已经形成辨识度较高的“本地求职工作台”气质：深绿色主色、低饱和背景、克制阴影、统一圆角和清晰的大标题，使产品不像通用后台模板。工作台首页尤其完整，品牌、主行动、指标和下一步引导的关系明确。

综合评分：**6.5 / 10**。

| 维度       | 评分 | 评价                                                                          |
| ---------- | ---: | ----------------------------------------------------------------------------- |
| 视觉一致性 | 8/10 | 色彩、卡片、状态标签和标题语言较统一                                          |
| 信息层级   | 7/10 | 首页优秀；来源和任务页层级被大量同权信息冲淡                                  |
| 操作效率   | 5/10 | 高级字段常驻、缺少过滤/分页/批量操作，重复操作成本高                          |
| 状态反馈   | 5/10 | 基础反馈存在，但错误、忙碌、刷新和禁用状态区分不足                            |
| 移动端     | 5/10 | 无全局横向溢出，但长表格和来源卡片在手机上效率很低                            |
| 可访问性   | 7/10 | 有 skip link、语义标题、表格 caption 和清晰焦点；仍缺少减弱动效与部分状态语义 |
| 性能感知   | 3/10 | 任务行各自轮询会制造请求风暴，是当前最严重的流畅度问题                        |

## 2. 做得好的部分

1. **品牌和首页视觉语言成熟。** 首页 Hero 的深绿渐变、浅绿重点字和浅色 CTA 形成稳定的品牌锚点，信息层次明显。
2. **基础可访问性意识较好。** 全局提供跳转到主要内容的链接，焦点轮廓清晰；列表和表格使用了语义结构、caption 和状态文本，而不是只依赖颜色。
3. **点击目标基本合格。** 按钮和表单控件的最小高度为 44px，满足桌面和触屏的基本可操作尺寸。
4. **状态色体系已成形。** 在招、待处理、失败、健康、退化等状态大多具备文字和颜色双重表达。
5. **空状态不是纯空白。** 个人资料、招聘平台、职位无结果和 Agent 无记录都有说明和下一步路径。

## 4. 详细发现与工程建议

### UI-001：任务页存在轮询风暴（P0）

**证据**

- `apps/web/app/tasks/page.tsx:56` 为每一行任务渲染一个 `TaskActions`。
- `apps/web/app/tasks/task-actions.tsx:21-30` 中，每个待处理或运行中的 `TaskActions` 都创建独立的 `setInterval`，每 3 秒执行 `router.refresh()`。
- 当前页面实际渲染约 100 条任务记录；浏览器日志出现大量同一时刻、同一路径的 RSC 请求失败。

**问题**

轮询职责放在行组件后，刷新次数与活动行数线性增长。100 个活动任务意味着约每 3 秒触发 100 次全页服务端刷新。除了网络和服务端压力，还会造成按钮忙碌状态、行内反馈、焦点和滚动体验不稳定。

**建议实现**

1. 将轮询提升到任务页唯一的客户端容器，例如 `TaskDiagnosticsView`，全页只保留一个定时器。
2. 页面不可见时暂停轮询；窗口重新可见后立即补一次刷新。
3. 优先考虑轻量状态接口，只增量刷新状态变化；至少不要为每行刷新整页 RSC。
4. 用户正在操作按钮时暂停本轮刷新，避免反馈被覆盖。
5. 在标题旁显示“自动刷新 · 刚刚更新”，并提供暂停/手动刷新。

**验收标准**

- 无论存在多少活动任务，3 秒窗口内最多产生 1 次诊断刷新。
- 页面切到后台后不持续轮询。
- 取消/重试后的行内反馈至少保留 4 秒，焦点不丢失。

### UI-002：职位入口没有直接到达实际招聘页面（P0）

**证据**

- 在 `/jobs` 点击真实职位“外卖-搜索产品运营”，当前先进入 `/jobs/01a02939-7070-756d-a746-f38bb6b8192f`。
- 该站内详情页进入全局错误状态：“页面暂时无法加载”，对应 API 返回 `400 INVALID_QUERY`。
- 数据中已经保存职位的 `detailUrl`/`applyUrl`，因此无需在本项目中重新实现职位详情页面。

**建议实现**

1. 职位标题直接链接到该职位的实际官方招聘页面（优先使用 `detailUrl`，缺失时回退到 `applyUrl`），不再经过自建站内详情页。
2. 使用新标签页打开，并保留 `target="_blank" rel="noopener noreferrer"`；链接旁使用外链图标，让用户提前知道会离开本地工作台。
3. 实际页面 URL 缺失或未通过既有 HTTPS/官方域名校验时，禁用外链并明确显示“官方页面暂不可用”，不能静默跳到错误页。
4. 站内已有的匹配分、状态等求职辅助信息继续保留在列表行或可展开摘要中，不以重新制作完整职位详情页为前提。

**验收标准**

- 列表首尾至少 5 个真实职位均可直接打开各自的实际官方招聘页面。
- 外链的新标签页行为和安全属性正确，原职位列表的筛选、分页及滚动位置保持不变。
- URL 缺失时有明确不可用状态，不进入站内错误页。

### UI-003：任务页缺少面向运维的浏览结构（P1）

**现状**

- 桌面端表格一屏只看到少量任务；移动端实测页面高度约 10668px。
- 类型显示为 `job.enrich`、`match.compute-revision` 等内部键，完整 UUID 直接占据第二行。
- 没有状态筛选、类型筛选、搜索、时间范围、分页或“只看失败”。

**建议布局**

- 顶部：`运行中 / 待处理 / 失败 / 最近完成` 四个可点击指标。
- 工具栏：状态 segmented control、类型下拉、ID 搜索、手动刷新。
- 默认视图：只展示活动任务和最近失败；已完成任务分页加载。
- 类型显示中文名为主、内部键为弱化副文本，例如“职位理解 / `job.enrich`”。
- UUID 默认截断为前 8 位，悬停或点击复制查看完整值。
- 桌面每页 25–50 条；移动端改为任务卡片，不强制复用桌面表格。

### UI-004：来源页把低频设置永久展开（P1）

**现状**

每个来源卡片同时展示：健康状态、支持状态、启用状态、4 项指标、最近运行、3 个操作、Cron 输入、计划开关、保存按钮。桌面端重复感强，移动端单张卡约 906px 高，10 张卡约 9703px。

**建议布局**

1. 默认卡片只保留公司、状态、最近成功、下次执行和主操作“立即同步”。
2. “健康检查”“启停”和计划配置放入 `更多` 菜单或可展开的“高级设置”。
3. 最近运行详情默认折叠；失败来源可自动展开错误摘要。
4. 允许按“需关注”排序，并在顶部增加 `健康 / 退化 / 未知` 汇总。
5. Cron 不应作为主要语言。默认提供“每天 03:00”等可读选项；仅在“自定义”时显示 Cron。

### UI-005：移动端数据表需要独立信息架构（P1）

**证据**

- 390px 视口下，职位表实际宽约 630px，任务表约 626px。
- 页面使用 `.table-scroll { overflow-x: auto; }`，技术上避免了全局横向溢出，但没有视觉提示用户可以横向滚动。
- 操作列位于最右侧，移动端首次进入时不可见。

**建议**

- 职位移动端改为卡片：标题、公司、地点、状态、匹配分为首屏字段，更新时间作为次要信息。
- 任务移动端改为卡片：状态和操作固定在卡片顶部/底部，不使用 6 列表格。
- 如果保留横向表格，增加右侧渐隐/“横向滑动查看更多”提示，并将首列 sticky；操作列也可 sticky 到右侧。
- 表头在滚动长列表时保持 sticky。

### UI-006：按钮和控件状态不完整（P1）

**证据**

- 全局按钮基础样式见 `apps/web/app/styles.css:171-181`，没有统一的 `:hover`、`:active`、`:disabled` 和 loading 样式。
- 当前只有首页大按钮、导航和指标卡具有专门 hover 反馈。
- SourceActions 在 busy 时一次禁用整张卡的多个动作，但视觉上缺少明确的“正在同步/正在检查/正在保存”动作级反馈。

**建议设计令牌**

| 状态     | 主按钮建议                                      |
| -------- | ----------------------------------------------- |
| Default  | `#1E6546` 背景、白字                            |
| Hover    | 背景加深 6–8%，轻微 `translateY(-1px)`          |
| Active   | 取消位移，内阴影表达按压                        |
| Focus    | 保留当前 3px 橙色焦点环                         |
| Disabled | 40–50% 不透明度、`not-allowed`、无阴影          |
| Loading  | 保持原宽度，左侧 14px spinner，文案描述当前动作 |

统一给链接按钮、次级按钮、危险按钮和 icon button 定义同一状态矩阵，避免页面级零散覆盖。

### UI-007：404 和错误状态不属于同一产品（P1）

**证据**

- `/agent-runs/<不存在的 ID>` 显示 Next.js 默认黑底英文 404，顶部仍保留白色 JobHunter 导航，形成明显割裂。
- 职位拥有局部 `not-found.tsx`，Agent 运行没有，应用根目录也没有统一 `not-found.tsx`。

**建议**

- 新增 `apps/web/app/not-found.tsx`，采用与现有空状态相同的浅色背景、图标、中文说明和返回工作台按钮。
- Agent 运行页可增加局部 not-found，主行动返回任务页。
- 错误页使用标准窄内容容器，不要让标题和按钮悬在大面积空白中。

### UI-008：来源操作错误会显示成成功色（P1）

**证据**

- `apps/web/app/sources/source-actions.tsx:18-51` 用同一个 `feedback` 字符串承载成功和异常。
- `apps/web/app/styles.css:883-887` 将 `.action-feedback` 固定为绿色。

**建议**

将反馈建模为 `{ tone: 'success' | 'error' | 'info', message: string }`；错误使用 `role="alert"` 和红色图标/边框，成功使用 `role="status"`。错误文案应留在当前来源卡内，但不要导致整张卡高度大幅跳动。

### UI-009：职位筛选应从常驻卡片改为弹出框（P2）

**现状**

8 个输入项全部常驻在页面顶部，其中“个人资料版本 ID”要求用户输入 UUID，“公司”则需要手动输入名称。筛选卡片长期占用较大首屏空间，主要列表内容被向下推移。

**建议**

- 移除常驻筛选卡片，在职位列表工具栏中提供“筛选”按钮；点击后打开 Popover 或侧边抽屉。桌面端优先使用锚定按钮的弹出框，移动端使用底部抽屉，避免小屏弹窗拥挤。
- 弹出框内包含关键词、公司、地点、职位族、状态、排序、最低分和资料版本；底部固定“重置”和“应用筛选”操作。
- “公司”由自由文字输入改为下拉选项，选项来自当前职位数据中的公司集合，并显示公司名称；职位量较大时使用可搜索下拉框。
- “个人资料版本 ID”替换为资料名称/版本下拉，默认自动选当前版本。
- 已生效条件在工具栏下方以可删除 chip 展示；“清除全部”只在存在筛选条件时显示。
- “筛选”按钮通过 badge 显示已生效条件数量，关闭弹出框后仍能看出当前处于筛选状态。
- 结果摘要同时显示总数和当前排序，例如“998 个职位 · 最近更新”。

### UI-013：职位列表缺少显式刷新按钮（P2）

**建议**

- 在职位列表工具栏右侧提供带刷新图标的“刷新”按钮，与“筛选”按钮并列。
- 刷新必须保留当前筛选、排序、游标/分页和滚动位置，只更新列表数据及结果摘要。
- 请求期间保持旧列表可见，按钮显示“正在刷新…”并禁用重复点击；成功后播报更新时间，失败时显示非阻断错误和“重试”。
- 显式刷新只刷新本地数据库查询结果，不应隐式触发所有招聘来源的网络同步；来源同步仍由来源页单独控制。

### UI-014：只保留国内职位数据（P1）

**证据**

- 当前数据库至少包含利雅得 15 条、迪拜 7 条、多哈 5 条，共 27 条明确境外地点职位。
- 境外职位已经进入本地 `jobs` 表，因此仅在 Web 列表临时隐藏不能修正首页指标、匹配任务、导出和后续统计。

**建议实现**

1. 将产品地域口径明确为“中国大陆职位”；如港澳台需要支持，应作为独立可配置口径，不与境外城市判断混在一起。
2. 在来源 Adapter 的 normalize 边界统一输出标准地域信息，例如 `countryCode`、`regionCode` 和规范城市名；不要只依赖自由文本地点。
3. 在同步写库前应用国内地域策略：只有能确认属于允许地域集合的职位才能进入正常职位流水线；境外和无法判断的记录进入带原因的跳过统计，不创建 Job。
4. 不能仅靠中文字符判断国内地点。应使用国家代码、来源字段和维护的省/市/区划表；“远程”“全国”“多地”等特殊值需单独定义策略。
5. 对历史数据执行一次可预览的清理/关闭迁移，先输出受影响职位数量和地点分布，再从有效职位、匹配结果和首页指标中移除。
6. 同步结果增加 `skipped_non_domestic`、`skipped_unknown_region` 统计，来源页可查看但不把这些记录计入可申请职位。

**验收标准**

- 新同步数据中不存在政策范围外的境外职位。
- 首页职位数、职位列表、匹配任务和导出均只统计国内职位。
- 利雅得、迪拜、多哈等既有记录不再出现在有效职位和匹配结果中。
- 无法识别地域的记录被明确记录为跳过原因，不被静默当作国内职位。

### UI-015：增加“校招/社招/实习”类别筛选，默认实习（P1）

**证据**

- 当前来源级字段只有 `social | campus | mixed`，不足以区分同一校园来源中的校招和实习。
- 当前职位数据实际包含：社招全职约 2801 条、实习约 535 条、校招约 159 条，以及约 393 条含糊的“校招/实习”。
- 职位筛选契约和 Web 查询参数当前没有统一招聘类别字段。

**建议实现**

1. 在职位领域数据中增加规范化字段 `recruitmentCategory`，取值固定为 `internship | campus | social`，并在 Web 端显示为“实习 / 校招 / 社招”。该字段应属于职位，而不是只属于来源。
2. 各 Adapter 在边界根据官方字段和入口类型映射类别；不能把“校招/实习”作为长期有效值。无法确定时应标为待归类并进入质量统计。
3. 在筛选弹出框顶部使用单选 segmented control 或 radio group：`实习`、`校招`、`社招`；默认选中“实习”。
4. URL 显式保存类别，例如 `category=internship`。首次进入 `/jobs` 且 URL 未指定类别时采用实习默认值；用户选择其他类别后，刷新和分页必须保持该选择。
5. 类别按钮可显示结果数量，但数量应来自同一查询口径，不能使用缓存中的全量近似值误导用户。

**验收标准**

- 首次打开 `/jobs` 默认只展示实习职位，筛选控件明确显示“实习”已选中。
- 切换校招、社招后结果集合正确，刷新、分页和复制 URL 后类别不丢失。
- 每个有效职位只能归入一个规范类别；“校招/实习”等含糊值完成迁移或明确进入待归类集合。

### UI-016：“职位族=研发”精确匹配导致错误零结果（P1）

**证据**

- `/jobs?family=研发` 当前显示“没有符合条件的职位”。
- `packages/db/src/repositories/job-query-repository.ts:133` 使用 `j.job_family IN (...)` 精确匹配。
- 当前数据库中 `job_family = '研发'` 为 0 条，但职位族、部门或标题包含“研发”的职位约 291 条；常见职位族实际使用“技术”“技术类”“后端开发”“大模型”“策略算法”等值。

**建议实现**

1. 短期修复：职位族筛选不能把用户自由输入直接当作精确枚举。至少对规范职位族、标题和部门执行统一的包含检索，并覆盖“研发”用例。
2. 长期方案：建立跨来源的职位族规范 taxonomy，例如将“技术”“技术类”“研发”“后端开发”“算法”等来源值映射到稳定的规范族；数据库同时保留原始值和规范值。
3. 筛选弹出框中的“职位族”改为规范分类的多选下拉，不再要求用户猜测来源原始值；可在选项下展示代表性子类。
4. “研发”可作为“技术/研发”规范族的搜索别名。别名只负责找到规范选项，最终查询使用规范 ID，避免不同来源文案导致结果漂移。
5. 零结果状态显示当前生效条件，并提供一键移除“职位族：研发”，便于用户理解结果为何为空。

**验收标准**

- 选择或搜索“研发”能返回技术研发相关职位，不再错误显示 0 条。
- 不相关的运营、销售职位不会因描述偶然出现“研发”而大量误入结果。
- 至少为“研发/技术、产品、设计、运营、销售、职能”建立跨来源映射测试。

### UI-010：简历导入控件过于原生（P2）

**现状**

原生文件选择控件与圆角卡片、按钮语言不一致。上传后 800ms 自动刷新，用户可能来不及阅读任务 ID；任务 ID 本身也不是用户最关心的信息。

**建议**

- 改为拖拽/点击上传区，显示 PDF/DOCX 图标、文件名、大小和移除按钮。
- 选中文件后主按钮文案变为“导入并生成资料”。
- 上传进度使用确定/不确定进度条；完成后显示“已创建资料提取任务”，任务 ID 放入可展开详情。
- 不要 800ms 强制刷新；改为轮询导入任务状态并原地切换到“生成中”，或至少给用户 3–5 秒阅读反馈。

### UI-011：移动端首屏垂直节奏偏松（P2）

普通页面的 `main` 使用 `padding: 5rem 0`，移动端没有统一收紧；`PageHeader` 在 900px 以下改为纵向后仍继承较大的 gap。结果是标题、描述和第一个内容区之间产生过多空白。

建议在 600px 以下将普通页面顶部/底部 padding 调整为 `2.5rem / 3.5rem`，PageHeader gap 调整为 `1rem`，H1 使用约 `2.25–2.75rem`，描述行高 `1.65`、最大宽度约 `34ch`。

### UI-012：缺少减少动态效果支持（P2）

`styles.css` 中存在导航、标签和卡片位移动画，但没有 `prefers-reduced-motion`。建议增加：

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

## 5. 分页面审计

### 工作台 `/`

**优点**

- Hero 是全站完成度最高的区域，主次 CTA、品牌色和下一步提示都清楚。
- 四个指标卡颜色区分克制，没有落入“彩色仪表盘”的噪声。
- “三步开始使用”很好地把产品能力翻译成用户目标。

**改进**

- “待办任务 2000”是首页视觉权重最大的数字之一，但用户不知道是积压、批处理还是异常。建议显示“2,000 待处理”，并增加趋势/处理速率或“其中 2 个失败”的更强告警层级。
- Hero 主文案在 390px 下约占 161px 高，整张 Hero 几乎占满首屏。可把手机字号上限收至约 3.25rem，并缩短文案上下间距，让首屏露出至少一部分概览指标。
- “LOCAL-FIRST”等英文 eyebrow 形成风格，但不应成为信息理解的前置条件；保持装饰性即可。

### 职位列表 `/jobs`

**优点**

- 表格扫描路径清楚，职位标题、部门副文本、状态和匹配分层级合理。
- URL 保存筛选条件，方便分享和返回。

**改进**

- 数据源与同步流水线只保留国内职位；境外与地域不明记录不进入有效职位集合。
- 筛选弹出框顶部增加“实习 / 校招 / 社招”类别选择，首次进入默认“实习”。
- 职位标题直接打开实际官方招聘页面，不再进入自建站内详情页。
- 用工具栏“筛选”按钮打开筛选弹出框；公司和资料版本均使用下拉选择，公司选项支持搜索。
- “职位族”使用规范分类多选与别名搜索，“研发”映射到技术/研发类别，不再对来源原始文本做精确等值查询。
- 在列表工具栏提供显式“刷新”按钮，使用刷新图标和“刷新”文字；点击后重新获取当前 URL 筛选与分页条件下的数据，而不是清空条件或跳回第一页。
- 刷新期间按钮进入 loading/disabled 状态并显示“正在刷新…”，完成后在 `aria-live` 区域提示“职位列表已更新”和更新时间；失败时保留旧列表并显示可重试错误。
- 行 hover 使用非常浅的绿色背景，并让整行可点击，但保留标题链接语义。
- 地点过长时限制为两行并显示“+N”；避免挤压状态和日期列。
- 增加页码/总量或“已加载 25 / 998”，当前仅有下一页，用户缺少位置感。

### 职位实际页面（外部官网）

本项目不再自行实现职位详情页。职位列表中的职位标题直接跳转到数据源提供的实际官方招聘页面：

- 默认优先打开 `detailUrl`；仅在其缺失时回退到 `applyUrl`。
- 外链必须经过既有官方 HTTPS URL 校验，并在新标签页打开。
- 列表中的外链图标和可访问名称需明确说明“打开官方职位页面”。
- 本地匹配分、状态、更新时间等信息留在职位列表，不需要为承载这些信息再建设完整详情页。

### 个人资料 `/profile`

当前数据库只存在“资料正在生成”状态，无可视化的已生成资料和删除流程。

**改进**

- 优化文件导入控件和原地进度反馈。
- “正在生成”状态增加步骤：已上传 → 正在提取 → 正在生成画像，并显示最近更新时间。
- 提供“查看任务”链接，避免用户只能刷新页面。
- 已生成状态中的原始 JSON/有效 JSON 是开发者视图，不宜默认展开；默认展示结构化资料，JSON 放入“开发者详情”。

### 招聘来源 `/sources`

**优点**

- 官网/平台来源的 segmented tabs 视觉清楚。
- 健康、支持和启用状态有明确文本，不只依赖颜色。
- 招聘平台空状态简洁，返回路径清楚。

**改进**

- 大幅收起低频设置，并优先呈现异常来源。
- “退化”“未知”的视觉区分可再加强；未知应中性，退化应强调可操作原因。
- 将 `unknown` 等英文覆盖状态完整本地化，用户界面不应混入内部枚举值。
- 增加最后同步耗时/职位变化数，使“是否值得立即同步”更易判断。

### 任务与 Agent 运行 `/tasks`

**优点**

- 任务和 Agent 运行分区合理，状态标签易识别。
- 诊断视图主动说明不显示载荷和模型原文，隐私边界明确。

**改进**

- 先集中修复轮询，再增加过滤、分页和移动端卡片。
- 将“任务”与“Agent 运行”改为 tabs，避免用户为看 Agent 记录先滚过大量任务。
- 错误摘要限制两行，点击展开；当前错误列可能导致行高失控。
- 失败任务的“重试”应为明确主操作；运行中任务的“取消”使用危险/警示语义，不宜与普通次级按钮完全一致。

### Agent 运行详情 `/agent-runs/:id`

当前无真实 Agent 运行记录，无法完成真实数据视觉验收；不存在 ID 会落入黑底默认 404。

基于代码建议：模型配置指纹使用截断+复制；Token 和成本用 tabular numbers 右对齐；工具调用按失败优先并支持展开错误；返回任务使用带箭头的标准 back link，而不是页面标题右侧普通文本链接。

### 错误和空状态

- 空状态总体统一且行动明确。
- 全局错误页文案过于笼统，错误原因和建议动作经常不匹配。
- 根级 404 缺失，必须统一为产品语言和视觉。
- 错误页面至少提供一个“离开当前页”的次级动作，避免只允许重试。

## 6. 建议的视觉规范

### 色彩

保留当前绿色主色体系。建议把语义色固定为设计令牌，并确保文本对比度不低于 WCAG AA：

| 语义    | 前景      | 背景      | 用途               |
| ------- | --------- | --------- | ------------------ |
| Primary | `#1E6546` | `#E2F1E8` | 主行动、成功、健康 |
| Info    | `#316D8B` | `#E3F1F7` | 处理中、信息       |
| Warning | `#8A5812` | `#FFF0D1` | 退化、待确认       |
| Danger  | `#8E2F26` | `#FFE7E2` | 失败、危险操作     |
| Neutral | `#4E5751` | `#E7EAE8` | 未知、已关闭、禁用 |

不要让所有反馈都使用绿色；反馈颜色必须跟成功、错误、警告语义一致。

### 字体与层级

- 正文：系统中文无衬线优先，16px，行高 1.65–1.75。
- 页面 H1：桌面 56–64px；移动 36–44px。仅首页 Hero 可更大。
- H2：24–28px；卡片标题 18–22px。
- eyebrow：11–12px，字距不超过 `0.14em`；英文仅作为视觉标签。
- 数字、Token、成本、时间统一 `font-variant-numeric: tabular-nums`。
- UUID/内部键使用等宽字体，但字号不低于 12px，默认截断。

### 间距与密度

建议以 4px 为基础栅格，常用间距为 8/12/16/24/32/48。管理页卡片内部优先 16–24px；列表行桌面高度控制在 56–72px。移动端每张普通卡片尽量不超过 280px，高级设置展开后例外。

### 圆角与阴影

当前 8px 控件、16px 卡片、24px Hero 的层级合理，可保留。普通卡片阴影进一步弱化，仅在 hover 或浮层中增强；列表型卡片主要靠边框分隔，避免每一项都像悬浮模块。

### 图标

当前箭头、星形、旋转符号多为 Unicode 字符，粗细和基线不统一。建议引入一套 16/20px 线性 SVG 图标，并统一 `stroke-width`、尺寸、对齐和无障碍隐藏规则。

## 7. 推荐实施顺序

### 第一阶段：阻断问题

1. 将职位标题改为直接打开经过校验的实际官方招聘页面，移除对自建详情页的依赖。

### 第二阶段：高密度页面重构

1. 任务页增加汇总、筛选、分页和移动端卡片。
2. 来源卡片默认收起高级设置，增加异常优先排序。

6. 清理既有境外职位，并校正首页、匹配和导出统计口径。
7. 职位和任务表增加 sticky header、移动端方案和滚动提示。

### 第三阶段：微交互与设计系统

1. 完成按钮/链接/表单的状态矩阵。
2. 优化简历上传、进度和生成状态。
3. 统一 SVG 图标、数字字体、截断和复制行为。
4. 增加 reduced-motion、触屏和键盘回归测试。

## 9. 审计限制

- 当前本地数据库没有 Agent 运行记录，因此 Agent 详情只能审查不存在记录状态和源代码结构，不能验收真实工具调用数据下的视觉效果。
