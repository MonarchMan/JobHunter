# JobHunter 全系统 UI 重设计指导

- 日期：2026-08-24
- 文档类型：设计指导与改造清单
- 适用范围：`apps/web` 全部页面、共享组件与全局样式
- 当前阶段：指导方案，尚未实施
- 关联规格：`specs/011-web-console/spec.md`、`specs/011-web-console/design.md`
- 关联审计：`docs/reports/ui-audit-2026-08-22.md`

## 1. 目标与设计判断

JobHunter 是面向个人求职者的本地工作台。它的核心价值不是展示数据，而是帮助用户在“建立画像、发现职位、判断是否适合、处理后台任务、前往官网投递”之间快速做出下一步决定。

本次重设计需要同时达成以下目标：

1. 去除现有绿色主视觉，建立不依赖绿色的新品牌色体系。
2. 从展示型大页面转为高效率、低干扰的个人求职控制台。
3. 统一导航、表格、表单、状态、反馈、弹层和移动端行为。
4. 使用克制且连续的动效提升反馈质量和页面质感。
5. 保留现有首页已经形成的品牌意识，但降低非首页页面的大标题与留白。
6. 满足 WCAG 2.2 AA，并完整支持键盘和 `prefers-reduced-motion`。

设计北极星是“正在整理中的个人求职档案”：界面应当像一套清晰、可信、随时可继续处理的职业资料，而不是通用 SaaS 模板、招聘网站广告页或开发者监控台。

明确避免：

- 不继续使用绿色作为品牌色、按钮色或大面积背景。
- 不使用深黑背景配荧光色的通用“AI 科技风”。
- 不用大量渐变、玻璃拟态和漂浮光斑制造高级感。
- 不把每段内容都包装成大圆角卡片。
- 不用连续循环动画干扰阅读。
- 不在普通页面沿用首页级别的超大标题。

## 2. 当前主要问题

根据代码检查和桌面端、390px 移动端实测，当前问题主要集中在以下方面：

| 范围     | 当前表现                                                       | 改造要求                                         |
| -------- | -------------------------------------------------------------- | ------------------------------------------------ |
| 全局     | 绿色承担品牌、操作和状态等过多职责                             | 改为深靛蓝主色，状态色独立建模                   |
| 样式基础 | `styles.css` 存在两组 `:root`，并散落大量直接颜色值和圆角值    | 建立单一语义令牌源，逐步移除硬编码               |
| 字体     | 声明了 Inter 和 Noto Sans SC，但未形成清晰、可靠的字体加载方案 | 本地化字体资源并区分中文、英文数字和诊断数据角色 |
| 页面标题 | 管理页面使用过大的 H1 与顶部留白                               | 首页保留品牌尺度，工作页面改用紧凑标题           |
| 职位列表 | 一页内容过长、字段拥挤、筛选层级不足                           | 缩减默认字段和行数，建立常用/高级筛选层级        |
| 来源     | 一个来源卡片同时展示摘要、运行、计划、统计和设置               | 改为摘要列表与详情抽屉                           |
| 任务     | 技术类型、完整 UUID 等实现语言占据主要位置                     | 默认使用用户语言，技术信息移入详情               |
| 刷新     | 任务页面每 3 秒整页刷新                                        | 改为可感知但不闪动的增量刷新                     |
| 移动端   | 职位页约 4270px 高，来源页约 8160px 高                         | 为移动端重新选择字段与操作，不只缩窄桌面布局     |
| 交互反馈 | hover、pressed、busy、success、error 反馈仍不完整              | 统一组件状态和动效语言                           |

## 3. 新主题：档案靛蓝

### 3.1 色彩系统

新的品牌系统使用“档案靛蓝 + 雾蓝灰 + 珊瑚行动色”。深靛蓝来自档案墨水和批注工具的意象，适合表达可信、判断与长期使用；珊瑚色只用于当前最值得执行的行动，形成属于 JobHunter 的决策光标。

#### 基础令牌

| 令牌                    | 值        | 用途                             |
| ----------------------- | --------- | -------------------------------- |
| `--color-ink`           | `#1C2130` | 主文字、深色图标                 |
| `--color-ink-muted`     | `#667085` | 次要说明、时间、元数据           |
| `--color-canvas`        | `#F5F6FA` | 应用背景                         |
| `--color-surface`       | `#FFFFFF` | 面板、表格、弹层                 |
| `--color-line`          | `#DEE2EC` | 边框与分隔线                     |
| `--color-primary`       | `#4E5FBB` | 主按钮、当前导航、可交互强调     |
| `--color-primary-hover` | `#3F4E9A` | 主色 hover                       |
| `--color-primary-soft`  | `#E9ECFF` | 选中项、轻量提示背景             |
| `--color-action`        | `#E06C5D` | “下一步行动”、关键数量和流程光标 |
| `--color-action-soft`   | `#FDECE9` | 行动提示背景                     |

#### 语义色

语义状态不得复用品牌色，也不得只靠颜色传达：

| 语义        | 前景      | 背景      | 辅助表达            |
| ----------- | --------- | --------- | ------------------- |
| 成功/完成   | `#236A8D` | `#E6F3F8` | 对勾 + 明确状态文字 |
| 信息/运行中 | `#4E5FBB` | `#E9ECFF` | 进度图标 + 状态文字 |
| 警告/退化   | `#9A6514` | `#FFF3D8` | 感叹号 + 可恢复说明 |
| 失败/危险   | `#A13D32` | `#FCEBE8` | 错误图标 + 修复操作 |
| 中性/停用   | `#5E6675` | `#EEF0F4` | 中性图标 + 状态文字 |

禁止为“成功”重新引入绿色。成功状态使用清晰的蓝青色、图标和文字共同表达。

### 3.2 字体

- 中文正文和控件：本地加载 `Noto Sans SC` 或 `Source Han Sans SC`。
- 英文标题与数字：`Geist Sans` 或 `Inter`。
- UUID、Token、版本、成本等诊断数据：`IBM Plex Mono`。
- 正文基准：16px/1.6；密集表格可用 14px/1.45。
- 页面 H1：桌面 36px，移动端 30px；首页 Hero 可单独使用 56–64px。
- 禁止依赖 `letter-spacing` 强行拉开中文标题。

### 3.3 形状、边框和阴影

- 普通控件圆角：8px。
- 面板和弹层圆角：12px。
- 状态标签圆角：6px，不默认使用完整胶囊形。
- 静态内容以边框区分层级，不给所有卡片加阴影。
- 抽屉、弹窗、浮层允许使用统一中等阴影。
- 点击目标最小高度 44px，紧凑表格行高建议 56–64px。

### 3.4 标志性元素：决策光标

“决策光标”是一条 3px 的珊瑚色竖线或短横线，只出现在“当前最应该处理的事项”旁，例如：

- 首页的下一步行动。
- 职位详情的核心判断。
- 失败任务的首要恢复入口。
- 画像缺失信息的当前步骤。

它不用于普通标题、所有卡片或纯装饰区域。全系统只在决策节点使用，以形成记忆点并维持克制。

## 4. 全局布局与导航

### 4.1 桌面端

在宽度大于 1024px 时使用固定宽度的左侧导航；工作区根据内容类型选择宽度，而不是所有页面共用同一窄容器。

```text
┌──────────┬──────────────────────────────────────────────┐
│ JobHunter│ 页面标题                         页面级操作 │
│          ├──────────────────────────────────────────────┤
│ 工作台   │ 摘要、筛选或状态                           │
│ 职位     │                                              │
│ 个人资料 │                 工作区域                     │
│ 来源     │                                              │
│ 任务     │                                              │
│ 设置     │                                              │
└──────────┴──────────────────────────────────────────────┘
```

- 左侧导航宽度建议 216–232px。
- 表格与诊断页最大宽度 1440px。
- 普通详情页最大宽度 960–1120px。
- 表单与设置页最大宽度 640–760px。
- 导航当前项使用浅靛蓝背景、深靛蓝文字和 3px 决策光标。

### 4.2 移动端

移动端使用顶部品牌栏和四项底部导航：工作台、职位、资料、更多。来源、任务和设置进入“更多”页面或导航抽屉。

- 不能把六个顶部文字链接压缩在一行。
- 底部导航需要处理安全区域和虚拟键盘。
- 页面主要操作可在必要时放入底部固定操作栏，但不得遮住表单错误或聚焦字段。

### 4.3 页面标题

- 首页使用品牌型 Hero。
- 工作页面使用紧凑标题栏：眉题可删除或缩小，不再占据一整屏。
- 标题右侧只保留一项主要操作，次要操作进入菜单或工具栏。
- 每个路由设置明确标题，如“职位 — JobHunter”“任务 — JobHunter”。

## 5. 全局动效系统

动效的目标是解释界面变化、维持空间连续性和确认操作结果。动效不承担装饰职责。

### 5.1 动效令牌

```css
:root {
  --motion-fast: 120ms;
  --motion-standard: 180ms;
  --motion-emphasis: 260ms;
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-standard: cubic-bezier(0.4, 0, 0.2, 1);
  --ease-in: cubic-bezier(0.4, 0, 1, 1);
}
```

原则：

- hover 和 pressed 使用 120ms。
- 折叠、Toast、局部内容切换使用 180ms。
- 抽屉和对话框使用 220–260ms。
- 常规产品动效不得超过 320ms。
- 优先动画 `opacity` 和 `transform`，避免频繁动画高度、宽度、阴影和模糊。
- 不使用永久漂浮、呼吸光圈、连续背景移动或无限旋转装饰。

### 5.2 组件动效

| 组件/场景         | 动效                                            | 约束                             |
| ----------------- | ----------------------------------------------- | -------------------------------- |
| 主导航            | 活动背景淡入，决策光标平移                      | 180ms，不移动页面内容            |
| 按钮 hover        | 颜色过渡并上移 1px                              | 120ms，触屏不依赖 hover          |
| 按钮 pressed      | `scale(0.98)`                                   | 80–120ms，按钮尺寸不变化         |
| 卡片/表格行 hover | 背景变为 `primary-soft`，可操作行上移不超过 1px | 普通静态卡片不浮起               |
| 筛选面板          | 透明度 + `translateY(-4px → 0)`                 | 180ms，焦点顺序不变              |
| 抽屉              | 遮罩淡入，面板 `translateX(16px → 0)`           | 240ms，关闭后恢复焦点            |
| 对话框            | 遮罩淡入，内容 `scale(0.98 → 1)`                | 220ms，初始焦点符合风险等级      |
| Toast             | `translateY(8px → 0)` + 淡入                    | 180ms，位置稳定且可读            |
| 列表刷新          | 仅变化行短暂淡入，状态徽标交叉淡化              | 禁止整页闪白或滚动位置跳动       |
| 空状态到数据      | 空状态淡出，数据区域淡入                        | 保持容器最小高度，避免布局跳跃   |
| 数字更新          | 旧值淡出、新值淡入                              | 不使用滚轮数字导致持续注意力竞争 |
| 加载              | 固定尺寸进度指示，不改变控件宽度                | 长任务显示阶段或真实进度         |

### 5.3 页面切换

- 支持时可用 View Transitions API 对页面标题和主内容做 160–200ms 的轻量淡入。
- 左侧导航和应用壳层保持不动，避免每次切页整体重播。
- 返回列表时恢复筛选、页码和滚动位置，不使用动画掩盖状态丢失。
- 首次首页进入可以有一次编排式动效：标题、说明、主行动依次以 40ms 间隔出现；后续路由不重复。

### 5.4 减少动态效果

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

减少动态效果后仍必须保留颜色、文字、焦点和状态反馈，不能让动画成为唯一的状态表达。

## 6. 页面改造清单

### 6.1 工作台

- 首次使用保留完整 Hero；画像和来源就绪后自动切换为紧凑的“今日行动”区。
- 将“下一步行动”作为决策光标的主要使用场景。
- 指标卡只保留可采取行动的数据，并补充异常原因或下一步入口。
- 增加“推荐职位”“需要处理”“最近活动”三个区域。
- 指标加载完成时使用一次 180ms 淡入，不使用滚动数字。
- 最近活动新增项只高亮变化行，不重新加载整个区域。

### 6.2 职位列表

- 常用筛选仅保留关键词、地点、公司和匹配度。
- 类别、状态、排序和画像版本进入“更多筛选”。
- 将内部“个人资料版本 ID”改为可读的画像版本名称或“当前画像”。
- 默认每页 20 条，支持紧凑/舒适密度切换。
- 桌面列精简为职位、公司与地点、匹配、更新时间、操作。
- 职位标题进入系统详情，单独提供“官网投递”操作。
- 选中的筛选条件显示为可移除标签，清除操作立即生效并保持输入焦点。
- 筛选结果更新时保留表格框架，内容进行 120–180ms 淡化替换。
- 移动端使用职位卡片，每张卡只保留决策所需信息。

### 6.3 职位详情

- 信息顺序调整为：核心判断、证据、职位内容、来源信息、技术详情。
- 页面顶部提供“官网投递”和“重新匹配”，只允许一个高强调主按钮。
- 匹配分、证据和风险使用文字、图标与颜色共同表达。
- 修订历史和 Agent 信息默认折叠。
- 匹配任务创建后保持按钮尺寸，显示进度并局部刷新结果。
- 新结果出现时突出变化区域 800ms，随后恢复正常背景。

### 6.4 个人资料

- 划分为简历文件、经历与技能、求职偏好、版本与数据管理。
- 页面顶部显示画像完整度和当前缺失项。
- 文件上传改成产品化上传区，覆盖选择、上传、解析、提取、完成、失败状态。
- 字段锁定、来源值和版本差异放入字段详情，不长期占用主页面。
- 自动保存明确显示“正在保存、已保存、保存失败”，但不反复弹 Toast。
- 字段展开使用 180ms disclosure 动效，错误出现时不得推动主操作离开视口。

### 6.5 招聘来源

- 将大卡片列表改为紧凑摘要表或列表。
- 默认字段为公司、来源类型、健康、启用状态、最近同步、下次执行。
- 点击来源打开右侧详情抽屉。
- “立即同步”保留为行级快捷操作。
- Cron、适配器 ID、统计和高级配置移入抽屉。
- 顶部增加健康汇总和快速筛选。
- 来源同步开始后，状态徽标平滑切换为“等待中/同步中”，禁止整张卡片闪动。
- 移动端每个来源摘要控制在约 100–140px 高。

### 6.6 任务与 Agent 运行

- 拆成“后台任务”和“Agent 运行”两个路由级标签页。
- 顶部增加待处理、运行中、失败和已完成汇总。
- `source.sync` 等技术名称默认翻译为用户可读文本。
- UUID 默认显示短 ID，完整值放到详情并提供复制按钮。
- 失败原因使用独立错误区域，并直接提供重试或查看详情。
- 活动数据使用单一页面级查询或推送机制增量更新；页面隐藏时暂停轮询。
- 状态更新仅交叉淡化对应徽标和行，不刷新整个页面。
- 长诊断信息使用右侧抽屉；危险确认继续使用模态对话框。

### 6.7 设置

- 按“匹配与模型、同步、数据与隐私、界面”分组。
- 每项设置使用标题、影响说明和控件三段式结构。
- 即时保存显示稳定的局部保存状态。
- 危险数据操作放入独立区域，并使用危险语义色。
- 普通设置不使用卡片堆叠，优先采用分组列表和分隔线。

### 6.8 空状态、错误与 404

- 空状态说明当前为什么为空，并提供唯一、明确的下一步。
- 404、路由错误和资源不存在页面继续保留应用导航。
- 错误内容不得显示堆栈、原始模型输出或敏感任务载荷。
- 重试只更新失败区域，不重新进入整页加载状态。
- 错误出现使用 180ms 淡入，不使用抖动、闪烁或红色呼吸动画。

## 7. 需要建立的共享基础

实施前应建立或规范以下共享所有者：

- `DESIGN.md`：记录本报告批准后的视觉令牌、字体、密度、形状和动效。
- `UX-CONTRACT.md`：记录导航结果、筛选恢复、异步状态、错误恢复、确认和焦点行为。
- 全局语义令牌与单一 `:root`。
- `Button`：emphasis 与 intent 两轴，覆盖 hover、active、focus、busy、disabled。
- `Field`、`Select`、`SearchField` 和表单错误。
- `StatusBadge`、`Alert` 和内联状态。
- `Dialog`、`AlertDialog`、`Drawer`、`Toast`。
- `DataTable`、移动端记录卡、筛选工具栏和分页。
- `EmptyState`、`LoadingState`、`ErrorState`。
- 动效令牌和 `prefers-reduced-motion` 基线。
- 全局可见且稳定的滚动条样式。

共享基础未就绪前，不应按页面复制颜色、动画时长或弹层实现。

## 8. 实施顺序

### 阶段 0：冻结新增漂移

- 创建 `DESIGN.md`、`UX-CONTRACT.md` 和迁移台账。
- 记录现有页面截图、状态和响应式基线。
- 禁止新增绿色品牌色、直接色值、页面局部动画常量和重复弹层。

### 阶段 1：全局基础

- 替换全局颜色、字体、背景、边框、焦点和滚动条。
- 实现新导航壳层和响应式导航。
- 建立按钮、状态、反馈、弹层和动效组件。

### 阶段 2：核心求职链路

- 职位列表。
- 职位详情。
- 官网投递入口。
- 匹配任务状态和结果刷新。

### 阶段 3：高频运维链路

- 任务与 Agent 运行。
- 招聘来源。
- 增量刷新和错误恢复。

### 阶段 4：个人资料与设置

- 简历上传与画像编辑。
- 设置、保存状态和危险操作。

### 阶段 5：首页收口

- 首页换用新色彩和共享组件。
- 完成首次使用态与日常使用态。
- 将决策光标控制在少量关键位置。

## 9. 验收标准

### 视觉与交互

- 全系统不再使用绿色作为品牌或成功状态色。
- 所有颜色来自语义令牌，旧绿色直接值无残留。
- 同类按钮、筛选、状态和反馈在所有页面表现一致。
- 页面切换、抽屉、对话框、筛选和刷新不存在明显跳动。
- 所有动效遵循统一时长和缓动，不出现无限装饰动画。
- 减少动态效果模式下仍可完整理解和操作界面。

### 响应式与可访问性

- 1280px 以上完成全部工作流，768px 完成主要操作，390px 完成核心只读与关键操作。
- 移动端不再展示六项顶部导航。
- 表格和卡片转换后保留相同状态、排序和操作。
- 键盘可完成筛选、打开详情、关闭弹层、分页和返回。
- 焦点可见，弹层关闭后恢复到触发控件。
- 对比度达到 WCAG 2.2 AA。

### 性能与稳定性

- 任务轮询不再导致每 3 秒整页闪动或滚动位置变化。
- 动画主要使用 `transform` 和 `opacity`，不会持续触发布局计算。
- 加载、成功和错误状态不会改变按钮尺寸或移动主要操作。
- 字体加载、异步数据和滚动条不会产生明显布局偏移。

### 工程验证

- 运行格式检查、类型检查、自动化测试和生产构建。
- 使用 Playwright 覆盖桌面、390px、键盘和减少动态效果。
- 为共享组件补充默认、hover、focus、active、busy、disabled、success、warning、error 状态测试。
- 对工作台、职位列表、来源、任务、个人资料建立代表性视觉回归基线。

## 10. 设计决策摘要

本方案不是简单把绿色替换成另一种颜色。深靛蓝负责建立可信、安静的工作背景；珊瑚行动色只标记真正的下一步；蓝青、琥珀和红色分别承担完成、警告和失败语义。动效围绕“进入、展开、更新、完成”四类状态设计，用空间连续性提升丝滑感，同时避免管理台因过度动画变慢或显得浮夸。

最终体验应让用户感到：信息很多，但界面始终知道此刻最值得处理的是什么。
