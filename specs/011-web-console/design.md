# 011 本地 Web 管理台设计

浏览器回归定位通知时限定通知区域，定位公司时使用完整名称；简历制作使用专属画像种子，不依赖其他测试留下的可变画像状态。

> 状态：Ready

TimePicker 外观为单个 HH:mm 时间框与时钟图标，支持键盘直接输入和小时／分钟双列选择面板，小时覆盖 00–23、分钟覆盖 00–59。面板支持方向键导航、Esc 关闭与外部点击收起，可在原生模态窗口内使用。SelectField 新增可选 compact 尺寸，设置频率与时间选择统一为 32px 高度。设置和来源同步计划共用组件，提交值继续使用 HH:mm。

PageTabs 统一一级分区标题栏，当前链接内使用 h1，其他链接保持同字号。PageHeader 与自定义页标题同步使用 16px。任务与用量的刷新操作各自放入筛选区，保留原自动刷新机制及状态提示。

> 中央调度服务已接入，实际数据迁移按整体三阶段计划执行，见 [ADR-0062](../../docs/adr/0062-central-task-scheduler.md)；验收记录见 003 规格的 tasks.md。

职位详情在 matching 的建议读取边界直接使用当前严格契约，不转换旧引用或合并旧字段。建议 JSON 或结构无效时不展示内容，仅返回建议失败状态，不阻断职位正文。

Agent 中文名称集中登记在 Web 状态标签模块。回归扫描 `apps/` 和 `packages/` 生产源码中的 Agent 定义及提示词 `agentKey`，逐项校验中文名称登记，防止新增类型静默使用通用占位。

职位日期列及移动卡片统一读取 DTO 的 `publishedAt`，复用同一日期展示函数，采用 zh-CN／Asia/Shanghai 与原生 `time` 语义；空值显示“未提供”，不输出无效 time 元素。保持现有 `published_desc` 数据库排序、分页与默认排序设置，不用 `updatedAt` 兜底，也不覆盖用户已保存的排序偏好。

默认设置、Web 查询 Schema 和仓储查询 Schema 均使用 `published_desc`；SQL 使用发布时间 DESC、ID ASC，空日期映射为低于所有合法非负时间的 -1，确保空值最后且游标／数字分页一致。已有显式排序和保存偏好不被重置。

设置表单保留显式保存：复选框 checked 与 automaticScoringEnabled 同向映射，提交前只是本地草稿；页面说明必须提示点击“保存设置”，不宣称即时保存。浏览器验证 Chromium/WebKit 的勾选、取消、保存和重载，后端集成测试验证新修订的评分任务开关。

职位行导航使用共享 `openLinkedRow` 渐进增强，委托给行内真实详情链接；保留 table/article 语义，不把整行改成嵌套按钮。排除交互元素、操作区域、portal 冒泡、已阻止事件、非主键/修饰键及文本选择。详情链接携带列表查询串作为 returnTo，服务端只接受 `/jobs` 或 `/jobs?...`，避免开放重定向。

首页精选职位使用 job_revisions(job_id, revision_no) 唯一索引定位最新修订，移除全量窗口排名与冗余修订关联。进程级 Web 容器通过可重试单例加载器管理：成功永久复用，失败仅缓存 1 秒以限制并发重试风暴，然后由下一请求重试。

## 技术结构

浏览器测试使用本轮 UUID 贯穿 Playwright metadata、夹具子进程环境和仅开发夹具启用的响应头。Next 仅在数据目录位于系统临时目录、具有夹具前缀且 UUID 合法时返回标识；globalSetup 通过只读 GET 验证标识后才允许测试执行。reuseExistingServer 固定 false，端口／baseURL 一致性在配置加载时校验；独立构建目录防止旧标识残留。

`apps/web` 使用 Next.js App Router。Server Components 负责初始查询，Route Handlers 调用应用层 command/query；浏览器端不直接访问 SQLite。耗时 command 返回 202 + task DTO。

```text
apps/web/app/
├─ page.tsx
├─ jobs/
├─ profile/
├─ sources/
├─ tasks/
├─ agent-runs/
├─ settings/
└─ api/
```

## 运行时编排

Web 启动器负责 Next 子进程、主线程调度及有界动态 Worker 线程池。Next 只提供协议入口并通过受限命令桥确认宿主就绪；父连接断开即退出。宿主停止后无任务继续执行；任务处理器变更需完整重启，页面热更新不重复创建调度器。

开发内部宿主加载源码，生产加载 dist，均由 apps 组合根装配四模块；不恢复公开 Worker 包或命令。Next 和内部服务显式接收工作区根目录与数据目录，避免配置路径漂移。

共享 DTO/Schema 位于 `packages/application/contracts`，不把领域实体直接序列化给 UI。

主要 Route Handler：

| 方法与路径                                                | 用途                       |
| --------------------------------------------------------- | -------------------------- |
| `GET /api/dashboard`                                      | 健康与任务摘要             |
| `GET /api/jobs`、`GET /api/jobs/:id`                      | 职位分页与详情             |
| `GET /api/profile`、`PATCH /api/profile`                  | 当前画像与带版本条件的修改 |
| `GET /api/profile/versions`                               | 画像历史                   |
| `GET /api/sources`                                        | 来源与最近运行             |
| `POST /api/sources/:id/sync`                              | 幂等入队同步               |
| `GET /api/tasks`、`GET /api/tasks/:id`                    | 任务查询                   |
| `POST /api/tasks/:id/retry`、`POST /api/tasks/:id/cancel` | 任务操作                   |
| `GET /api/agent-runs/:id`                                 | 脱敏 Agent 运行详情        |
| `GET/POST /api/resumes/:id/deletion`                      | 删除影响预览/确认入队      |
| `GET/PATCH /api/settings`                                 | 读取/修改非敏感系统设置    |

所有响应使用统一 envelope：`{ data, meta?, error? }`；错误包含稳定 code、用户可读 message 和 correlationId，不返回堆栈。

## 列表分页契约

所有 Web 列表返回统一的分页元数据：

```ts
{
  items: T[],
  page: { current: number, total: number, totalPages: number, pageSize: number },
  hasPreviousPage: boolean,
  hasNextPage: boolean
}
```

页面 URL 使用 `page`（任务和 Agent 运行分别使用 `taskPage`、`agentPage`）。数据查询采用稳定排序的 `LIMIT/OFFSET` 与总数查询；旧的内部游标查询仍可供 CLI/导出流程使用。页码控件始终显示首页、末页和当前页附近页码，省略区间使用省略号。

分页底栏左侧显示筛选后的总数，右侧显示每页数量选择，页码居中；窄屏页码独占上行，下行总数与数量选择仍分居左右，不显示“第 m/n 页”。任务详情首个属性为 ID，批量任务在状态属性内呈现进度条与已处理/总数；已处理包含成功、失败和取消，不能把进度百分比当作成功率。批量评分仅从经过校验的任务输入和检查点汇总数量，不向页面暴露原始输入及逐项结果。任务类型选择框按最长选项定宽，并保留“全部”文案。

## 页面信息架构

任务与 Agent 列表的 Web 入口统一解析 `range=today|7d|30d|all`，缺失或无效值回落当天。按北京时间自然日计算，近7/30天包含当天，使用起日零点（含）至明日零点（不含）的 UTC 毫秒边界；任务按创建时间、Agent 按开始时间过滤，详情批次先完整聚合再按批次创建时间过滤。仓储在分页与计数之前应用相同边界，避免批次被拆散；页面和 API 共用边界解析，清除筛选恢复当天，分页、每页数量和币种切换保留范围。内部诊断查询不传边界时仍可显式读取完整历史。

任务表格的耗时列复用公共文本悬停提示，显示完整“开始 - 完成”时间；鼠标悬停与键盘聚焦均可查看，不设置原生 title，避免提示样式重复。提示通过手动 Popover 进入浏览器顶层，绕开表格滚动区域裁剪；以触发文本中心对齐，视口边缘收窄换行，滚动和缩放时同步定位，Escape 关闭提示。

原值与提示面板共享悬停保持状态，离开后延迟 250ms 关闭，移入任一处取消关闭；面板允许鼠标停留和选择文本，点击不触发行详情或外层链接导航。

数值输入统一使用公共 NumberField，保留原生 number 输入的键盘、表单提交、范围与步长校验，隐藏系统调节器，使用项目样式的上下箭头按钮。支持受控/非受控输入、空值和小数步长；禁用、只读及到达上下限时相应按钮不可操作。

- Dashboard：健康与待办摘要。末尾“面试充电站”由独立 Server Component 渲染固定八项资源，使用原生外链和本地静态文案，不新增 API、任务、数据库或第三方图片请求。复用工作台面板与运行时令牌；链接卡片宽屏四列、中屏两列、窄屏单列，自然文档滚动。外链使用 `target="_blank" rel="noopener noreferrer"`，不携带画像或跟踪参数；提供统一新标签提示与键盘焦点。自动化覆盖名单、目标 URL、安全属性、键盘打开、响应式和 axe。
- Jobs：左/顶部筛选、结果表、详情页；分数采用数字和文字，不只靠颜色；确定性 MatchResult 与版本化 MatchAdvice 分区展示，建议失败不影响分数。

职位列表分数链接按评分规范分为四档：80–100 高契合（绿色）、60–不足80 较契合（蓝色）、40–不足60 部分契合（橙色）、0–不足40 低契合（红色）；未评分以灰色“无”显示，不归入低契合。桌面表格与移动卡片共用分档，表格仅使用彩色文字、不加底色，移动卡片使用浅色底与深色字区分相邻说明文字；两者均不添加下划线。悬停说明与辅助描述提供档位文字，键盘焦点保留清晰轮廓。

- Profile：版本选择、字段差异、偏好和锁定。
- Sources：总页标题为“招聘来源”，通过“官网来源 / 招聘平台来源”二级菜单分组。官网来源先按稳定 companyId 聚合并按公司分页，一家公司一张卡；桌面端每行两张公司卡片，1100px 以下回落为单列，卡片不为同排较高内容强制拉伸。卡片标题使用紧凑两层 Grid：首层为 Logo、公司名称、来源数量和当前系统同步渠道，次层为渠道选择及同步/启停操作；控件使用固定高度和垂直居中，窄屏只整体换行，避免 Windows 中文字体度量造成基线错位。多渠道公司选择“全部”时显示自然高度的公司总览，四项指标共享一个分隔式数据条，宽卡四项同排、常规卡两列；选择具体渠道后才展示该渠道的运行统计与高级设置，不为视图切换设置空白最小高度。具体渠道只同步当前渠道，“全部”同步该公司当前启用的全部来源。公司名称链接到当前选择对应来源的官方招聘入口，并以安全的新标签打开。右上角纯文字标签读取系统“同步招聘渠道”设置，默认显示“实习”且不带装饰圆点；公司综合健康仍采用最差健康状态，并由 1px 状态边框、3px 内侧色轨和浅色标题光晕表达。招聘平台来源在未接入时保留明确空状态。
- Tasks/Agent Runs：诊断和重试。任务与 Agent 运行分别使用独立的 `taskPage`、`agentPage` 页码；点击任一项目使用 dialog 弹出详情，失败时展示错误类别、脱敏失败原因、尝试次数和时间线，Agent dialog 通过详情 API 加载工具调用。任务类型、Agent 键和 Agent 错误类别在 Web 展示边界统一映射为中文，未知扩展值使用中文兜底，不直接泄漏机器标识。
- Settings：修改非敏感系统设置；常用设置只包含自动同步、自动匹配和默认职位视图。来源计划由开关、每天/每周频率和本地时间生成 cron；新职位修订按自动匹配开关创建规则评分或 AI 建议链路；职位默认排序持久化在应用设置中，筛选记忆仅保存在本机浏览器。职位理解关闭时不清理历史任务。

## 数据与安全

面试资源卡片使用下载到 `public/assets/interview-resources/` 的官方 Logo／站点图标，并在同目录记录来源。图片固定 32px、保持原比例、空替代文本（旁边已有网站名），加载失败不影响文字链接；运行时不访问第三方图像服务。

首页面试资源是外链白名单的显式例外：只允许代码中维护的八个官方 HTTPS 首页，不接受用户输入 URL；不经过数据库，不拼接用户数据或跟踪参数。以下数据库外链约束仍适用于招聘职位。

所有 mutation 使用 POST/PATCH，先从只读 CSRF 端点取得随机 token，并同时以 `SameSite=Strict`、`HttpOnly` Cookie 和自定义请求头回传；服务端校验二者恒等、Origin/目标协议与端口一致且均为 loopback，即使首期无账户也拒绝跨站写入。服务端启动强制 host 为 127.0.0.1/::1/localhost。外链限定数据库中已验证的官方 HTTPS URL，并使用 `target=_blank rel="noopener noreferrer"`。敏感简历删除先返回稳定影响 hash 和数量，用户输入 `DELETE` 二次确认后只入队 Worker 任务；执行前再次计算影响，变化时要求重新预览。

首期使用 2–5 秒退避轮询活动任务，不引入 WebSocket。页面 action 使用服务端 idempotency token，浏览器重试返回同一 task。

## 单宿主运行约束（ADR-0065）

同一数据目录 Web/CLI 互斥；主线程统一调度，业务 Handler 由有界动态线程池执行。Web 启动器拥有运行时，Next 只使用受限命令桥。CLI 不启动周期或消费无关历史任务，执行命令等待目标工作流；关闭宿主停止执行，强杀后由下次启动恢复。此约定替代原独立后台服务和退出继续运行的描述。详见 [003 设计](../003-task-worker/design.md)。

任务卡片分组提供有效的 group 角色与可访问名称。分区导航仅在分区首页承载一级标题，详情页使用自身主标题；验收不得依赖下拉框隐藏测宽文字或历史任务位于未筛选第一页的假设。

Agent 详情明确一次运行可包含多次实际模型请求；逐请求明细尚未加载时不展示“没有明细”。有汇总 Token 但没有逐请求记录时说明明细缺失、无法还原次数，不将其解释为没有调用模型或伪造请求。失败详情同时展示已脱敏的安全摘要，便于定位字段校验错误。

多请求 Agent 的详情逐项列出失败或纠正原因，HTTP 200 的响应也可能未通过 Agent 输出校验。历史请求没有明确诊断时展示未记录，不从最终成功状态猜测首个错误。最后一次输出校验失败可使用运行中保留的 invalid_output 摘要展示；不改写历史请求。
