# 011 本地 Web 管理台规格

> 状态：Implemented

WEB-001 补充验收：首页精选职位按索引定位各职位最新修订，保留原筛选、排序和返回字段。Web 容器初始化并发复用同一次尝试；失败后短暂退避再允许新尝试，不永久缓存失败 Promise，不关闭已成功初始化的容器。

WEB-003 补充验收：职位表格行及移动卡片的非交互区域可进入站内详情，匹配分数提供等价原生链接用于键盘访问。职位名称仍打开官网；勾选、投递、评分按钮及其弹层、文本选择和修饰键点击不得误触行导航。站内详情保留所选画像，返回列表恢复原筛选和分页；返回地址只允许本地 `/jobs` 列表。

> 里程碑：R2
> 依赖：002–010, 012

## 目标

提供仅本机访问的可视化管理台，用于浏览匹配职位、查看证据、维护画像、观察来源同步和处理失败任务。

## 非目标

- 不支持多用户、远程公网部署或移动原生应用。
- 不自动提交职位申请。
- 不在 HTTP 请求内执行采集、模型或批量匹配。
- 不加入首期投递流程 CRM；官网投递仍通过外部链接完成。

## 功能需求

- **WEB-001**：首页必须显示 active 职位数、当前匹配数、来源健康、待处理/失败任务和最近同步摘要。
- **WEB-002**：职位列表必须支持关键词、公司、地点、细分职位类别、状态、最低分筛选及稳定的数字页码分页/排序；页码必须保留首页和末页，并在当前页附近显示邻近页码；不得提供职位族自由输入。
- **WEB-003**：职位详情必须显示当前标准化 JD、官网详情/投递链接、修订时间线、匹配分项、证据、风险和建议状态。
- **WEB-004**：画像页面必须显示当前/历史版本、来源简历、提取值与有效值，并支持偏好修改、字段修正、锁定和解锁。
- **WEB-005**：来源页面必须显示支持状态、启停、调度、健康、最近运行和统计，并可入队手动同步/健康检查。
- **WEB-006**：任务与 Agent 页面必须显示状态、尝试、错误分类、版本、Token/成本，可执行 retry/cancel。
- **WEB-007**：所有耗时动作只创建任务并立即返回 task ID，界面轮询或推送状态。
- **WEB-008**：closed 职位默认隐藏；stale 必须有明显标记；官网链接在新标签打开并使用安全 rel 属性。
- **WEB-009**：删除、恢复或敏感清理必须显示影响预览和二次确认。
- **WEB-010**：服务默认且首期只能绑定 loopback；配置非 loopback 必须拒绝启动。
- **WEB-011**：设置页必须展示并修改职位理解系统开关；关闭时只影响未来同步产生的职位理解任务，不删除已有任务。
- **WEB-012**：所有 Web 列表必须使用统一数字页码分页契约；任务列表与 Agent 运行列表必须独立分页，分页链接必须保留当前筛选条件。
- **WEB-013**：启动 Web 管理台时必须同时启动独立 Worker 子进程；Web 与 Worker 任一异常退出时必须停止另一个，收到终止信号时必须向两个子进程转发并清理资源。
- **WEB-014**：任务列表和 Agent 运行列表的每个项目必须支持点击弹出详情；失败项目必须展示失败类别、详细安全原因、尝试次数和时间信息。
- **WEB-015**：官网来源必须按公司聚合为一张卡片；卡片标题区以两层稳定布局呈现公司身份、来源数量、渠道选择与操作，避免把不同高度控件挤在同一文字基线上。渠道选择只显示该公司已经接入的“实习 / 校招 / 社招”，并提供“全部”聚合视图。多渠道公司的“全部”必须显示独立的紧凑公司总览，不得重复堆叠渠道详情卡或使用固定最小高度；四项汇总指标必须共享分隔式数据条，并根据卡片宽度在四列和两列之间响应。未接入渠道不得显示为可选项；公司名称必须链接到当前所选渠道对应的招聘官网；“立即同步”作用于当前选择的渠道范围。卡片右上角必须显示系统“同步招聘渠道”设置的当前值，默认“实习”，且不带装饰圆点；公司综合健康仍取已接入来源中的最差状态，并通过细状态边框、内侧色轨和浅色光晕表达，渠道详情保留自身真实状态和操作。
- **WEB-016**：设置页必须只增加自动同步、自动匹配和默认职位视图三个常用分组。自动同步控制计划启停、每天/每周频率和本地执行时间；自动匹配控制新职位修订的规则评分及可选 AI 求职建议；默认职位视图控制默认排序，并可在本机浏览器记住和恢复最近一次筛选。

## 质量需求

- **WEB-Q01**：使用 Next.js + React + TypeScript，复用应用层 DTO 和 Zod Schema。
- **WEB-Q02**：桌面 1280px 及以上优先，同时在 768px 可完成主要只读操作。
- **WEB-Q03**：关键页面满足键盘操作、可见焦点、表单 label、语义表格和基础 WCAG AA 对比度。
- **WEB-Q04**：首屏读取不应触发写操作；页面刷新不得重复创建任务。
  浏览器回归须区分页内进度与全局通知，并以独立画像验证简历制作，避免其他流程修改共享数据后造成误报。

## 验收场景

1. 打开职位列表，默认只见 active 非 excluded，筛选后 URL 保存筛选状态。（WEB-002,008）
2. 职位详情可追溯到修订、匹配规则和 Agent 状态，投递链接是官方 HTTPS。（WEB-003）
3. 点击同步立即显示 task ID/状态，不等待官网请求完成；刷新不重复入队。（WEB-005,007, WEB-Q04）
4. 修改并锁定画像字段产生新版本，失败时表单保留输入并显示稳定错误。（WEB-004）
5. 尝试绑定 `0.0.0.0` 时启动失败并说明首期只允许 loopback。（WEB-010）
6. 仅键盘可完成列表筛选、打开详情和返回。（WEB-Q03）
7. 启动 Web 后，Web 服务与 Worker 均保持运行，提交同步任务后由 Worker 领取执行；停止任一子进程时另一子进程也被停止。（WEB-013）
8. 点击任务或 Agent 运行项目弹出详情；失败状态展示安全的详细失败原因。（WEB-014）
9. 同一公司的多个来源只显示一张公司卡；多渠道公司的“全部”视图只展示紧凑公司级汇总，四项指标在宽卡同排、常规卡两列且没有固定高度空白；切换到已接入的实习/校招/社招渠道后才展示对应渠道状态和高级设置，“立即同步”始终同步当前选择范围。（WEB-015）
10. 修改三个设置分组后，来源计划使用所选频率和时间，新职位按开关创建评分/建议任务；无显式 URL 排序时应用默认排序，启用记忆后重新打开职位页可恢复最近筛选。（WEB-016）
