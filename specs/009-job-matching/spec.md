# 009 职位匹配与建议规格

主动重新评分或重新生成建议必须重新调用模型，不复用成功的 Agent 输出；即使输入、提示词及配置相同也创建新的成功运行并覆盖当前结果。失败重试仍可恢复原运行并累计用量；统一分析失败时重试本次分析。确定性规则每次重新计算，相同结果允许幂等保存。

当前评分职责：规则覆盖明确资格、岗位方向与地点偏好，模型综合全部相关维度，允许两种评估覆盖相同维度。规则按适用条件等权计分，岗位与地点独立展示；岗位方向不匹配只影响得分，不作硬排除。未设置的方向与地点不计分，未知不伪造满足。模型接收脱敏材料并综合评价，保留 30/70 合成和规则降级。只执行当前规则，不提供版本选择或旧引擎重放；每职位只保留一份当前结果，不自动重算。

职位详情按规则评分、模型评分两张卡片并列展示；缺口合并去重并跳过不适用维度。Agent 建议只保留亮点、缺口和准备建议，需要确认的问题写成准备行动，不单列待确认，也不输出或存储引用编号、引用明细与简历重点。

规则评分按岗位、地点、资格条件分组展示实际得分与满分；风险与待确认条件分开显示简洁规则名称，不重复保存解释和空证据。

> 状态：Implemented

- **MCH-026**：一次批量评分只创建一个任务，冻结职位修订与画像版本；逐项保存成功及失败检查点。批次失败仍保留成功项，自动或手动重试仅处理失败和未执行项，失败项重新运行统一分析；取消及进程恢复不得丢失已保存进度。

- **MCH-025**：规则按明确资格、岗位方向和偏好等权计分，未知不硬排除，无适用条件时为 100。模型综合所有维度，与规则允许交叉；只使用代码中的当前规则配置，不保存规则集表。

- **MCH-024**：规则与模型按 30%/70% 加权，总分限制 0..100。model 为 null 或包含 score 与 reasons 的对象，缺失模型分时退回规则分。模型分、理由及解析内容摘要参与评分输入摘要，建议绑定该摘要。职位理解事实不含画像内容。

- **MCH-023**：校招与实习识别明确届别及含括号的毕业月份闭区间，月份窗口优先于同句届别名称。多段教育日期全部满足才通过、全部冲突才失败，其余未知；缺失、非法日期和非封闭列举保留未知，优先项不硬排除。保留资格回归，不提供旧算法重放或自动重算。

- **MCH-022**：介绍/福利章节后出现空行分隔的编号职责或任职要求时恢复提取；仅空行或编号介绍/福利不恢复。原文字段与片段保留，只使用当前解析策略，不自动重算历史记录。

## 建议输出与恢复验收

- 建议只返回文本，不再生成引用编号或引用目录；Schema 拒绝旧引用字段，升级版本隔离旧缓存。
- 职位事实、模型评分与求职建议使用同一次 Agent 运行；分析失败不得发布本次评分，批次重试跳过已成功职位。

## 目标

基于当前职位事实和候选人画像，在用户明确选择具体职位后生成可解释、可重算的资格判断、确定性分数、排序和 Agent 建议。

## 非目标

- Agent 不直接决定是否排除职位或修改确定性分数。
- 不训练排序模型。
- 不生成虚构简历经历或替用户投递。

## 功能需求

- **MCH-001**：单职位评分可使用已有当前 JobUnderstanding enrichment；新理解仅由用户显式选择 LLM 模式或 WEB-016 已启用的自动评分策略生成。职位理解事实（技能、年限、级别、领域）按职位存储且不含画像内容；Agent 输出的 fitScore 只随该次匹配调用传递，不写入 enrichment。
- **MCH-002**：规则计算使用 pass/fail/unknown、ruleId 和有效证据；存储仅保留风险和未知规则标识；只有明确 fail 才排除。
- **MCH-003**：只执行当前条件评分，岗位与地点单独分组，其余资格和偏好归入条件组；按适用条件数分配总权重 100。招聘类别只来自职位，未知不套用系统当前同步渠道；删除旧五维、技能与实践关键词评分引擎。
- **MCH-004**：每个规则分项只保存 dimension、score、max_score，总分限制 0..100；模型分数和理由独立保存于 model。
- **MCH-005**：同一职位同类型 metadata 只有一条记录；相同内容幂等返回，变化时覆盖 value，保留 ID 和 created_at。
- **MCH-006**：画像、职位内容、解析或评分结果变化更新输入摘要；过期任务不得覆盖当前结果，不进行全量自动重算。
- **MCH-007**：默认列表只推荐 active 且非 excluded 职位；stale 可通过显式筛选查看，closed 不可标记为当前可投。
- **MCH-008**：JobAdviceAgent 基于指定 MatchResult 的确定性分项和证据输出建议快照，仅含亮点、缺口和准备建议；按执行内容哈希选择当前结果，不维护 Agent/Prompt 版本。
- **MCH-009**：Agent 建议不得修改 MatchResult 或 totalScore；失败时不创建 MatchAdvice，确定性结果仍可用且相同 cacheKey 可重试。
- **MCH-010**：排序必须稳定：totalScore 降序、发布时间/末见时间降序、jobId 升序。
- **MCH-011**：用户可触发当前规则重算，不选择历史规则；职位仅保存当前评分和建议，运行审计归 Agent 与任务记录。
- **MCH-012**：匹配评分由用户选择具体职位/画像手动触发（`match.score-job` / `match.score-batch`），或由 WEB-016 已保存启用的策略针对同步产生的新修订自动执行；关闭自动评分时不得自动触发。自动评分不再派生独立任务，而是在 `source.sync` 任务的评分阶段（阶段 B）内，由 matching 提供的逐职位评分服务对同步运行新增/修订的职位串行执行；评分开关开启即运行规则与模型两阶段评分（llm 模式），模型不可用或理解最终失败时降级为规则分（计入 degradedCount）而不使该项失败，求职建议开关控制同次分析中的 advice 输出、不改变评分模式。自动路径仅处理本运行新增/修订的职位修订，不读取全量职位；手动批量评分维持模型失败即该项失败（`requireModelScore: true`）。画像导入或规则升级不触发全量重算。
- **MCH-013**：用户可对单个职位或显式勾选的一组职位选择规则或 LLM 模式；规则模式生成确定性分数，LLM 模式生成职位理解与模型分，再执行当前规则并合成总分；建议开关启用时生成建议。模式不代表算法版本。
- **MCH-014**：按招聘类型校验明确必需的学历/专业/资质、工作年限、届别/应届身份、在读身份/实习天数/月数/到岗日期；未声明不添加门槛，优先项不硬排除，必需信息缺失为 unknown。画像可编辑资格，不推测身份。
- **MCH-015**：岗位方向使用确定性分类匹配，不匹配仅影响方向得分。技能及经历/项目的关键词覆盖计分已删除，由模型综合评价相关性，不按数量或描述长度自动加分。
- **MCH-016**：risk_results 保存确认不满足的规则标识，unknown_rules 保存无法确认的规则标识；两者去重。未设置的偏好不计风险，缺失资料不等于不合格。

## 质量需求

- **MCH-017**：当前条件解析保留对象、原文、必需/优先/豁免、与/或及数值比较语义；区分经验上下限、区间和中文数字，局部“优先”“不限”不传播；不支持的复合条件保留未知。
- **MCH-018**：技能证据的关键词计分及词典旧实现已删除；否定、学习计划与实际使用的语义区别交给模型，规则不产生技能分。
- **MCH-019**：“经验不限”取消年限门槛；工作经历质量由模型评价，不保留旧类别权重或旧经历评分引擎。
- **MCH-020**：实践质量由模型评价，删除旧职责关键词、数量和证据覆盖计分实现，保留原始实践材料作为模型输入。
- **MCH-021**：规则配置以内容哈希标识，只保留当前实现；历史算法及兼容选择分支删除，不自动全量重算。迁移保留评分与用量快照，当前规则、内容隔离和数据库迁移测试必须通过。

- **MCH-Q01**：单职位确定性计算不访问网络或数据库，输入输出可纯函数测试。
- **MCH-Q02**：单职位匹配必须可取消且不读取全量职位；系统不得为后台批量匹配读取全量职位。
- **MCH-Q03**：每个分数和建议事实必须可追溯到画像或职位证据；无证据不得伪装确定事实。
- **MCH-Q04**：模型不可用时仍可完成硬过滤、评分、排序和导出。

## 验收场景

1. 明确地点排除规则 fail 的职位为 excluded，证据包含用户偏好路径和职位地点。（MCH-002）
2. 岗位明确要求年限但资料缺失时为 unknown，没有要求不增设门槛。（MCH-002,014）
3. 适用条件分组后的规则满分合计为 100，模型分独立合成。（MCH-003,004）
4. 相同有效输入不新增 metadata；新解析覆盖同职位评分并保留原 ID。（MCH-005,006）
5. 更新画像后旧结果不能作为当前结果；新评分覆盖同职位记录，旧任务写回被拒绝。（MCH-006,011）
6. 建议超时保留评分，失败运行可重试；重新生成建议覆盖同职位原建议。（MCH-008,009）
7. closed 职位不出现在默认推荐列表，但仍可查看最后的匹配结果。（MCH-007）
8. 自动评分关闭时新增职位在同步任务中不执行评分阶段；开启后同步任务的评分阶段仅处理本次运行新修订，评分开关开启即包含模型评分阶段（模型失败降级为规则分），建议开关决定同次分析是否生成 advice 输出。点击具体职位评分只创建该职位/画像组合的独立任务。（MCH-012）
9. 模型可用时总分为规则分×0.3+模型分×0.7，model 保存分数和理由；降级时 model 为 null，总分等于规则分。（MCH-024）
10. Agent 建议包含画像不存在的经历时，事实一致性校验/评测判定失败。（MCH-Q03）
11. 职位列表勾选两个职位并选择 LLM 模式时，只为这两个职位分别创建显式任务；没有画像时操作保持禁用并提示先导入或选择个人资料。（MCH-013）

## 未解决问题

评分权重为当前政策，离线回归验证规则正确性；尚无人工标注的真实排序评测，不宣称 Top-K 命中率提升。

## 当前职位派生信息

职位事实仅存于 jobs；job_metadata 使用独立 ID、职位外键及 UNIQUE(job_id, name)，分别保存 enrichment、match_result、match_advice 的当前结果。重复生成覆盖同类型记录，保持 ID 和首次创建时间。规则定义仅由代码常量提供。

评分 value 中 components 仅含 dimension、score、max_score；risk_results 仅含确认不满足的规则标识，unknown_rules 仅含信息不足的规则标识，未设置偏好不计风险。model 为 null 或含 score、reasons 的对象。输入摘要、资料身份及生成时间用于识别过期结果；旧任务不得覆盖新输入生成的结果。

## 统一职位分析

职位事实、模型匹配和求职建议由 job-analysis 一次调用输出。规则模式关闭模型匹配输出；建议开关控制建议内容；全部模型输出关闭时不调用模型。输出块按启用项校验，开关参与输入身份。规则汇总不作为建议的前置依赖。旧 job.enrich、match.advise 不再注册独立任务。正常评分只产生一次 Agent 运行，失败重试保留独立诊断。
