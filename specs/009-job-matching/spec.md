# 009 职位匹配与建议规格

> 状态：Implemented

- **MCH-022**：介绍/福利章节后出现空行分隔的编号职责或任职要求时恢复提取；仅空行或编号介绍/福利不恢复。原文字段与片段保留；v3.1 独立启用，v3 历史解析保持不变，不自动重算历史记录。

> 依赖：001, 002, 003, 007, 008

## 建议引用与阶段恢复补充验收

- 模型只返回系统证据目录中的 ID，由系统还原引用原文；未知 ID 严格拒绝。
- 业务引用校验先于 Agent 成功缓存，失败共享一次输出纠正预算；升级版本隔离旧缓存。
- 评分完成后建议失败必须明确显示阶段，保留评分结果 ID；手动重试从建议阶段恢复，不重新评分。

## 目标

基于不可变职位修订和候选人画像，在用户明确选择具体职位后生成可解释、可版本、可重算的资格判断、确定性分数、排序和 Agent 建议。

## 非目标

- Agent 不直接决定是否排除职位或修改确定性分数。
- 不训练排序模型。
- 不生成虚构简历经历或替用户投递。

## 功能需求

- **MCH-001**：单职位评分可使用已有版本化 JobUnderstanding enrichment；新理解仅由用户显式选择 LLM 模式或 WEB-016 已启用的自动评分策略生成。
- **MCH-002**：硬规则必须输出 pass/fail/unknown、ruleId 和证据；只有明确 fail 才排除。
- **MCH-003**：保留首期 v1 五维规则供历史重放。v2 使用职位自身招聘类别选择规则：社招技能/经历/项目/方向/行业/地点为 30/30/15/15/5/5，校招为 30/15/30/15/0/10，实习为 35/0/30/20/0/15；每类总权重 100，类别未知不套用系统当前同步渠道，输出待确认的暂定结果。
- **MCH-004**：每个分项必须保存得分、上限、命中/缺失证据和不确定项，总分限制 0..100。
- **MCH-005**：相同 ProfileVersion、JobRevision、JobEnrichmentIdOrNone 和 RulesetVersion 重复计算必须返回同一结果，不创建重复记录。
- **MCH-006**：画像、职位修订、实际使用的 enrichment 或规则集变化必须产生新匹配身份；不得在后台对全量职位或全量画像批量重算。
- **MCH-007**：默认列表只推荐 active 且非 excluded 职位；stale 可通过显式筛选查看，closed 不可标记为当前可投。
- **MCH-008**：JobAdviceAgent 必须基于指定 MatchResult 的确定性分项和证据输出版本化 MatchAdvice，包括亮点、缺口、不确定项、简历强调建议和准备建议。
- **MCH-009**：Agent 建议不得修改 MatchResult 或 totalScore；失败时不创建 MatchAdvice，确定性结果仍可用且相同 cacheKey 可重试。
- **MCH-010**：排序必须稳定：totalScore 降序、发布时间/末见时间降序、jobId 升序。
- **MCH-011**：用户可查看规则集版本和触发重算；旧结果保留用于审计但不作为当前默认结果。
- **MCH-012**：匹配任务由用户选择具体职位/画像触发，或由 WEB-016 已保存启用的策略针对同步产生的新修订创建；关闭自动评分时不得自动触发。画像导入或规则升级不触发全量重算。
- **MCH-013**：用户必须可对单个职位或显式勾选的一组职位选择规则或 LLM 模式；规则模式只生成确定性分数，LLM 模式依次生成职位理解、基于理解的确定性分数和 Agent 建议。
- **MCH-014**：v2 按类型校验明确必需的学历/专业/资质、社招工作年限、校招届别/应届身份、实习在读身份/每周天数/持续月数/到岗日期；未声明不添加门槛，优先项不硬排除，必需信息缺失为 unknown。画像可编辑资格与可用时间，不推测未提供的身份。
- **MCH-015**：技能按职位要求覆盖率计分，必需技能权重高于优先技能，规范别名并去重；岗位大类相同有基础分、细分类一致更高。经历/项目按相关技能与方向的最佳证据计分，不按条目数量或描述长度加分，实习允许实习经历参与项目实践维度。
- **MCH-016**：v2 分项区分 known/unknown/not_applicable；未知贡献 0 已证实分而非默认半分，不删除其权重。只有明确不适用的维度可重分配权重。展示证据完整度与暂定标记，缺失不等于不合格；保留 v1 JSON 和历史匹配，不后台全量重算。

## 质量需求

- **MCH-017**：v3 条件解析保留对象、原文、必需/优先/豁免、与/或及数值比较语义；区分经验上下限、区间和中文数字，局部“优先”“不限”不传播到其他条件；不支持的复合条件为待确认，不猜测通过或排除。
- **MCH-018**：v3 技能证据识别否定、计划学习和自述/实际使用来源；可从项目与工作经历补充技能，保留双侧证据。任选一项的技能按组计分，忽略明确不要求的技能；词典按岗位方向补充，未识别内容不伪装已理解。
- **MCH-019**：v3 “经验不限”只取消年限门槛，相关工作经历仍按对应类别原权重评分；没有经历证据保持未知，不因此重分配权重。
- **MCH-020**：v3 实践评分区分参与、负责和可定位的交付/验证证据，并匹配职位职责；不按字数、数字数量、漂亮措辞或重复条目加分。只有与目标职责相关的证据参与贡献评分，保留证据来源和缺失提示。
- **MCH-021**：v3 以独立规则 ID/定义启用，v1/v2 输入及结果可重放；不重启真实服务、不自动全量重算。新规则专项对照与数据库版本幂等测试必须通过，真实排序评测由独立任务完成。

- **MCH-Q01**：单职位确定性计算不访问网络或数据库，输入输出可纯函数测试。
- **MCH-Q02**：单职位匹配必须可取消且不读取全量职位；系统不得为后台批量匹配读取全量职位。
- **MCH-Q03**：每个分数和建议事实必须可追溯到画像或职位证据；无证据不得伪装确定事实。
- **MCH-Q04**：模型不可用时仍可完成硬过滤、评分、排序和导出。

## 验收场景

1. 明确地点排除规则 fail 的职位为 excluded，证据包含用户偏好路径和职位地点。（MCH-002）
2. v1 缺少年限为 unknown；v2 仅在职位明确要求年限而候选年限缺失时输出 unknown，没有要求不增设门槛。（MCH-002,014）
3. v1 五维及 v2 各类别有效维度满分均为 100，权重和非 100 的规则集被拒绝。（MCH-003,004）
4. 相同有效输入重跑不创建第二条 MatchResult；同一职位改用新 enrichment 时创建新结果并保留基础结果。（MCH-005,006）
5. 更新画像后新版本产生新结果，旧版本仍可查询。（MCH-006,011）
6. Agent 超时后确定性分数可见，失败运行可重试；不同 Prompt/模型建议形成独立 MatchAdvice，不覆盖旧建议。（MCH-008,009）
7. closed 职位不出现在默认推荐列表，但历史匹配仍可审计。（MCH-007）
8. 自动评分关闭时新增职位不产生匹配任务；开启后仅处理策略范围内新修订。点击具体职位评分只创建该职位/画像组合的任务。（MCH-012）
9. Agent 建议包含画像不存在的经历时，事实一致性校验/评测判定失败。（MCH-Q03）
10. 职位列表勾选两个职位并选择 LLM 模式时，只为这两个职位分别创建显式任务；没有画像时操作保持禁用并提示先导入或选择个人资料。（MCH-013）

## 未解决问题

v2 权重为初始政策，离线回归验证规则正确性；尚无人工标注的真实排序评测，不宣称 Top-K 命中率提升。
