# 009 职位匹配与建议规格

主动重新评分或重新生成建议必须重新调用模型，不复用成功的 Agent 输出；即使输入、提示词及配置相同也创建新的成功运行和结果。失败重试仍可恢复原运行并累计用量；建议阶段失败时保留已完成评分检查点。确定性规则每次重新计算，相同结果允许幂等保存。

当前评分职责：规则覆盖明确资格、岗位方向与地点偏好，模型综合全部相关维度，允许两种评估覆盖相同维度。规则按适用条件等权计分，岗位与地点独立展示；岗位方向不匹配只影响得分，不作硬排除。未设置的方向与地点不计分，未知不伪造满足。模型接收脱敏材料并综合评价，保留 30/70 合成和规则降级。只执行当前规则，不提供版本选择或旧引擎重放；历史结果只读快照，不自动重算。

职位详情按规则评分、模型评分两张卡片并列展示；缺口合并去重并跳过不适用维度。Agent 建议只保留亮点、缺口和准备建议，需要确认的问题写成准备行动，不单列待确认，也不输出或存储引用编号、引用明细与简历重点。

规则评分按实际参与计算的地点、公司规模、用工类型、排除词及具体资格条款逐项展示，不以“客观条件”作为展示分项。不展示“待确认”和“查看匹配依据”展开项；缺少事实仍按原有 unknown 口径计算，不虚构未执行的岗位方向评分。

> 状态：Implemented

- **MCH-026**：一次批量评分只创建一个任务，冻结职位修订与画像版本；逐项保存成功、失败及建议阶段检查点。批次失败仍保留成功项，自动或手动重试仅处理失败和未执行项，建议失败仅恢复建议；取消及进程恢复不得丢失已保存进度。

- **MCH-025**：规则按明确资格、岗位方向和偏好等权计分，不使用技能或实践关键词打分；未知不硬排除，保留完整度和暂定分，没有限制时为 100。模型综合相关维度，允许与规则交叉；保留 30/70 合成，模型缺失时退回规则分。删除规则/Agent/Prompt 手动版本，规则结果内容参与去重，历史快照不改写。

- **MCH-024**：评分分为规则和模型两个阶段，总分按 30%/70% 加权并限制在 0..100。模型输出整数 fitScore 及 1-5 条中文理由，缺失时降级为规则分；model_score 是否为空表达实际使用模式，不重复保存评分版本。身份包含是否使用模型，不包含非确定性模型分。职位理解事实只引用职位，不保存画像内容。

- **MCH-023**：校招与实习识别明确届别及含括号的毕业月份闭区间，月份窗口优先于同句届别名称。多段教育日期全部满足才通过、全部冲突才失败，其余未知；缺失、非法日期和非封闭列举保留未知，优先项不硬排除。保留资格回归，不提供旧算法重放或自动重算。

- **MCH-022**：介绍/福利章节后出现空行分隔的编号职责或任职要求时恢复提取；仅空行或编号介绍/福利不恢复。原文字段与片段保留，只使用当前解析策略，不自动重算历史记录。

## 建议引用与阶段恢复补充验收

- 建议只返回文本，不再生成引用编号或引用目录；Schema 拒绝旧引用字段，升级版本隔离旧缓存。
- 评分完成后建议失败必须明确显示阶段，保留评分结果 ID；手动重试从建议阶段恢复，不重新评分。

## 目标

基于不可变职位修订和候选人画像，在用户明确选择具体职位后生成可解释、可版本、可重算的资格判断、确定性分数、排序和 Agent 建议。

## 非目标

- Agent 不直接决定是否排除职位或修改确定性分数。
- 不训练排序模型。
- 不生成虚构简历经历或替用户投递。

## 功能需求

- **MCH-001**：单职位评分可使用已有版本化 JobUnderstanding enrichment；新理解仅由用户显式选择 LLM 模式或 WEB-016 已启用的自动评分策略生成。职位理解事实（技能、年限、级别、领域）按职位存储且不含画像内容；Agent 输出的 fitScore 只随该次匹配调用传递，不写入 enrichment。
- **MCH-002**：硬规则必须输出 pass/fail/unknown、ruleId 和证据；只有明确 fail 才排除。
- **MCH-003**：只执行当前条件评分，岗位与地点单独分组，其余资格和偏好归入条件组；按适用条件数分配总权重 100。招聘类别只来自职位，未知不套用系统当前同步渠道；删除旧五维、技能与实践关键词评分引擎。
- **MCH-004**：每个分项必须保存得分、上限、命中/缺失证据和不确定项，总分限制 0..100。
- **MCH-005**：相同 ProfileVersion、JobRevision、JobEnrichmentIdOrNone 和 RulesetVersion 重复计算必须返回同一结果，不创建重复记录。
- **MCH-006**：画像、职位修订、实际使用的 enrichment 或规则集变化必须产生新匹配身份；不得在后台对全量职位或全量画像批量重算。
- **MCH-007**：默认列表只推荐 active 且非 excluded 职位；stale 可通过显式筛选查看，closed 不可标记为当前可投。
- **MCH-008**：JobAdviceAgent 基于指定 MatchResult 的确定性分项和证据输出建议快照，仅含亮点、缺口和准备建议；按执行内容哈希选择当前结果，不维护 Agent/Prompt 版本。
- **MCH-009**：Agent 建议不得修改 MatchResult 或 totalScore；失败时不创建 MatchAdvice，确定性结果仍可用且相同 cacheKey 可重试。
- **MCH-010**：排序必须稳定：totalScore 降序、发布时间/末见时间降序、jobId 升序。
- **MCH-011**：用户可触发当前规则重算，界面不展示或选择规则版本；历史结果保留快照用于审计。
- **MCH-012**：匹配评分由用户选择具体职位/画像手动触发（`match.score-job` / `match.score-batch`），或由 WEB-016 已保存启用的策略针对同步产生的新修订自动执行；关闭自动评分时不得自动触发。自动评分不再派生独立任务，而是在 `source.sync` 任务的评分阶段（阶段 B）内，由 matching 提供的逐职位评分服务对同步运行新增/修订的职位串行执行；评分开关开启即运行规则与模型两阶段评分（llm 模式），模型不可用或理解最终失败时降级为规则分（计入 degradedCount）而不使该项失败，求职建议开关只独立控制每项的建议阶段、不改变评分模式。自动路径仅处理本运行新增/修订的职位修订，不读取全量职位；手动批量评分维持模型失败即该项失败（`requireModelScore: true`）。画像导入或规则升级不触发全量重算。
- **MCH-013**：用户可对单个职位或显式勾选的一组职位选择规则或 LLM 模式；规则模式生成确定性分数，LLM 模式生成职位理解与模型分，再执行当前规则并合成总分；建议开关启用时生成建议。模式不代表算法版本。
- **MCH-014**：按招聘类型校验明确必需的学历/专业/资质、工作年限、届别/应届身份、在读身份/实习天数/月数/到岗日期；未声明不添加门槛，优先项不硬排除，必需信息缺失为 unknown。画像可编辑资格，不推测身份。
- **MCH-015**：岗位方向使用确定性分类匹配，不匹配仅影响方向得分。技能及经历/项目的关键词覆盖计分已删除，由模型综合评价相关性，不按数量或描述长度自动加分。
- **MCH-016**：分项区分 known/unknown/not_applicable，未知贡献 0 已证实分但保留权重；展示证据完整度与暂定标记，缺失不等于不合格。历史评分只读取快照，不重放旧算法或后台全量重算。

## 质量需求

- **MCH-017**：当前条件解析保留对象、原文、必需/优先/豁免、与/或及数值比较语义；区分经验上下限、区间和中文数字，局部“优先”“不限”不传播；不支持的复合条件保留未知。
- **MCH-018**：技能证据的关键词计分及词典旧实现已删除；否定、学习计划与实际使用的语义区别交给模型，规则不产生技能分。
- **MCH-019**：“经验不限”取消年限门槛；工作经历质量由模型评价，不保留旧类别权重或旧经历评分引擎。
- **MCH-020**：实践质量由模型评价，删除旧职责关键词、数量和证据覆盖计分实现，保留原始实践材料作为模型输入。
- **MCH-021**：规则配置以内容哈希标识，只保留当前实现；历史算法及兼容选择分支删除，不自动全量重算。迁移保留评分与用量快照，当前规则、内容隔离和数据库迁移测试必须通过。

- **MCH-Q01**：单职位确定性计算不访问网络或数据库，输入输出可纯函数测试。
- **MCH-Q02**：单职位匹配必须可取消且不读取全量职位；系统不得为后台批量匹配读取全量职位。
- **MCH-Q03**：每个分数和建议事实必须可追溯到画像或职位证据；无证据不得伪装确定事实。
- **MCH-Q04**：模型不可用时仍可完成硬过滤、评分、排序和导出。

## 验收场景

1. 明确地点排除规则 fail 的职位为 excluded，证据包含用户偏好路径和职位地点。（MCH-002）
2. v1 缺少年限为 unknown；v2 仅在职位明确要求年限而候选年限缺失时输出 unknown，没有要求不增设门槛。（MCH-002,014）
3. v1 五维及 v2 各类别有效维度满分均为 100，权重和非 100 的规则集被拒绝。（MCH-003,004）
4. 相同有效输入重跑不创建第二条 MatchResult；同一职位改用新 enrichment 时创建新结果并保留基础结果。（MCH-005,006）
5. 更新画像后新版本产生新结果，旧版本仍可查询。（MCH-006,011）
6. Agent 超时后确定性分数可见，失败运行可重试；不同 Prompt/模型建议形成独立 MatchAdvice，不覆盖旧建议。（MCH-008,009）
7. closed 职位不出现在默认推荐列表，但历史匹配仍可审计。（MCH-007）
8. 自动评分关闭时新增职位在同步任务中不执行评分阶段；开启后同步任务的评分阶段仅处理本次运行新修订，评分开关开启即包含模型评分阶段（模型失败降级为规则分），建议开关只决定每项是否附加建议阶段。点击具体职位评分只创建该职位/画像组合的独立任务。（MCH-012）
11. LLM 模式评分成功时总分为规则分×0.3+模型分×0.7，scoring_version 为 weighted-v1；模型未配置或最终失败时总分等于规则分，scoring_version 为 rules-v1，任务仍成功。（MCH-024）
9. Agent 建议包含画像不存在的经历时，事实一致性校验/评测判定失败。（MCH-Q03）
10. 职位列表勾选两个职位并选择 LLM 模式时，只为这两个职位分别创建显式任务；没有画像时操作保持禁用并提示先导入或选择个人资料。（MCH-013）
