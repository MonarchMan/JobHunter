# 009 职位匹配与建议规格

> 状态：Implemented
> 依赖：001, 002, 003, 007, 008

## 目标

基于不可变职位修订和候选人画像，生成可解释、可版本、可重算的资格判断、确定性分数、排序和 Agent 建议。

## 非目标

- Agent 不直接决定是否排除职位或修改确定性分数。
- 不训练排序模型。
- 不生成虚构简历经历或替用户投递。

## 功能需求

- **MCH-001**：每个新 JobRevision 可生成版本化 JobUnderstanding enrichment；失败时仍允许基础匹配。
- **MCH-002**：硬规则必须输出 pass/fail/unknown、ruleId 和证据；只有明确 fail 才排除。
- **MCH-003**：首期评分必须包含技能 35、经历 25、方向/职级 15、行业 10、地点/偏好 15，规则集可版本化配置且总权重为 100。
- **MCH-004**：每个分项必须保存得分、上限、命中/缺失证据和不确定项，总分限制 0..100。
- **MCH-005**：相同 ProfileVersion、JobRevision、JobEnrichmentIdOrNone 和 RulesetVersion 重复计算必须返回同一结果，不创建重复记录。
- **MCH-006**：画像、职位修订、实际使用的 enrichment 或规则集变化必须产生新匹配身份并可批量重算；基础结果和 enrichment-aware 结果均保留。
- **MCH-007**：默认列表只推荐 active 且非 excluded 职位；stale 可通过显式筛选查看，closed 不可标记为当前可投。
- **MCH-008**：JobAdviceAgent 必须基于指定 MatchResult 的确定性分项和证据输出版本化 MatchAdvice，包括亮点、缺口、不确定项、简历强调建议和准备建议。
- **MCH-009**：Agent 建议不得修改 MatchResult 或 totalScore；失败时不创建 MatchAdvice，确定性结果仍可用且相同 cacheKey 可重试。
- **MCH-010**：排序必须稳定：totalScore 降序、发布时间/末见时间降序、jobId 升序。
- **MCH-011**：用户可查看规则集版本和触发重算；旧结果保留用于审计但不作为当前默认结果。

## 质量需求

- **MCH-Q01**：单职位确定性计算不访问网络或数据库，输入输出可纯函数测试。
- **MCH-Q02**：批量匹配必须分页处理并可取消，不一次加载全部职位。
- **MCH-Q03**：每个分数和建议事实必须可追溯到画像或职位证据；无证据不得伪装确定事实。
- **MCH-Q04**：模型不可用时仍可完成硬过滤、评分、排序和导出。

## 验收场景

1. 明确地点排除规则 fail 的职位为 excluded，证据包含用户偏好路径和职位地点。（MCH-002）
2. 职位缺少经验年限时结果 unknown 而非 fail，不硬排除。（MCH-002）
3. 五维满分总分为 100，权重和非 100 的规则集被拒绝。（MCH-003,004）
4. 相同有效输入重跑不创建第二条 MatchResult；同一职位改用新 enrichment 时创建新结果并保留基础结果。（MCH-005,006）
5. 更新画像后新版本产生新结果，旧版本仍可查询。（MCH-006,011）
6. Agent 超时后确定性分数可见，失败运行可重试；不同 Prompt/模型建议形成独立 MatchAdvice，不覆盖旧建议。（MCH-008,009）
7. closed 职位不出现在默认推荐列表，但历史匹配仍可审计。（MCH-007）
8. Agent 建议包含画像不存在的经历时，事实一致性校验/评测判定失败。（MCH-Q03）

## 未决问题

无。默认权重作为规则集 v1，可在真实评测后通过新版本调整。
