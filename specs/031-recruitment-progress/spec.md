# 031 应聘进展集中展示规格

> 状态：Ready
> 依赖：029, 030

## 目标

在日历之外提供按公司和岗位组织的应聘流程视图，展示投递、测评/笔试、面试、Offer 或流程结束，以及面试多轮时间线。

## 功能需求

- **PROGRESS-001**：公司分组必须从已确认的 `JobApplication` 派生；同一公司下的不同岗位必须保持独立申请。
- **PROGRESS-002**：岗位流程条必须展示“投递 → 测评/笔试 → 面试 → Offer/结束”，当前阶段由申请事件投影得到，不允许页面直接改写状态。
- **PROGRESS-003**：面试邀请、改期和取消事件必须按岗位申请聚合为多轮面试；轮次优先使用 `stageLabel`，无法识别时使用稳定的“第 N 轮面试”。
- **PROGRESS-004**：岗位详情必须展示完整申请事件时间线，并保留安全的原邮件入口和当前日程引用；不展示邮件正文或凭据。
- **PROGRESS-005**：公司级摘要只做聚合展示，不覆盖岗位申请状态；公司可显示进行中、待处理、有 Offer 或已结束等汇总状态。
- **PROGRESS-006**：查询必须复用 `job_applications` 与 `application_events`，首版不新增重复事实表。

## 验收场景

1. 同一公司存在多个岗位时，公司卡片下分别显示每个岗位和各自流程阶段。
2. 一面、二面、三面显示为独立面试轮次，改期只更新对应轮次的安排。
3. 面试时间线按邮件事实时间排序，不能因任务完成顺序导致旧事件覆盖新事件。
4. Offer、拒信和流程结束出现在申请时间线中，不进入招聘日历。
