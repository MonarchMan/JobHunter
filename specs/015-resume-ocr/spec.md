# 015 简历图片 OCR 规格

> 状态：Implemented
> 里程碑：R2 增量
> 依赖：003, 007, 008, 011, 013, 014

## 目标

允许用户在“个人资料”页导入 JPEG/PNG 扫描简历，由 Worker 在本地完成中英文 OCR，再复用现有画像 Agent、证据校验和版本化保存链路填充在线简历。

## 非目标

- 不在 Web 请求进程或浏览器中执行 OCR、模型调用或画像写入。
- 不在本增量中渲染图片型 PDF；图片型 PDF 继续保留 `needs_ocr` 状态。
- 不新增一套绕过 `CandidateProfileData` 和现有画像 Agent 的页面专用字段解析器。

## 功能需求

- **OCR-001**：简历导入边界必须按内容签名识别 JPEG 和 PNG，继续执行 10 MiB 大小限制，不得仅信任扩展名或浏览器 MIME。
- **OCR-002**：JPEG/PNG 导入必须保存 Artifact 与 `needs_ocr` 文档，并立即创建 `resume.profile.extract` 后台任务；重复文件和重复请求必须沿用内容哈希与任务幂等键去重。
- **OCR-003**：Worker 必须使用本地安装的简体中文和英文 OCR 数据识别图片，不得要求浏览器或首次任务从远端下载语言数据。
- **OCR-004**：OCR 文字必须经过统一空白归一化、最小有效字符和最大字符限制；通过质量门禁后将文档更新为 `parsed`，再交给现有画像 Agent、证据校验和画像版本合并。
- **OCR-005**：“个人资料”导入区必须接受 PDF、DOCX、JPEG 和 PNG，清楚说明图片会在后台进行 OCR，并使用既有持久内联反馈展示入队、完成或失败结果；任务成功后必须自动刷新在线简历。
- **OCR-006**：参考文件 `docs/resumes/nowcoder_1787802316450.jpeg` 必须能识别出教育、技能和项目相关正文，并可经画像 Agent 填充在线简历的对应结构化章节。

## 质量与失败行为

- **OCR-Q01**：OCR 只能由 Worker 执行；识别、模型调用和数据库写入不得处于同一数据库事务中。
- **OCR-Q02**：任务 payload、日志和错误摘要不得包含图片字节、OCR 正文或本地绝对路径。
- **OCR-Q03**：OCR 必须响应任务取消并释放 Worker 资源；临时失败沿用任务重试，低质量文本作为不可重试校验失败。
- **OCR-Q04**：原有文本型 PDF、DOCX 和 UTF-8 文本导入、去重、画像提取行为必须保持兼容。
- **OCR-Q05**：上传控件必须保留键盘文件选择、拖放、禁用/busy、内联错误和屏幕阅读器状态反馈。

## 验收场景

1. 在“个人资料”页选择参考 JPEG，接口立即返回待处理任务，页面提示正在后台识别而不等待 OCR 完成。（OCR-001、OCR-002、OCR-005、OCR-Q01）
2. Worker 读取已保存 Artifact，在无 OCR 网络下载的条件下识别中英文，文档转为 `parsed`，随后生成包含教育、技能和项目的画像版本。（OCR-003、OCR-004、OCR-006）
3. 将扩展名伪装为图片但内容不是 JPEG/PNG/PDF/DOCX/TXT 时，服务端拒绝导入且不创建画像版本。（OCR-001、OCR-Q04）
4. 重复上传同一图片只保留一个 Artifact、一个 ResumeDocument，并复用同一画像任务。（OCR-002）
5. OCR 被取消、文本过短或引擎失败时，任务进入真实的取消/失败状态，原有画像版本不被覆盖，错误中不出现原图、正文或绝对路径。（OCR-Q02、OCR-Q03）
