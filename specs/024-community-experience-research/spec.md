# 024 外部 Agent 网友面经研究规格

> 状态：Implemented
> 依赖：002, 003, 011, 012, 021, 022

## 目标

让用户按目标岗位创建公开面经研究请求，导出供应商无关的研究 Prompt/JSON Schema，或把请求交给本机受限外部 Agent 执行。研究 Agent 先按问题的技术区分度筛选并做语义级归并，外部结果再经过本地校验、确定性去重和人工审核，接受后进入独立的“网友面经”列表，从而形成从研究目标到可用面试准备资料的完整闭环。

## 首版假设

- 已有原生搜索执行器为 `codex-local@v1`；本机未安装、未登录或执行失败时，Prompt 导出与 JSON 研究包人工导入仍可用。
- 已实现的 `browser-assisted-codex@v2` 由 JobHunter 持有匿名隔离浏览器的生命周期，并由 Worker 确定性执行 `search` / `open` / `readPage`；Codex 只接收已采集的有界原文，不获得任何联网或浏览器工具。该执行器只接受当前的 `community-research-prompt@v4`。
- 外部 Agent 只接收结构化岗位 Brief、研究约束和输出 Schema，不接收姓名、联系方式、完整简历、个人回答、项目目录或 SQLite 路径。
- 原生搜索与人工导包路径不由 JobHunter 重新抓取来源页面；受限浏览器路径只在单次研究中读取清洗后的有界页面文本。两类结果均标记为 `unverified`，用户在明确看到状态后才能接受。
- 只保存问题、有限答案摘录和来源元数据；问题周边证据摘录与第三方整篇正文均不进入 Bundle 或数据库，用户通过原始来源链接核对上下文。
- 网友面经复用 `interview_experiences` / `interview_question_entries`，通过来源与审核字段和个人面经严格区分。

## 非目标

- 不绕过登录、付费墙、验证码、robots、访问控制或站点限流。
- 不做全站爬虫、长期监控或自动接受外部内容。
- 不把网友回答当作用户事实、标准答案或可直接照读的回答。
- 不允许外部 Agent 直接写数据库、读取 data root 或执行项目代码。
- 不连接或复用用户日常浏览器、登录态、Cookie、历史、密码、扩展或本地存储。
- 不向 Codex 暴露通用浏览器操作、Playwright/CDP 句柄、任意脚本、输入、点击、表单提交、上传或下载能力。
- 不在首版实现 Claude Code 适配器、语义向量聚类或自动可信度评分。

## 功能需求

- **COMM-001**：用户必须能创建包含目标岗位、可选公司/地区/级别/阶段、日期范围、语言、来源/条目上限及允许/禁止域名的研究 Brief；规范化 Brief 生成稳定请求指纹并支持幂等创建。
- **COMM-002**：系统必须从冻结 Brief 确定性生成版本化 Markdown Prompt 和 JSON Schema，二者可预览、复制和下载；预览与执行必须读取请求绑定的精确文件版本，并明确合规、引用、答案摘录长度、以技术区分度为主的价值筛选、跨来源语义级问题归并和禁止代答约束。`community-research-prompt@v4` 额外声明 Worker 预采集证据和 Prompt injection 边界，并禁止在输出中携带问题周边证据摘录；旧 Prompt 不得在原请求上静默升级。
- **COMM-003**：用户必须能选择已注册且与请求冻结 Prompt 版本兼容的 `codex-local@v1` 或 `browser-assisted-codex@v2` 发布异步研究任务；Web 以短事务原子完成 Task 入队和 ResearchRequest 关联，Worker 在隔离临时目录中执行，支持取消、超时、失败诊断和重试；手工重试必须原子关联新 Task，同一请求不得并发执行。未装配、不兼容或不可用的执行器不得在 Web 中显示为可用；旧 `@v1`/`@v2` 请求选择 v2 浏览器执行时必须拒绝并要求创建新请求。
- **COMM-004**：所有外部执行器只能获得 Prompt、Schema 和隔离输出路径；必须使用非交互只读沙箱，禁用 Shell、统一执行、Computer Use、多 Agent/Goal、授权请求、未授信插件/App/Skill、本地图片和工作区依赖工具，并且不把工作区、项目目录、SQLite、密钥值或个人面经传入参数、输出或日志。`codex-local@v1` 仍只保留原生实时网页搜索；`browser-assisted-codex@v2` 的联网与浏览器能力必须全部由 JobHunter Worker 持有，Codex 只从 stdin 接收有界、分区标记为不可信的预采集页面，不得获得 MCP bearer、Browser/Page 句柄、网络工具或页面原始 HTML。运行中的 Codex 版本不能精确禁用这些本机与联网能力时必须拒绝执行。
- **COMM-005**：即使没有可用执行器，用户也必须能上传最大 2 MiB 的 UTF-8 JSON `ResearchBundle`；自动执行结果必须进入完全相同的导入路径。
- **COMM-006**：导入必须严格校验 Schema 版本、请求指纹、可公开寻址且非保留/示例用途的 HTTP(S) 来源 URL、来源引用完整性、日期、问题非空和答案摘录长度；Bundle Schema 不接收证据摘录；仅由检索失败或占位内容构成的包视为无效，且无效包不创建网友面经候选。
- **COMM-007**：研究 Agent 必须在输出前对全部来源进行语义级问题归并：考察同一核心能力的高相似问题只保留技术信息最具体、追问价值最高的一条，有来源答案时优先选择摘录更完整且证据可回溯的版本，不得补写答案或跨来源拼接问题与证据。本地规范化仍必须移除 URL fragment、统一问题空白并计算稳定指纹；同一来源经历内漏过 Agent 的完全重复问题只保留首项，不引入首版向量聚类或自动相似度阈值。
- **COMM-008**：有效研究包只产生 `needs_review` 候选；页面展示公司、岗位、阶段、问题、可选答案摘录、来源链接、时间、警告和 `unverified` 状态，不展示证据摘录。
- **COMM-009**：用户必须能逐条接受或拒绝候选，并以请求修订号做并发校验；未经人工接受的候选不得进入网友面经查询。
- **COMM-010**：已接受内容必须出现在独立“网友面经”列表，可按公司、岗位和阶段浏览，并始终显示外部陈述、来源链接和未核验提示，不与个人历史面经混为用户事实。
- **COMM-011**：ResearchRequest 必须展示 Prompt 已就绪、排队、执行中、待审核、完成、失败和取消状态；任务迟到或与当前请求指纹不符时不得覆盖较新结果。
- **COMM-012**：同一请求可在没有候选被接受时重新导入研究包，最多保留 5 个有效 Bundle 版本；已有接受结果后不得静默替换，必须创建新的研究请求。
- **COMM-013**：研究原包、Prompt 与 Schema 使用通用文件实体保存，业务状态使用 ResearchRequest 和 Task；不为每种研究文档建立专用文档表。
- **COMM-014**：Web 必须完成创建请求、Prompt/Schema 导出、发布外部任务、人工导包、状态轮询、候选审核和网友面经浏览的完整流程。
- **COMM-015**：`browser-assisted-codex@v2` 必须由 JobHunter 为每次任务启动匿名隔离 BrowserContext 并持有完整生命周期；Worker 必须从冻结 Brief 生成有限、确定性的搜索词，使用固定搜索提供方依次执行 `search`、`open`、`readPage`，至少取得一个通过岗位词与面试词相关性硬门槛的可读公开页面，并在关闭 BrowserContext、网关与临时 Profile 后才启动 Codex。Codex 不得获得用户浏览器、登录态、MCP token、网络工具、通用浏览器操作、Shell 或任意本机脚本能力。网关必须校验每次导航与重定向，遵守允许/禁止域名，使用固定公网 IP 的 loopback 前向代理，并限制网络目标、连接、搜索次数、页面数、单响应/隧道/任务下行字节和时间；取消、超时或退出时关闭完整进程树与清理临时资源。
- **COMM-016**：`search` 必须返回受控来源引用，`open` 只能导航到该次搜索产生或 Brief 允许的公开 HTTP(S) 来源，`readPage` 只能返回带标题、最终 URL、抓取时间的清洗限长文本。Worker 必须对各查询结果按排名轮询，按请求 URL 与最终 URL 去重，并拒绝未同时命中从目标岗位派生的相关词和面试语义词的页面；页面正文只能通过 Codex stdin 传递，不得进入进程参数、环境变量、业务日志或长期文件。网页内容必须作为不可信数据与工具元数据分区；页面中的指令、代码、下载或授权建议不得扩大工具范围。执行器必须保留有界临时调用 trace；统一导包前在内存中确定性删除未完成 `open + readPage` 的来源/经历，以及问题原文不存在于同源正文的条目，将无法从原文证明的答案摘录置空并添加裁剪警告，裁剪后无真实问题则拒绝整包。剩余 Bundle 中每个来源 URL 必须等于当次 `open` 的最终 URL；`question.text` 与非空 `answerExcerpt` 必须逐字来自该页正文，但页面正文和问题周边证据摘录不得写入 Bundle 或数据库。
- **COMM-017**：当 Brief 的 `allowedDomains` 非空时，应用层必须先按规范化域名和目标岗位确定性生成 `site:<domain>` 定向查询，再生成通用查询；Worker 必须把两者作为优先、通用两个阶段执行，先搜索并耗尽优先阶段的合格候选，只有来源目标尚未满足且页面预算未耗尽时才搜索通用阶段。每个查询内部也必须先解包搜索跳转、执行公网 URL 与 Brief 域名策略过滤，再以过滤后的非空结果决定当前固定搜索提供方是否成功；原始 DOM 有链接但全部越界或无效时必须回退下一提供方。域名顺序、岗位顺序、查询模板和截断规则必须稳定，预览与执行使用同一冻结计划；`allowedDomains` 仍是允许范围而不是保证某站点一定成功，不能据此绕过登录、验证码或限流。
- **COMM-018**：采集层必须为搜索结果 URL 和 `open` 最终 URL 计算版本化的 canonical source identity，用于识别只在 fragment、默认端口、主机大小写或已知跟踪参数上不同的同一内容页；去重只能丢弃重复尝试，不能把 canonical identity 写回来源字段。EvidencePack、trace 和最终 Bundle 必须保留实际完成读取并通过安全校验的最终 URL，具有业务语义的查询参数不得被误删。
- **COMM-019**：页面完成 `readPage` 后、进入 EvidencePack 前必须通过确定性页面质量门槛。门槛至少拒绝登录/验证码/空壳页、仅评论或导航列表、正文过短，以及缺少足够面试问题候选或问题密度过低的页面；问题候选识别必须兼容问号、编号清单和无问号的技术题目标题。拒绝原因只以有界分类写入临时 trace，不长期保存被拒绝正文；全部页面未通过时不启动 Codex，也不创建候选或 Bundle 版本。
- **COMM-020**：必须用 `allowedDomains = ["nowcoder.com"]`、目标岗位包含“大模型算法”和“大模型应用开发”的显式联网覆盖测试验证定向采集：在不登录、不绕过限制的前提下，至少取得 4 个 canonical identity 不同且通过质量门槛的牛客公开面经页面，其中两个岗位方向各至少 2 个；最终来源仍进入人工审核而不自动接受。外部站点暂时不可用时测试必须明确报告未达标，不能用固定样本或重复 URL 参数变体冒充成功。
- **COMM-021**：浏览器网关必须以受信任解析结果验证并固定公开目标 IP，所有候选地址都通过非公网/保留网段拒绝规则。仅当运行环境显式允许透明网络转译、系统 DNS 返回非空且每一个地址都位于 `198.18.0.0/15` 时，系统才可通过有界受信任 DNS 查询取得并校验真实公网地址，再只把该 `198.18/15` 地址用于实际连接；安全策略、域名审计和固定目标仍以已校验的公网地址为准。混合答案、字面 IP、受信任查询无公开答案或任一公网校验失败时不得启用转译，也不得把 `198.18/15` 当作普通公网地址放行。

## 质量与失败行为

- **COMM-Q01**：外部进程、网络研究和文件写入不发生在数据库事务内；候选替换和审核使用短事务与 CAS。
- **COMM-Q02**：外部输出视为不可信数据；页面不渲染其 HTML，日志只记录白名单状态、退出码和截断错误摘要。
- **COMM-Q03**：执行器超时或取消必须终止子进程；自动导包 claim 与最终提交都必须核验当前 Task 仍为 running 且未请求取消；输出超过 2 MiB、退出非零、缺失结果或无效 JSON 均不得产生候选。
- **COMM-Q04**：普通 CI 只使用伪执行器和脱敏研究包，不访问网络、不依赖本机 Codex 登录。
- **COMM-Q05**：公开来源链接以新窗口安全打开；页面清楚区分“来源未核验”与“用户已接受用于准备”。
- **COMM-Q06**：浏览器、网络、模型和文件写入不发生在数据库事务内；普通 CI 只使用伪浏览器网关和固定样本，真实联网仅作为显式手工 smoke test。
- **COMM-Q07**：QueryPlan、canonical source identity 和页面质量判定必须是纯确定性、版本化且可用固定样本回归的规则；联网覆盖测试只补充真实站点可达性与覆盖度证据，不替代普通 CI。
- **COMM-Q08**：受信任 DNS 响应、透明转译判定和代理连接地址都必须有数量、字节、时间、缓存与并发上限；DNS 失败、混合转译答案或非公网答案必须 fail closed，不能降级为未校验的系统连接。

## 验收场景

1. 用户创建后端岗位研究请求，得到稳定 Prompt 与 Schema；重复相同 Brief 返回同一请求。（COMM-001,002,013）
2. 伪外部执行器返回合法研究包，Worker 通过统一导入路径生成待审核候选；任务取消会中止执行且不产生候选。（COMM-003–006,011, COMM-Q01–Q04）
3. 研究 Prompt 要求 Agent 将不同措辞但同问 SFT 优化等核心能力的问题归并为一个高价值代表项；用户手动导入仍由本地规则折叠同来源完全重复项。（COMM-002,005–008）
4. 指纹不符、`file:`/保留用途 URL、仅含检索失败占位内容、超长摘录或问题引用未知来源的包被拒绝，数据库没有候选残留。（COMM-006, COMM-Q02,Q03）
5. 用户接受一条、拒绝一条；只有接受项进入网友面经，并持续显示来源与未核验提示。（COMM-008–010, COMM-Q05）
6. 本机没有 Codex 时自动任务给出安装/登录恢复说明，用户仍可复制 Prompt、导入结果并完成审核。（COMM-002,003,005,011,014）
7. 旧修订审核和迟到外部结果都被拒绝；已有接受项的请求不能被新包静默替换。（COMM-009,011,012）
8. 研究 Task 失败后从通用任务页重试，请求原子指向新 Task；取消发生在执行器返回或 staging 写入之后时，候选与正式 Bundle 版本仍不提交。（COMM-003,011, COMM-Q01,Q03）
9. `community-research-prompt@v4` 请求由 Worker 使用伪浏览器网关确定性完成 `search/open/readPage`，再把有界原文从 stdin 交给无网络工具的伪 Codex；网关拒绝登录、表单、下载、任意 URL/脚本、内网与越界重定向，注入页面伪指令时执行器不扩权，并在内存中将问题回溯到本次 `open` trace 的最终 URL；持久化结果不包含证据摘录，旧 Prompt 请求选择该执行器被拒绝。（COMM-002,004,015,016, COMM-Q02,Q06）
10. 浏览器研究任务在成功、失败、取消与超时后都不遗留 BrowserContext、Codex/工具服务子进程或临时 Profile，无效结果不产生候选和正式 Bundle 版本。（COMM-003,005,011,015, COMM-Q01,Q03,Q06）
11. Brief 允许 `nowcoder.com` 时，冻结 QueryPlan 先产生覆盖两个目标岗位的 `site:nowcoder.com` 查询，再产生通用查询；没有允许域名时保持通用查询行为。（COMM-001,015,017, COMM-Q07）
12. 同一牛客正文的无参数 URL、带 `utm_*`/分享跟踪参数 URL 和重定向最终 URL 只消耗一个来源名额，但 trace、EvidencePack 与 Bundle 保留实际成功读取的最终 URL；带业务主键的不同页面不得合并。（COMM-016,018, COMM-Q07）
13. 固定样本中的登录空壳、评论列表和低问题密度页面被挡在 EvidencePack 之前；包含编号技术题清单但没有问号的真实面经仍可通过，并记录有界质量判定。（COMM-015,016,019, COMM-Q02,Q07）
14. 显式牛客联网覆盖测试取得至少 4 个不同内容页，且“大模型算法”和“大模型应用开发”各至少 2 个；重复跟踪 URL、不相关评论页和空壳页不计入覆盖数，结果只进入 `needs_review`。（COMM-008,017–020, COMM-Q05–Q07）
15. 固定网络样本证明：普通公网系统 DNS 直接固定公网地址；系统 DNS 全部落在 `198.18/15` 时先通过受信任 DNS 验证公网目标、再按显式开关使用转译连接地址；混合 `198.18/15 + 私网/公网`、非公网字面 IP 和受信任查询无结果均不会启用转译或绕过 SSRF 拒绝，公网字面 IP 也只按普通公网目标固定而不走转译。（COMM-015,021, COMM-Q02,Q06,Q08）

## 验收结果

- 普通测试已覆盖冻结 QueryPlan、伪浏览器采集、岗位与面试相关性拒绝、Prompt injection、URL/SSRF/重定向、loopback MCP 认证与 Host/Origin、Codex 无网络/浏览器凭据、Prompt 版本拒绝和全结果路径资源回收。
- 显式联网 smoke test 已在无登录公开网页上完成，并确认至少一个来源经过真实 `open + readPage`。
- 实际产品研究任务已产生非空、可从同源正文逐字回溯的问题并进入 `needs_review`；未执行自动接受，审核边界保持不变。

## 未解决问题

- 定向来源覆盖增强仍在实现和真实联网验收中；完成前不把多来源牛客覆盖声明为已交付能力。
