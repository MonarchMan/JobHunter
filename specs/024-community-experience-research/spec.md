# 024 外部 Agent 网友面经研究规格

> 状态：Implemented
> 依赖：002, 003, 011, 012, 021, 022

## 目标

让用户按目标岗位创建公开面经研究请求，导出供应商无关的研究 Prompt/JSON Schema，或把请求交给本机受限外部 Agent 执行。外部结果必须经过本地校验、确定性去重和人工审核，接受后进入独立的“网友面经”列表，从而形成从研究目标到可用面试准备资料的完整闭环。

## 首版假设

- 首个自动执行器为 `codex-local@v1`；本机未安装、未登录或执行失败时，Prompt 导出与 JSON 研究包人工导入仍可用。
- 外部 Agent 只接收结构化岗位 Brief、研究约束和输出 Schema，不接收姓名、联系方式、完整简历、个人回答、项目目录或 SQLite 路径。
- 首版不由 JobHunter 重新抓取来源页面；所有来源标记为 `unverified`，用户在明确看到状态后才能接受。
- 只保存问题、有限答案摘录、有限证据摘录和来源元数据，不镜像第三方整篇正文。
- 网友面经复用 `interview_experiences` / `interview_question_entries`，通过来源与审核字段和个人面经严格区分。

## 非目标

- 不绕过登录、付费墙、验证码、robots、访问控制或站点限流。
- 不做全站爬虫、长期监控或自动接受外部内容。
- 不把网友回答当作用户事实、标准答案或可直接照读的回答。
- 不允许外部 Agent 直接写数据库、读取 data root 或执行项目代码。
- 不在首版实现 Claude Code 适配器、语义向量聚类或自动可信度评分。

## 功能需求

- **COMM-001**：用户必须能创建包含目标岗位、可选公司/地区/级别/阶段、日期范围、语言、来源/条目上限及允许/禁止域名的研究 Brief；规范化 Brief 生成稳定请求指纹并支持幂等创建。
- **COMM-002**：系统必须从冻结 Brief 确定性生成版本化 Markdown Prompt 和 JSON Schema，二者可预览、复制和下载；预览与执行必须读取请求绑定的精确文件版本，并明确合规、引用、摘录长度和禁止代答约束。
- **COMM-003**：用户必须能选择 `codex-local@v1` 发布异步研究任务；Web 以短事务原子完成 Task 入队和 ResearchRequest 关联，Worker 在隔离临时目录中执行，支持取消、超时、失败诊断和重试；手工重试必须原子关联新 Task，同一请求不得并发执行。
- **COMM-004**：外部执行器只能获得 Prompt、Schema 和隔离输出路径；必须使用非交互只读沙箱，仅保留原生实时网页搜索，禁用 Shell、统一执行、本地浏览器、Computer Use、多 Agent/Goal、授权请求、插件、App、Skill、本地图片和工作区依赖工具，并且不把工作区、项目目录、SQLite、密钥值或个人面经传入参数、输出或日志；运行中的 Codex 版本不支持这些限制时必须拒绝执行。
- **COMM-005**：即使没有可用执行器，用户也必须能上传最大 2 MiB 的 UTF-8 JSON `ResearchBundle`；自动执行结果必须进入完全相同的导入路径。
- **COMM-006**：导入必须严格校验 Schema 版本、请求指纹、HTTP(S) 来源 URL、来源引用完整性、日期、问题非空和摘录长度；无效包不创建网友面经候选。
- **COMM-007**：规范化必须移除 URL fragment、统一问题空白并计算稳定指纹；同一来源经历内的完全重复问题只保留首项，不同来源的相同问题保留独立出处并展示重复次数。
- **COMM-008**：有效研究包只产生 `needs_review` 候选；页面展示公司、岗位、阶段、问题、有限摘录、来源链接、时间、警告和 `unverified` 状态。
- **COMM-009**：用户必须能逐条接受或拒绝候选，并以请求修订号做并发校验；未经人工接受的候选不得进入网友面经查询。
- **COMM-010**：已接受内容必须出现在独立“网友面经”列表，可按公司、岗位和阶段浏览，并始终显示外部陈述、来源链接和未核验提示，不与个人历史面经混为用户事实。
- **COMM-011**：ResearchRequest 必须展示 Prompt 已就绪、排队、执行中、待审核、完成、失败和取消状态；任务迟到或与当前请求指纹不符时不得覆盖较新结果。
- **COMM-012**：同一请求可在没有候选被接受时重新导入研究包，最多保留 5 个有效 Bundle 版本；已有接受结果后不得静默替换，必须创建新的研究请求。
- **COMM-013**：研究原包、Prompt 与 Schema 使用通用文件实体保存，业务状态使用 ResearchRequest 和 Task；不为每种研究文档建立专用文档表。
- **COMM-014**：Web 必须完成创建请求、Prompt/Schema 导出、发布外部任务、人工导包、状态轮询、候选审核和网友面经浏览的完整流程。

## 质量与失败行为

- **COMM-Q01**：外部进程、网络研究和文件写入不发生在数据库事务内；候选替换和审核使用短事务与 CAS。
- **COMM-Q02**：外部输出视为不可信数据；页面不渲染其 HTML，日志只记录白名单状态、退出码和截断错误摘要。
- **COMM-Q03**：执行器超时或取消必须终止子进程；自动导包 claim 与最终提交都必须核验当前 Task 仍为 running 且未请求取消；输出超过 2 MiB、退出非零、缺失结果或无效 JSON 均不得产生候选。
- **COMM-Q04**：普通 CI 只使用伪执行器和脱敏研究包，不访问网络、不依赖本机 Codex 登录。
- **COMM-Q05**：公开来源链接以新窗口安全打开；页面清楚区分“来源未核验”与“用户已接受用于准备”。

## 验收场景

1. 用户创建后端岗位研究请求，得到稳定 Prompt 与 Schema；重复相同 Brief 返回同一请求。（COMM-001,002,013）
2. 伪外部执行器返回合法研究包，Worker 通过统一导入路径生成待审核候选；任务取消会中止执行且不产生候选。（COMM-003–006,011, COMM-Q01–Q04）
3. 用户手动导入含重复问题的合法包，同来源重复被折叠，不同来源保留并显示出现次数。（COMM-005–008）
4. 指纹不符、`file:` URL、超长摘录或问题引用未知来源的包被拒绝，数据库没有候选残留。（COMM-006, COMM-Q02,Q03）
5. 用户接受一条、拒绝一条；只有接受项进入网友面经，并持续显示来源与未核验提示。（COMM-008–010, COMM-Q05）
6. 本机没有 Codex 时自动任务给出安装/登录恢复说明，用户仍可复制 Prompt、导入结果并完成审核。（COMM-002,003,005,011,014）
7. 旧修订审核和迟到外部结果都被拒绝；已有接受项的请求不能被新包静默替换。（COMM-009,011,012）
8. 研究 Task 失败后从通用任务页重试，请求原子指向新 Task；取消发生在执行器返回或 staging 写入之后时，候选与正式 Bundle 版本仍不提交。（COMM-003,011, COMM-Q01,Q03）
