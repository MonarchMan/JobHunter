# 002 SQLite 持久化规格

> 状态：Implemented
> 依赖：001

## 目标

为所有首期领域数据提供可迁移、可校验、可备份的 SQLite 和本地文件持久化实现。

## 非目标

- 不支持多个远程数据库节点。
- 不实现业务状态决策。
- 不将密钥保存到数据库。

## 功能需求

- **PST-001**：首次初始化必须创建专题表设计中的全部表、约束、索引和 FTS5 搜索结构。
- **PST-002**：每次连接必须启用 foreign keys、WAL 和 busy timeout，并验证数据库能力。
- **PST-003**：迁移必须按版本顺序且至多执行一次；失败时不得留下标记为成功的半迁移。
- **PST-004**：Repository 必须为应用层提供事务单元，且领域层不可见 Drizzle 类型。
- **PST-005**：职位、修订、观察和状态事件必须支持同事务原子写入。
- **PST-006**：文件必须先原子写入再登记；重复内容可按 SHA-256 复用，路径不得逃逸 `var/`。
- **PST-007**：关键词查询必须使用 FTS5，并支持公司、状态、地点、细分职位类别和分数筛选组合。
- **PST-008**：备份必须先取得数据库一致性快照，再从快照导出被引用文件清单、哈希和元数据；恢复前必须验证清单，恢复后运行完整性检查，恢复时不得有 CLI/Worker/Web 持有活动数据库连接。
- **PST-009**：普通设置表只接受设置 Registry 明确声明为非敏感的 key 和 Schema；未知 key 以及任何秘密值都必须拒绝。
- **PST-010**：删除/清理必须是显式用例，不得由普通查询或同步隐式触发。
- **PST-011**：系统设置必须通过白名单 Registry 持久化；职位理解设置的默认值为关闭，且初始化/迁移后的数据库必须显式保存关闭状态。

## 质量需求

- **PST-Q01**：所有事务不得包含网络、模型或大文件解析操作。
- **PST-Q02**：空库迁移、上一版本升级、外键检查和 integrity check 必须自动化。
- **PST-Q03**：默认个人数据路径必须可配置，且不提交版本库。

## 验收场景

1. **PST-A01**：空目录初始化后，Schema 版本正确，PRAGMA 与 FTS5 自检通过。
2. **PST-A02**：重复运行迁移不修改已有数据，也不重复执行 migration。
3. **PST-A03**：在 Revision 写入失败时，Job 当前投影和 StatusEvent 一并回滚。
4. **PST-A04**：含 `../` 或绝对路径的 artifact 相对路径被拒绝。
5. **PST-A05**：相同文件内容重复写入不产生内容重复文件。
6. **PST-A06**：备份快照后新增的数据库/文件不进入本次备份；快照所引用文件全部存在且哈希一致。篡改一个文件后，恢复在替换现有数据前失败。
7. **PST-A07**：数据库缺少 FTS5 时启动失败并给出能力错误码。

## 未解决问题

无。
