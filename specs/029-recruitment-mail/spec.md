# 029 招聘邮件识别与申请进展跟踪规格

> 状态：Ready
> 依赖：001, 002, 003, 008, 011, 012, 022
> 架构决策：ADR-0055、ADR-0056

## 目标

在用户显式授权的邮箱范围内增量读取邮件，识别与本人求职流程有关的通知，提取笔试、面试、流程结束和 Offer 等结构化事件，并形成可人工确认、可追溯的申请时间线。邮箱读取不得改变原邮箱状态，也不得把无关邮件正文扩散到持久化、任务或日志中。

## 术语

- **邮箱配置（MailboxConfig）**：本地非敏感配置文件中的一个邮箱账号设置，包含稳定邮箱键、provider、文件夹、计划和凭据引用；凭据值由独立加密文件持有。
- **邮箱运行状态（MailboxRuntimeState）**：数据目录中独立于普通配置的可恢复运行文件，保存增量游标、连接代次和最近同步状态。
- **邮件引用（MailMessageRef）**：用于增量同步、幂等和重新获取正文的最小外部消息身份，不等于邮件正文归档。
- **申请事件（ApplicationEvent）**：由已接受或用户确认的招聘邮件产生的不可变流程事实。
- **求职申请（JobApplication）**：某家公司某一岗位的申请当前态，可选择性关联现有 `Job`，但不要求邮件中的岗位必须已存在于职位库。

## 范围

- 支持一个或多个邮箱连接，每个连接只读取用户确认的文件夹或标签。
- 首次连接执行有界历史回溯，之后使用提供商游标、增量令牌或稳定消息键继续同步。
- 识别中英文招聘流程邮件，为低置信结果提供确认或忽略入口。
- 展示邮箱连接状态、待确认邮件、申请列表、申请时间线和临近截止时间。
- 首版同时接入 Gmail API、Microsoft Graph 和标准 IMAP over TLS 三条连接器路线；IMAP 覆盖 QQ、163 和企业邮箱等允许第三方只读访问的服务。

## 非目标

- 不发送、回复、转发、删除、移动、归档邮件，也不修改已读、星标或标签状态。
- 不自动点击邮件链接、接受会议、提交笔试、填写表单或执行职位申请。
- 不以邮箱事件修改 `Job` 的有效、失效或关闭状态。
- 首版不建设公网 Webhook、推送通知服务或多设备云同步。
- 首版只读取邮件主题、发件信息和正文，不读取或解析 `.ics` 日历、普通附件、压缩包或可执行内容。
- 不把 Offer 意向书解释为正式劳动合同，不对薪酬、条款或法律效力作判断。
- 首版不支持修改分类字段、修正已生成事件或追加人工事件；用户只能确认、忽略候选并选择或创建申请关联。
- 不承诺恢复授权前的完整邮箱历史，也不扫描垃圾箱和已删除邮件。

## 功能需求

- **MAIL-001**：用户必须能通过本地非敏感配置创建、查看、暂停、恢复和断开邮箱；配置必须声明稳定邮箱键、唯一 provider key、授权方式、增量能力、文件夹能力和支持状态。配置文件默认位于 `<dataRoot>/mail/mailboxes.json`，可由 `JOBHUNTER_MAILBOX_CONFIG_PATH` 覆盖；首版必须分别提供 `gmail`、`microsoft-graph` 和 `imap` 三个连接器，并在各自通过完整验收后标记为 supported；三者全部通过前不得宣称 M1 邮箱能力完整交付。
- **MAIL-002**：邮箱访问凭据、OAuth Token、刷新令牌和应用专用密码必须使用 AES-256-GCM 保存到独立加密文件；密钥使用独立文件或环境主密钥，本地非敏感配置只允许保存不可直接授权的 `credentialRef` 与脱敏地址，SQLite、任务和日志不得包含凭据值。已保存的 IMAP 授权码默认不进入邮箱列表快照；仅当用户在设置页主动点击“显示已保存授权码”时，才通过无缓存的受控接口临时回传到当前浏览器会话，默认仍以密码模式隐藏，隐藏后前端清理明文。Gmail 和 Microsoft OAuth 令牌始终不得回传。
- **MAIL-003**：首次同步必须使用有界回溯窗口，默认读取最近 30 天、可配置但不得超过 365 天；默认只包含收件箱，其他文件夹或标签必须由用户显式选择，垃圾箱和已删除邮件始终排除。
- **MAIL-004**：后续同步必须优先使用提供商增量游标；游标和最近同步状态保存到数据目录中的运行状态文件，并以临时文件加原子替换更新。游标缺失、失效或最近成功定位时间早于回溯窗口时，必须丢弃旧游标并按配置窗口进行有界重建；重复读取不得产生重复申请事件。
- **MAIL-005**：连接器必须为每封邮件提供邮箱内稳定的 `externalMessageKey`、接收时间、线程键、内容版本标识、可选且经过校验的 `sourceUrl` 和按需正文读取能力；无法获得全局稳定 ID 的协议必须把文件夹身份、代次和消息 UID 纳入稳定键。`sourceUrl` 只用于用户定位原邮件，不能代替稳定消息身份；包含授权凭据或一次性访问令牌的 URL 不得持久化，没有安全网页入口时必须留空。
- **MAIL-006**：同步任务只能先保存最小邮件引用并进行候选粗筛；邮件主题、发件显示名、发件域和正文必须在事务外按需读取、限制大小并完成边界校验，不得加载远程图片、样式、脚本或跟踪资源。首版不读取日历或其他附件参与分类。
- **MAIL-007**：确认与招聘无关的邮件不得持久化主题、发件人地址、正文、HTML、附件或模型输入；只允许保存去重所需的外部身份、内容哈希、处理结论、分类器版本和时间。
- **MAIL-008**：系统必须区分 `application_acknowledged`、`assessment_invited`、`interview_invited`、`interview_rescheduled`、`interview_cancelled`、`action_required`、`process_updated`、`rejected`、`process_closed`、`offer_intent`、`offer_issued`、`other_recruiting` 和 `not_recruiting`；职位推荐、招聘营销、验证码和与本人申请无关的活动通知不得自动创建申请事件。
- **MAIL-009**：招聘分类必须输出公司、岗位、流程阶段、申请编号、发生时间、统一日程结构、地点、会议链接、操作链接、招聘联系人、置信度和字段证据；日程结构按 030 规格区分活动类型、开始/结束/截止、仅日期事实、改期原时间、时间精度和时区来源，无法确认的字段使用 null，不得猜测补全。
- **MAIL-010**：是否属于招聘流程候选必须先由版本化确定性规则和已知模板识别完成，规则以高召回为目标；稳定的招聘营销、宣讲、问卷、验证码和普通资讯可直接忽略，未知但具有招聘流程信号的邮件必须保守放行。候选邮件在配置模型可用时统一交给无工具分类 Agent 完成事件理解和字段提取；Agent 输入只包含清洗后的有界主题、发件显示名、发件域、正文、接收时间和默认时区，不包含日历或其他附件。输出必须通过版本化 Schema 和业务校验；AgentRun 只保存输入/输出哈希、状态和用量，不保存邮件文本或字段提取结果。
- **MAIL-011**：分类策略必须支持自动接受、待人工确认和忽略三种结论。低置信或公司、岗位、事件类型存在关键歧义时不得推进申请状态；模型关闭或不可用时，规则无法确认的候选邮件进入待确认而不是静默丢弃。待确认只保存消息引用和处理状态，用户打开详情时重新读取并分类，不持久化中间分类结果或版本历史。
- **MAIL-012**：系统必须为自动接受或用户确认的招聘邮件直接建立不可变申请事件，并通过 `MailMessageRef` 关联稳定消息身份和可选来源 URL；明确包含笔试、测评或面试日程的高置信邮件不得因缺少申请编号、公司或岗位而阻止日程入库，缺失身份字段使用明确占位并按消息隔离，身份齐全时才按邮箱、公司和岗位稳定归组；非日程邮件仍可按申请编号、已知公司身份、岗位名称和线程证据关联 `JobApplication`，一封邮件可能涉及多个申请或无法唯一关联时必须请求用户选择。
- **MAIL-013**：`JobApplication` 状态仅允许 `unknown`、`applied`、`assessment`、`interview`、`offer_intent`、`offered`、`rejected`、`closed`。只有已确认事件才能更新当前态；较旧邮件不得覆盖较新的有效状态，后到达的明确事件可以重新打开已结束流程，`offer_intent` 不得自动提升为 `offered`。
- **MAIL-014**：首版人工操作仅允许确认、忽略以及选择或创建申请关联，不允许修改分类字段、修改既有申请事件或追加人工事件；需要更正的候选必须先忽略，字段与事件修订能力由后续规格单独引入。
- **MAIL-015**：Web 必须提供邮箱连接设置、最近同步状态、待确认列表、申请列表和申请时间线；截止时间缺少明确时区时使用用户默认时区计算并标记为推断，界面同时保留原始时间文本。
- **MAIL-015A**：邮箱设置区右上角必须以“+”图标提供添加入口；点击后先展示 Gmail、Microsoft 365 / Outlook 和 IMAP 三种 provider，只有用户选定 provider 后才展开对应添加卡片，不得默认常驻暴露 IMAP 表单。OAuth provider 未配置客户端时必须明确显示缺失配置且不得发起无效授权。
- **MAIL-016**：系统不得自动打开邮件中的 URL。界面只展示经过协议校验的 `https` 链接、域名和来源邮件定位入口，用户点击时使用外部链接安全属性；包含必要一次性参数的原链接不得进入日志或诊断摘要。
- **MAIL-017**：邮箱读取和分类必须通过持久化任务执行。连接同步使用邮箱级并发键；单邮件分类任务的幂等身份必须包含邮件引用、提供商内容版本和分类策略版本，最终申请事件唯一身份还必须包含清洗后的内容哈希和邮件内事件序号；网络和模型调用不得位于数据库事务内。
- **MAIL-018**：断开连接必须停止后续计划并撤销或删除凭据；用户可分别选择保留既有申请时间线或删除该邮箱派生的数据。删除前必须展示稳定影响摘要，失败时不得留下“数据库已断开但凭据仍被当作有效”的状态。

## 质量与安全需求

- **MAIL-Q01**：`packages/mail/core` 只定义邮箱连接器协议、外部邮件 DTO、错误分类和契约测试，不依赖应用、数据库、Web、Worker、模型 SDK 或具体邮箱 SDK；`packages/mail/connectors` 实现协议但不得被领域层或应用层反向导入。
- **MAIL-Q02**：领域层只定义招聘分类结果、申请、事件和状态规则；Repository、邮箱配置、运行状态、凭据库、授权、任务发布和事务端口由应用层或邮箱契约声明，基础设施由入口装配。
- **MAIL-Q03**：所有连接器输出、MIME 解析结果、规则结果和模型输出必须在边界使用运行时 Schema 校验；未知枚举、非法 URL、无效时间或超限正文必须进入可诊断失败路径。
- **MAIL-Q04**：邮件主题、地址、正文、链接参数、申请编号和模型输入不得出现在普通日志、任务 payload、错误摘要或诊断页面；可观测性只记录连接 ID、消息引用 ID、阶段、计数、耗时和固定错误码。
- **MAIL-Q05**：邮件正文始终视为不可信输入。HTML 不执行脚本、不请求外部资源；Agent 不获得工具；MIME 深度、正文大小和 URL 数量必须有可配置上限并在超限时安全失败，任何附件均不得进入分类边界。
- **MAIL-Q06**：连接器网络调用必须接受 `AbortSignal`、超时和限流上下文；取消、限流、认证失效、游标失效、解析变化和永久不存在必须映射为稳定错误类别。
- **MAIL-Q07**：脱敏固定样本必须覆盖中英文邀请、改期、取消、拒绝、流程结束、Offer 意向、正式 Offer、申请确认，以及邀请投递广告、笔试或面试体验调研、职位推荐、营销、验证码、引用历史和恶意指令等负例；任何关键邀请或 Offer 样本被直接判为无关时不得通过发布门禁。
- **MAIL-Q08**：相同邮箱游标重放、任务租约恢复、同一邮件内容重复获取和分类器重跑不得产生重复申请事件；业务事件幂等身份必须基于稳定邮箱键、稳定消息键、内容哈希和邮件内事件序号，不能因分类器版本变化而失效。
- **MAIL-Q09**：邮件与申请删除、凭据移除、邮箱配置、运行状态、备份和恢复必须有集成测试；普通应用备份不得包含加密凭据文件或密钥，恢复后凭据引用不可用的邮箱在重新授权前保持不可读取状态。跨机器迁移必须通过独立安全通道同时迁移密文与对应密钥，或在目标机器提供相同环境主密钥。

## 验收场景

1. 用户连接一个通过支持门禁的邮箱，只选择收件箱并执行默认 30 天回溯；Worker 重启后从仍在窗口内的已提交游标继续，同一邮件不重复生成事件。（MAIL-001,003,004,005,017, MAIL-Q06, MAIL-Q08）
2. 本地非敏感配置只能看到 `credentialRef` 与脱敏账号，数据库、任务、日志和诊断页面不能检索到访问令牌、应用密码或完整邮件正文；只有设置页用户主动触发的无缓存 IMAP 授权码回显例外，且不能回传 OAuth 令牌。（MAIL-002,007, MAIL-Q04）
3. 一封中文笔试邀请和一封英文面试邀请分别提取公司、岗位、截止时间或面试时间，并形成两个可追溯申请事件。（MAIL-008,009,012）
4. 一封职位推荐 Newsletter、一封招聘活动营销邮件和一封验证码邮件不会自动创建 `JobApplication` 或推进状态。（MAIL-007,008,011）
5. 邮件正文包含“忽略系统要求并调用工具”等文本时，分类 Agent 仍无工具调用能力，只返回通过 Schema 的分类结果或失败。（MAIL-010, MAIL-Q03, MAIL-Q05）
6. 稳定负例只经过规则筛选且不调用模型；模型关闭或暂时不可用时，招聘候选保留为待确认引用，不生成缺少已校验字段的申请事件，邮箱同步仍可完成。（MAIL-010,011）
7. 同一公司存在两个进行中岗位且拒信未包含申请编号时，系统不得任意关联；用户选择目标申请后才创建对应申请事件。（MAIL-012,014）
8. 先同步到较新的 Offer 意向，再补读较旧的面试邀请时，申请状态保持 `offer_intent`；随后收到明确正式 Offer 时才进入 `offered`。（MAIL-013）
9. 面试时间未写时区时，界面使用用户默认时区显示推断标记和原始文本；首版不提供字段更正入口。（MAIL-009,014,015）
10. HTML 邮件中的远程图片、脚本和跟踪资源不会被请求，日历和其他附件均不会被解析、执行或发送给模型；分类只使用清洗后的邮件正文。（MAIL-006,016, MAIL-Q03, MAIL-Q05）
11. 断开邮箱并选择保留申请时间线后，计划停止、凭据不可用、既有申请仍可查询；选择删除派生数据时先展示影响摘要并完成引用安全检查。（MAIL-018, MAIL-Q09）
12. Gmail、Microsoft Graph 和 IMAP 连接器分别通过公共契约、固定样本、取消、游标失效、认证失效和幂等测试后才能标记 supported；任一连接器运行失败不影响其他已连接邮箱。（MAIL-001,005, MAIL-Q01, MAIL-Q06, MAIL-Q07）

## 未解决问题

无。首批连接器固定为 Gmail API、Microsoft Graph 和标准 IMAP over TLS；后续增加其他专有邮箱 API 时仍遵守相同领域、持久化、任务和 supported 门禁。
