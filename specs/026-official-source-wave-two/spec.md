# 026 第二批官网来源扩展规格

> 状态：In Progress
> 依赖：004, 005, 016, 017, 018, 019

## 目标

将快手、哔哩哔哩、滴滴、携程和米哈游纳入官网接入范围，先完成快手与哔哩哔哩的匿名协议验证，再按证据逐渠道实现与晋级。

## 需求

- **SWT-001**：五家公司纳入研究台账，分别记录实习、校招、社招官方入口和物理来源；未验证渠道不能声明 supported。
- **SWT-002**：第一批优先验证快手与哔哩哔哩；列表最多采样三页，必须包含首页与末页，并读取至少一条岗位详情。不得以全量在线遍历作为本次门禁。
- **SWT-003**：记录请求协议、响应总数、分页参数、稳定职位 ID、岗位级 URL、职责要求和渠道分类依据；样本 ID 重复、总数漂移、分页错误、验证页面或不明空结果均不能算通过。
- **SWT-004**：使用公开匿名 HTTP 或受控浏览器执行官网脚本；遵守 SSR-003 的会话与访问边界。采样证据声明 partial / sampled_pages，不推断全量覆盖。
- **SWT-005**：验证通过后，物理适配器按 companies/<company>/<channel> 组织，拥有 Schema、离线测试、定向在线测试；catalog、Registry 和支持矩阵同步更新后才能默认启用。
- **SWT-006**：遵循既有逻辑渠道到多物理来源映射。待接入公司允许只有逻辑渠道而无物理来源；不创建占位 adapter。既有公司和来源的稳定 ID 不变。
- **SWT-007**：B 站社招通过 SourcePageClient 初始化匿名会话并重放官网 JSON；生产默认每页 50 条，分页始终按请求容量与 total 计算，不使用响应 pages/size。业务失败、Schema 漂移和非社招记录必须显式失败；重复 ID、缺页、总数变化或采样均不得报告 complete。
- **SWT-008**：B 站社招使用稳定数字 ID、岗位级新站 URL 和字段白名单；列表正文内联包含职责与要求，HTML 转纯文本，官网无时区日期明确按 Asia/Shanghai 解释。没有浏览器客户端时返回 access_blocked，不自动尝试裸 HTTP。
- **SWT-009**：快手社招、日常实习和校园招聘必须分别验证并注册独立 adapter；依据官方项目与职位性质校验频道，不以兄弟渠道成功替代独立首页/末页/详情门禁。
- **SWT-010**：快手分页优先调用当前官网已加载的原始公开职位请求方法，由官网完成匿名请求处理；不复制签名、不修改浏览器属性、不处理验证码。运行时模块或协议变化必须显式失败，不猜测模块 ID 或降级为空结果。
- **SWT-011**：快手每个渠道须验证配置容量、响应页码、末页边界、总数和唯一 ID；名单只保存公开字段，字典映射地点和工作经验。采样、短页、重复 ID、总数漂移均不得报告完整覆盖。生产请求低频串行，健康检查仅取首页。
- **SWT-012**：快手三个逻辑渠道对应四个 required 物理来源：社招、日常实习、校园留用实习、应届校招。实习渠道必须同时纳入后两种实习入口，各自保留 ID 空间和缺失状态；校园两来源每次从完整项目清单选取对应类型最新有效年份，缺失或同年多项目歧义必须失败。

- **SWT-013**：滴滴社招、实习、校招按官网实际导航和协议独立验证与接入，不以单一入口代表整个公司。多个物理来源保留各自身份和同步状态；国内招聘与海外招聘分开声明范围。
- **SWT-014**：滴滴生产适配器必须校验公开业务响应、招聘类型、分页容量、总数、稳定 ID 和职责要求；健康检查只取首页。每个来源以首页/末页和一条详情 smoke 验收，采样或分页异常报告 partial，不能关闭旧岗位。禁止使用登录 Cookie、签名伪造或验证码绕过。
- **SWT-015**：滴滴三渠道映射社招、实习、常规校招三个 required 物理来源，以及校园下的未来精英 supplemental 来源。当前校招支持范围以已验证的常规校招为准，未来精英后续独立验证，不阻断校招逻辑渠道 supported。Moka pause 记录参与分页校验但不作为在招岗位入库；未知状态失败。未来精英无真实详情时自身保持 experimental/default off。
- **SWT-016**：缺少列表正文的来源声明 detail=required；同步在数据库事务外先取得真实详情再归一化与入库，失败隔离且不写占位正文。既有 inline/deferred 行为不变；在线 smoke 仍只读取一条详情，不运行全量同步。
- **SWT-017**：滴滴社招明确验证响应 page 等于请求页、size 等于已验证容量 16，不修改总数来掩盖缺页。用户手动确认第 65 页异常属于官网行为后，允许将可正常获取列表与详情的适配器记为 supported，并记录已知上游分页缺陷；此为该来源的明确验收例外，不放宽其他来源门禁。supported 不代表该次采集完整，短页、重复、总数漂移仍必须报告 partial 并禁止缺失下线。在线验证不全量遍历。

- **SWT-018**：携程按当前官网导航独立确认社招、实习、校招及必要物理来源；匿名列表/详情协议、分页与招聘性质须独立验证，未证实覆盖的品牌或国际站不隐含覆盖。实现严格边界校验、字段白名单、必要真实详情、限流和 partial 下线保护；仅首尾页与一条详情 smoke，不全量在线门禁。

- **SWT-019**：独立核实米哈游社会、校园和实习入口及实际招聘性质，按必要物理来源建模；使用匿名官方协议，严格校验分页回显、身份、正文和渠道归属。缺少列表正文时沿用 required 详情，不保存占位描述。每个物理来源只以首尾页和一条详情 smoke 验证，采样及异常保留 partial 与缺失下线保护；未验证来源不晋级 supported。

## 验收场景

1. 台账列出全部五家公司，区分待调研、协议验证、已实现、supported。（SWT-001, SWT-005）
2. 快手与哔哩哔哩有可复核的首页、末页、详情证据，或明确的失败证据；失败不伪装为支持。（SWT-002, SWT-003, SWT-004）
3. 新实现通过离线 Schema、分页异常和归一化测试；在线测试默认跳过且可按来源选择。（SWT-005）
4. 无适配器的逻辑渠道保持零物理来源，新增公司不改变旧来源身份。（SWT-006）
5. 滴滴暂停岗位不成为 active，详情失败不创建占位岗位；partial 不增加既有岗位缺失次数。实验来源默认关闭。（SWT-013, SWT-014, SWT-015, SWT-016）
6. 携程社招、日常实习和应届校招独立通过首尾页及详情 smoke，按 category/kind 分类；不依赖标题猜测、不使用登录会话，中文语言偏好与地域字段一致，partial 同步不增加旧岗位缺失次数。（SWT-018）
