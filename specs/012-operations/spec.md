# 012 配置、可观测性与运维规格

> 状态：Implemented
> 依赖：002, 003

## 目标

提供个人本地系统可安全运行、诊断、备份、恢复和清理所需的横切能力。

## 功能需求

- **OPS-001**：配置必须分两阶段解析：先以 CLI 参数 > 环境变量 > 默认值确定 dataRoot/configPath，再加载本地非敏感配置并按 CLI 参数 > 环境变量 > 配置文件 > 默认值合并其余字段；输出最终来源但不输出秘密值。
- **OPS-002**：启动必须校验 Node、目录读写、SQLite/FTS5、Schema、配置、适配器注册和可选模型配置。
- **OPS-003**：日志必须为结构化事件，包含 correlation/run/task/source/job/agent ID 中适用字段。
- **OPS-004**：日志必须字段级脱敏 API Key、Authorization、Cookie、联系方式、简历正文和来源私有敏感字段。
- **OPS-005**：doctor 必须区分 healthy、degraded、failed，并提供机器 JSON 和可操作建议。
- **OPS-006**：用户必须能查看来源、任务、数据库、文件和模型配置（不调用模型）的健康状态。
- **OPS-007**：备份必须可创建、列出、校验和恢复；恢复前 dry-run 并验证其他进程已停止，真正恢复显式确认并保留可回滚旧数据目录。
- **OPS-008**：用户必须能按策略清理孤立文件、过期原始记录、观察记录和 Agent 临时数据；默认 dry-run。孤立文件必须超过安全窗口后才可删除，默认 24 小时。
- **OPS-009**：简历等敏感删除必须列出影响并在确认后执行，产生不含敏感正文的审计事件。
- **OPS-010**：系统必须提供版本、Schema 版本、规则集和 Prompt 版本诊断，便于问题复现。
- **OPS-011**：CLI、Web 和 Worker 必须复用同一运行时配置加载器，并从显式工作区根目录读取 `.env` 与 `<dataRoot>/config.json`；进程启动目录不得改变模型配置结果。

- **OPS-012**：Worker 每 30 分钟检查 WAL，每天检查主库空闲页并 optimize；清理 1,000 条及以上记录后请求补查，休眠或重启后只补一次。WAL 达到 64 MiB 时先 PASSIVE，空闲仍超阈值才 TRUNCATE。主库空闲比例达到 25% 且空闲空间达到 64 MiB，并距上次成功 VACUUM 至少 7 天时才登记整理。
- **OPS-013**：整理须跨进程互斥，检查无其他运行中任务、无可领取任务和未来 60 秒内到期调度，并封闭新写入和领取的竞态；Web 写入返回可重试 503，读取保持可用。锁忙或条件不满足记录跳过原因，30 分钟后重查，不改变来源健康。
- **OPS-014**：VACUUM 前创建一致性备份并校验，磁盘须容纳备份及至多主库两倍临时空间并保留余量；成功后校验完整性与外键。只在新备份和整理校验成功后保留最近两份自动维护备份，不触碰手工备份。崩溃后可恢复维护标记，不遗留永久写入封锁。
- **OPS-015**：维护重操作在 Worker 管理的独立子进程执行；日常检查仅更新单条摘要，实际整理才生成任务审计。摘要包含大小、空闲比例、回收量、耗时、最近成功时间、跳过及失败原因，阈值未达到不能伪报空间收益。

## 质量与安全需求

- **OPS-Q01**：日志默认写 stderr 和滚动本地文件；文件权限尽可能限制为当前用户。
- **OPS-Q02**：任何诊断输出不得显示秘密值，即使启用 debug。
- **OPS-Q03**：备份恢复和清理在 Windows 中必须使用解析后的绝对目标，禁止对工作区或用户目录做递归删除。
- **OPS-Q04**：健康检查不得造成高成本模型调用或完整官网同步。

## 验收场景

1. dataRoot 只由 CLI/环境/默认值确定；同一普通配置在文件、环境和 CLI 提供不同值时采用 CLI 并显示来源，配置文件不能递归改变自身位置。（OPS-001）
2. 缺少可选模型 Key 时 doctor degraded，但同步/确定性匹配可启动。（OPS-002,005）
3. 构造含 Authorization、邮箱和简历正文的错误，日志中均被字段级替换。（OPS-004）
4. 篡改备份文件后 verify/restore 失败且当前数据未变化。（OPS-007）
5. cleanup 无 confirm 时只显示候选项和预计释放空间；刚写入但尚未登记、年龄不足安全窗口的文件不进入删除计划。（OPS-008）
6. 指向工作区根或用户目录的清理目标被拒绝。（OPS-Q03）
7. doctor 不发送官网完整请求或模型请求。（OPS-Q04）
8. 分别从工作区根目录和应用子目录启动 CLI、Web、Worker 时，三者解析到相同的模型 provider、base URL、model 和脱敏 API Key 来源。（OPS-001,011, OPS-Q02）
