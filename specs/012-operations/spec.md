# 012 配置、可观测性与运维规格

复审验收：不可重试 Agent 错误的诊断原因不得触发存储租约恢复；错误消息中的 JSON 凭据须脱敏，解析原文不得复制到外层摘要；模型失败收尾写账本失败时同时保留两条原因。（OPS-018）

> 状态：Implemented
> 依赖：002, 003

## 目标

提供个人本地系统可安全运行、诊断、备份、恢复和清理所需的横切能力。

## 功能需求

- **OPS-001**：运行参数统一存放在工作区根目录 `.env`，模板中的用户配置变量使用无项目前缀名称（如 `DATA_ROOT`、`LOG_LEVEL`），按 CLI 临时参数 > 进程环境 > `.env` > 内置默认值解析；输出最终来源但不输出秘密值。不再读取或创建运行配置 JSON，也不提供 `--config`。
- **OPS-002**：启动必须校验 Node、目录读写、SQLite/FTS5、Schema、配置、适配器注册和可选模型配置。
- **OPS-003**：日志必须为结构化事件，包含 correlation/run/task/source/job/agent ID 中适用字段。
- **OPS-004**：日志必须字段级脱敏 API Key、Authorization、Cookie、联系方式、简历正文和来源私有敏感字段。
- **OPS-005**：doctor 必须区分 healthy、degraded、failed，并提供机器 JSON 和可操作建议。
- **OPS-006**：用户必须能查看来源、任务、数据库、文件和模型配置（不调用模型）的健康状态。
- **OPS-007**：备份必须可创建、列出、校验和恢复；恢复前 dry-run 并验证其他进程已停止，真正恢复显式确认并保留可回滚旧数据目录。
- **OPS-008**：用户必须能按策略清理孤立文件、过期原始记录、观察记录和 Agent 临时数据；默认 dry-run。孤立文件必须超过安全窗口后才可删除，默认 24 小时。
- **OPS-009**：简历等敏感删除必须列出影响并在确认后执行，产生不含敏感正文的审计事件。
- **OPS-010**：系统必须提供版本、Schema 版本、规则集和 Prompt 版本诊断，便于问题复现。
- **OPS-011**：CLI、Web 和 Worker 必须复用同一运行时配置加载器，并从显式工作区根目录读取唯一运行配置文件 `.env`；进程启动目录不得改变模型配置结果。模型环境变量统一为 `BASE_URL`、`MODEL`、`API_KEY`，其中 `BASE_URL` 缺省为 OpenAI 官方地址且用于自动推断协议。

- **OPS-012**：Worker 每 30 分钟检查 WAL，每天检查主库空闲页并 optimize；清理 1,000 条及以上记录后请求补查，休眠或重启后只补一次。WAL 达到 64 MiB 时先 PASSIVE，空闲仍超阈值才 TRUNCATE。主库空闲比例达到 25% 且空闲空间达到 64 MiB，并距上次成功 VACUUM 至少 7 天时才登记整理。
- **OPS-013**：整理须跨进程互斥，检查无其他运行中任务、无可领取任务和未来 60 秒内到期调度，并封闭新写入和领取的竞态；Web 写入返回可重试 503，读取保持可用。锁忙或条件不满足记录跳过原因，30 分钟后重查，不改变来源健康。
- **OPS-014**：VACUUM 前创建一致性备份并校验，磁盘须容纳备份及至多主库两倍临时空间并保留余量；成功后校验完整性与外键。只在新备份和整理校验成功后保留最近两份自动维护备份，不触碰手工备份。崩溃后可恢复维护标记，不遗留永久写入封锁。
- **OPS-015**：维护重操作在 Worker 管理的独立子进程执行；日常检查仅更新单条摘要，实际整理才生成任务审计。摘要包含大小、空闲比例、回收量、耗时、最近成功时间、跳过及失败原因，阈值未达到不能伪报空间收益。
- **OPS-016**：日常 optimize、checkpoint 与阈值检查在存在运行中任务或已到期待领取任务时必须延期，不得与业务任务争抢 SQLite 写锁；检查与任务之间仍出现竞态时，Worker 必须把锁忙和维护写保护统一视为可恢复的基础设施繁忙。

- **OPS-017**：宿主是任务日志文件的唯一写入与轮转者；工作线程只提交有界脱敏事件。Web 请求进程使用独立文件，禁止多个写入者共享轮转。关闭时等待已接收事件排空；通道拥塞显式统计丢弃数。
- **OPS-018**：异常诊断保留有界且脱敏的 name/message/stack/code/cause；线程失败和启动失败可定位原始原因，公开任务摘要不暴露堆栈。序列化或磁盘故障不能改变业务结果，降级必须可见。
- **OPS-019**：文件级别、控制台级别和展示格式独立配置。默认文件 info、控制台 warn；交互终端可读文本，非交互 JSON。CLI stdout 只包含命令结果；debug 不绕过脱敏。重复基础设施告警按有界窗口聚合，周期指标采用 debug。
- **OPS-020**：自动附加宿主、进程、线程及任务/轮次上下文；Agent 和模型事件关联已有账本 ID。HTTP 异常响应的 correlationId 必须对应落盘事件，并记录适用请求方法与路径，不记录查询参数。
- **OPS-021**：提供只读日志查询与脱敏导出入口，可按任务、关联 ID 筛选按时间排列的事件；覆盖当前文件和轮转文件，并返回扫描/结果截断提示。导出不包含任务 payload、模型正文或凭据，不改变业务账本。

## 质量与安全需求

- **OPS-Q01**：日志按独立级别写 stderr 和滚动本地文件；文件权限尽可能限制为当前用户。
- **OPS-Q02**：任何诊断输出不得显示秘密值，即使启用 debug。
- **OPS-Q03**：备份恢复和清理在 Windows 中必须使用解析后的绝对目标，禁止对工作区或用户目录做递归删除。
- **OPS-Q04**：健康检查不得造成高成本模型调用或完整官网同步。

## 验收场景

1. 同一参数在 `.env`、进程环境和 CLI 提供不同值时采用 CLI 并显示来源；旧 `config.json` 不影响解析，init 不创建运行配置文件。（OPS-001）
2. 缺少可选模型 Key 时 doctor degraded，但同步/确定性匹配可启动。（OPS-002,005）
3. 构造含 Authorization、邮箱和简历正文的错误，日志中均被字段级替换。（OPS-004）
4. 篡改备份文件后 verify/restore 失败且当前数据未变化。（OPS-007）
5. cleanup 无 confirm 时只显示候选项和预计释放空间；刚写入但尚未登记、年龄不足安全窗口的文件不进入删除计划。（OPS-008）
6. 指向工作区根或用户目录的清理目标被拒绝。（OPS-Q03）
7. doctor 不发送官网完整请求或模型请求。（OPS-Q04）
8. 分别从工作区根目录和应用子目录启动 CLI、Web、Worker 时，三者从 `BASE_URL`、`MODEL`、`API_KEY` 解析到相同的 provider、base URL、model 和脱敏 API Key 来源；未配置 `BASE_URL` 时均得到 OpenAI 官方地址。（OPS-001,011, OPS-Q02）
9. 来源同步运行期间维护检查到期时，本轮检查不推进检查时钟且不执行 optimize；同步任务继续运行，空闲后的下一轮检查再执行。（OPS-016）

## 日志升级验收

错误诊断补充：包装错误必须保留原始 cause；线程存储分类不能替换诊断快照。AggregateError 保留有界子异常及省略数量，超大事件优先保留错误摘要、代码、关键堆栈与关联身份，再裁剪普通字段。（OPS-018）

10. 多个工作线程同时产生日志并触发轮转，只有宿主打开任务日志文件，所有保留事件可解析且关联正确。（OPS-017）
11. 线程内抛出带错误码、嵌套原因的异常，文件包含脱敏堆栈，公开响应只包含摘要；启动失败也有可检索事件。（OPS-018）
12. undefined response、循环引用、BigInt、抛错 getter 和超大输入不会让业务日志调用抛错；磁盘不可写时只发出受控降级通知。（OPS-018）
13. 默认控制台不输出成功任务流水及周期指标，文件仍记录正常执行；JSON 命令输出保持可解析。（OPS-019）
14. 两个并行任务的日志上下文不串线；Web 500/基础设施 503 的响应 ID 能查到对应事件；模型事件可用账本请求 ID 关联。（OPS-020）
15. CLI 查询覆盖轮转文件和 Web 独立文件，按 ID 过滤并支持 JSON 输出；恶意文件名/损坏行被安全处理，输出受限。（OPS-021）

工程类型验收必须覆盖生产源码、单元、集成、端到端及浏览器测试。编辑器中的测试文件与命令行使用相同的 NodeNext 模块解析和 development 导出条件；文件重命名后不得依赖旧构建产物或默认推断项目解析测试导入。保持严格模式，不以禁用检查或扩大强制断言绕过夹具与接口不一致的问题。
