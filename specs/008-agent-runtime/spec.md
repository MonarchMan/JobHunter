# 008 轻量 Agent 运行时规格

异常诊断约束：未知异常使用固定公开摘要，原始解析输入仅留在脱敏原因链；模型调用失败与账本收尾失败须同时保留，账本失败的不可重试分类优先。不可重试工具异常不得因 cause 中的存储锁忙被租约恢复重放。（OPS-018）

错误诊断：模型、工具和账本包装错误保留原始 cause；账本错误关联请求 ID 与写入阶段且不能触发网络重发。工具失败记录写入异常不能覆盖原始工具故障，内部诊断不包含工具参数或模型正文。（OPS-018）

当前实现不再提供 Agent、Prompt 手动版本。缓存和重试通过实际定义的内容哈希隔离，历史运行只保留结果快照；界面不展示业务版本号。此约定取代下文旧版本治理描述。

Agent 同一执行输入重试更新原记录，保留运行 ID，刷新状态、输出和错误；各次调用用量、分项成本累计，未知值仍未知。任务 ID 作为执行作用域，输入、模型及版本变化不得覆盖不同运行。工具调用历史保留并续编号；不合并或删除既有历史重复记录。

## 国内供应商缓存计费补全

国内官网未列报价的旧型号允许使用 cc-switch 明确收录的海外 USD 参考价兜底，仅限维护的型号白名单。现有国内报价（包括部分字段未知的报价）优先，不得以缺少用量或时长为由替换成海外价格。USD 参考价保留币种与来源版本；显式币种和单价配置优先，历史记录不回算。

本次只补齐国内按量 API，海外版本不扩展。国内官网价缺省使用 CNY，旧型号美元参考价白名单缺省 USD，显式币种设置优先；历史金额保持原币种。

- 内置报价同时描述普通输入、输出、缓存读取、缓存写入及写入时长；按供应商入口、原生币种和输入长度选择，不能固定汇率换算或把国内价套给海外入口。
- OpenAI 兼容字段与 Anthropic 缓存字段在边界归一化；显式零有效，缺失值保留 null。不同缓存写入时长分别计价，时长缺失且价格不同则不猜价。
- 显式配置可分别覆盖输入、输出、缓存读取、普通缓存写入和 1 小时缓存写入价格，其余分项按目录报价。
- 新运行保留价格版本与逐请求分项快照；旧记录不重新定价。不能确认地区、模型版本、服务档位或必要计价条件时保留未定价。

每次模型请求保存缓存命中、未命中、写入 Token 及分项成本；缺失字段为 null，显式 0 不参与回退。运行成本逐次累加；已上报用量的请求缺价时总成本未知，未发生模型调用的运行按 0 记录，未送达或被拒绝且未上报用量的失败请求按 0 计入运行合计，其逐请求明细仍为 null，不因此把运行显示为未定价。DeepSeek 官方入口按请求开始时间选择北京时间忙闲价，周末及已知中国节假日为闲时；未维护年份不猜测高峰日历。旧记录明细保持 null，历史合计不回算。

历史未定价运行可在核对官网价格与用量后进行定向成本回填；只更新计价字段，保留运行事实。缺少缓存明细时按未命中上界估算，必须在价格版本标记该假设，不声称为实际账单。

## 业务输出校验补充验收

- Agent 定义可提供纯业务输出校验器；新输出、缓存命中及并发胜者均通过校验才能返回。
- 业务校验与 JSON/Schema 校验共享最多一次纠正，沿用步数、用量和超时预算；不合格缓存标记失败且不再复用。

## 目标

提供最小、透明、可版本、可预算、可测试的模型与工具运行能力，支撑画像、职位理解和建议 Agent。

## 非目标

- 不实现通用多 Agent 图编排、长期记忆或自治任务规划。
- 不允许 Agent 直接写数据库或任意访问网络/文件。
- 不绑定单一模型供应商。

## 功能需求

- **AGT-001**：ModelClient 必须支持结构化请求、超时、AbortSignal、用量和标准错误分类。
- **AGT-002**：AgentDefinition 必须声明功能 key、当前 Prompt、输入输出 Schema、工具和预算，不声明 Agent/Prompt 手动版本。
- **AGT-014**：Agent 执行定义以内容哈希标识；删除手动版本、历史提示词和版本选择，历史运行保留快照，不作为当前定义的缓存复用。
- **AGT-015**：模型适配器必须按互斥的普通输入、缓存读取、缓存写入和输出 Token 分项计算原生币种微单位估算；非零用量缺少对应单价或必要时长时，总成本必须为 `null` 并展示为“未定价”，不得用 0 表示未知成本。
- **AGT-016**：默认价格必须按标准化模型 ID、供应商入口、币种及用量阶梯查内置价格目录；显式单价覆盖内置值，未知模型或未知计价条件不得使用猜测价格。
- **AGT-003**：普通调用不复用结果、不保存输出正文；可恢复后台步骤必须显式提供 taskId、stepKey、resourceKey，并结合定义、模型及输入身份定位结果。失败重试保留运行身份和累计用量，跨任务或主动重算不得复用。
- **AGT-004**：输出必须通过 Zod；失败时最多执行一次受限修复，仍失败则保存 failed。
- **AGT-005**：Runner 必须强制 timeout、maxSteps、输入/输出 Token 与估算成本上限。
- **AGT-006**：工具必须白名单注册、输入输出校验、默认只读并记录脱敏调用摘要。
- **AGT-007**：每次运行必须记录模型配置哈希、输入哈希、状态、耗时、Token、估算成本、货币/定价版本和错误分类。
- **AGT-008**：Prompt、Schema、工具或执行限制变化必须改变内容哈希，隔离旧缓存；不自动重算历史业务结果。
- **AGT-009**：模型限流/临时错误可交给 Worker 重试；无效配置、预算超限和持续无效输出不得自动循环。
- **AGT-010**：每个业务 Agent 启用前必须有脱敏黄金集和可重复评测报告。
- **AGT-011**：首个线上 Provider 必须支持 OpenAI 兼容的 Chat Completions JSON 接口；模型配置统一从 `.env` 的 `BASE_URL`、`API_KEY`、`MODEL` 读取，不再接受 `JOBHUNTER_MODEL_*` 或显式 Provider。`BASE_URL` 缺省为 `https://api.openai.com/v1`。
- **AGT-012**：线上 Provider 必须支持 Anthropic Messages JSON 接口；配置边界根据 `BASE_URL` 自动选择协议，主机名标签或路径段含独立 `anthropic` 时选择 Anthropic，否则选择 OpenAI 兼容协议。原生请求、工具调用、结构化输出、用量与错误必须转换为项目自有 DTO，且不得暴露 API Key。
- **AGT-013**：DeepSeek Chat Completions 必须优先使用其支持的 `json_object` 模式；模型返回代码围栏 JSON、空正文或非 JSON 正文时，适配器必须先执行有界规范化，仍无法解析则交给 Runner 的唯一一次结构化修复，禁止在适配器与 Runner 之间形成无限重试。
- **AGT-017**：OpenAI 兼容与 Anthropic 适配器必须按客户端实例记忆协商成功的结构化输出格式；首次 400 回退探测只发生一次，后续请求直接使用已协商格式，不逐请求重复 400 试探。网关响应格式能力变化时按新客户端实例重新协商。
- **AGT-018**：网络类失败的 `temporary` 错误摘要必须附带脱敏原因代码（如 `ECONNREFUSED`），只保留字母数字与点划线且限长，不得包含地址、URL、请求或响应正文。

## 质量与安全需求

- **AGT-Q01**：Agent Runner 不依赖职位或简历具体业务类型。
- **AGT-Q02**：日志不得包含 API Key、完整 Prompt 输入、完整简历或工具敏感输出。
- **AGT-Q03**：FakeModelClient 必须支持普通测试完全离线运行。
- **AGT-Q04**：模型不可用不影响同步、查询和确定性匹配。

## 验收场景

1. 同一后台任务步骤、资源与输入恢复时复用成功结果；普通调用或不同任务再次调用模型。（AGT-003）
2. Prompt 或模型配置变化导致新 cacheKey。（AGT-003,008）
3. 同一步骤首次失败后重试保留运行 ID、历史用量和诊断；合法新分派可恢复旧轮次遗留记录。（AGT-003）
4. 首次输出 Schema 无效、修复成功时保存修复后的有效结果且只修复一次。（AGT-004）
5. 工具循环超过 maxSteps 被终止为 budget_exceeded。（AGT-005）
6. 工具请求未注册能力时被拒绝，不执行副作用。（AGT-006）
7. 模型返回 rate limit，运行失败分类正确且 Worker 按策略重试。（AGT-009）
8. 日志敏感扫描未发现输入正文或密钥。（AGT-Q02）
9. 显式在线烟测可以使用本地 `.env` 发起最小结构化请求；普通测试和 CI 不读取真实密钥、不产生付费调用。（AGT-001,011, AGT-Q02）
10. `BASE_URL` 指向 Anthropic 官方地址或含独立 `anthropic` 标识的网关时，Worker 与 CLI 自动使用 Messages API 完成结构化输出和工具调用；其他地址继续使用 OpenAI 兼容协议。（AGT-001,012, AGT-Q02, AGT-Q04）
11. DeepSeek 首次请求直接使用 `json_object`；代码围栏 JSON 可在本地规范化，普通文本或空正文触发一次无工具修复，第二次仍非法时保存 `invalid_output`。（AGT-004,009,013）
12. 不支持 `json_schema` 的通用网关首次请求收到 400 后回退 `json_object` 成功；同一客户端的第二次请求直接携带 `json_object`，不再发送 `json_schema` 400 试探。（AGT-017）
13. 模型网关连接被拒绝时运行失败分类为 `temporary` 且摘要含 `ECONNREFUSED` 原因代码，日志不出现网关地址。（AGT-018, AGT-Q02）

## 未解决问题

无。首个模型供应商由运行配置选择；开发与 CI 使用 FakeModelClient。

## 执行恢复修正

普通 run 只记录诊断，不复用成功输出或保存正文。删除 resultPolicy、cache、persistOutput 和 retryKey 配置；runStep 显式提供 taskId/stepKey/resourceKey，按执行身份和输入定义恢复结果。创建运行时原子保存执行关联。输入或定义变更必须创建新运行；任务成功、取消或删除时清除恢复正文，失败任务保留恢复所需结果。

结构纠正与调用明细：一次 Agent 运行可包含首次请求及最多一次输出纠正，协议协商也可产生多次实际 HTTP 请求。每次实际请求独立记账，同一步骤恢复不得新增虚假请求。额外字段错误的纠正提示必须给出字段层级和有界的额外字段名，不记录输出值；不通过忽略额外字段来放宽正式输出契约。

逐请求失败说明：HTTP 成功但 Agent 输出校验失败时，在下一次纠正请求发出前，为对应请求记录脱敏的失败原因。格式或流式协议协商、传输及供应商错误也应保留明确原因。单次运行成功不得覆盖此前失败请求的原因，恢复及记账幂等更新不能抹除诊断；不保存原始输出正文。
流式请求中断时，已接收并校验的用量必须保留在原请求 ID 下；允许仅有输入、缓存或输出等部分分项。缺失分项保持未知，不能因取消、断流或后续解析失败而清空已知用量，也不能将 HTTP 200 视为成功完成。不恢复历史未接收或未保存的数据。
