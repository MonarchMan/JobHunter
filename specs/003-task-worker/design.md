# 003 中央任务服务设计

> 状态：In Progress

> 中央任务服务、任务存储合并和维护联动已实现；真实数据迁移按整体三阶段计划另行执行。见 [ADR-0062](../../docs/adr/0062-central-task-scheduler.md)。

## 运行模型

每个规范化本地数据目录只运行一个中央任务服务，与 CLI/Web 生命周期独立。CLI 和 Web 使用 common 的统一任务应用端口提交、查询、取消、重试及等待，并由 TaskClient 确认中央服务可用，不维护自己的调度与领取循环。持久化入队可参与业务短事务；IPC 同时提供简单任务命令，但不跨进程拆开业务记录与任务发布的原子提交。中央调度者管理多个执行进程，执行进程只接受分派。

common 提供客户端、服务发现、启动协调、本机 IPC、调度、执行进程管理和提交门控端口；业务模块提供处理器与周期配置查询契约。apps 组合根显式注入实现，通过内部启动模式运行服务和执行宿主，不增加 apps/worker 包或公开 worker 命令，common 不导入业务实现。

客户端首次连接时竞争跨进程启动锁，持锁后重新探测再启动。服务全生命周期保持排他所有权；PID 文件或心跳超时不能单独证明旧服务已退出。Unix socket、Windows named pipe 和锁通过平台适配器实现，IPC 限制为本机用户访问并校验消息。协议或配置不兼容时返回明确诊断，不另启第二套服务。

CLI 退出、停止等待或 Web 重启只关闭自身连接，不终止后台任务。显式服务关闭才停止分派、通知执行进程、等待安全点并释放资源。迁移、恢复和维护须协调中央服务及执行进程，禁止旧进程继续写入。连接层检测到待应用迁移时要求持有中央服务锁：普通入口须先显式停止服务，服务自身仅在持锁装配阶段允许迁移。同版本查询连接不受此门控影响。

## 分派、执行与恢复

中央调度者在短事务内选择到期 pending 任务、设置 running、生成唯一分派凭证并递增累计尝试次数；网络与模型调用在事务外进行。执行进程报告心跳和检查点，由中央调度者判断超时、撤销旧凭证、通知取消，再按预算重新分派。

业务仓储必须在结果提交事务内验证当前任务、服务代次、分派凭证、running 与取消状态，不能先在内存检查再另开事务写入，也不能只保护 tasks 更新。业务结果和检查点可在同一 SQLite 事务提交时必须原子提交。撤销先发生则拒绝旧结果；结果提交先发生则后续取消不得把已发布结果伪装成 cancelled。

调度者重启取得排他所有权后撤销旧分派，从已提交检查点恢复。执行进程控制连接断开后停止工作；迟到返回仍须被门控拒绝。业务幂等防止重复事实，分派校验防止旧执行者覆盖结果，外部请求不承诺恰好一次。

执行权持久化的精确列结构在实现协议时确定，不能先删除现有租约保护。SQLite 承担状态持久化与原子条件更新，调度和超时判断由系统逻辑负责。

按类型独立队列与并发槽位，中央服务统一跨进程网络许可与来源节流。会话型平台任务路由到持有会话的执行进程，进程丢失后要求重连，不将凭据写入任务。数据库锁忙异步退避，不伪报续期或提交成功。

## 存储与诊断

来源发现扫描作为 `source.scan` 内部阶段任务存入 tasks，parent_task_id 指向来源同步主任务；它由已领取的主任务同步驱动，不再独立领取。每次全量重扫创建新扫描任务 ID，评分恢复复用已有扫描 ID。阶段任务的 private_state 保存来源、触发方式与成功游标，public_state 保存覆盖、统计与诊断证据，不保留不参与恢复的版本和配置哈希。职位观察及临时已见集合外键改指 tasks，历史扫描保留 ID；可准确关联的历史主任务保留父关系，其余作为历史独立阶段任务保留。主任务撤销或终结时原子取消未完成阶段，防止悬挂扫描；通用任务列表默认展示根任务，来源诊断聚合阶段详情。

任务状态列分工：private_state 保存经任务处理器 Schema 校验的执行输入；public_state 保存已脱敏的检查点、进度和最终结果，允许执行期间更新。迁移沿用原输入与结果的 JSON 结构，避免同时保存旧字段和新字段两份数据。查询、关联和业务检查点写入统一使用新列；周期设置的 payload_json 是周期配置内部属性，不属于 tasks。公开诊断必须显式投影，不返回 private_state。

tasks 使用经过类型校验的 public_state/private_state 和必要索引列，合并 sync_runs；周期配置回归业务所有者，移除 schedules 专表。保留累计尝试次数、操作令牌幂等、并发键、扫描身份与覆盖判断。全量重扫更换扫描身份，评分重试复用采集结果。诊断只投影脱敏字段，详情批次保持单次聚合分页与批量读取。真实数据按整体三阶段计划在实现完成后统一备份与迁移。

## 验收

以 [中央调度架构](../../docs/arch/worker-and-concurrency.md) 为统一算法与验收依据。使用假时钟验证退避、周期和超时，真实 SQLite 验证门控事务，多进程测试验证并发冷启动、服务重启、旧分派拒绝及全局限流，CLI/Web 端到端验证共享服务和入口退出独立性。新增清单完成前不得标为 Implemented。

## 周期设置持久化

0054 迁移将周期执行配置和 next_run_at/last_enqueued_at 放入 application_settings 的 task.periodic 命名空间，移除 schedules 表与 tasks.schedule_id。来源的自动化与覆盖配置仍由 recruitment 拥有，运行投影由通用周期服务维护；同一设置行上的 CAS 与任务入队在一个短事务内提交，调度幂等键保持不变。到期扫描使用 JSON 表达式部分索引，不建立旧表兼容视图。
