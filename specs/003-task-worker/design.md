# 单宿主、主线程调度与有界动态线程池设计方案

> 状态：In Progress
> 决策已批准，本次运行模型已实现；验证范围及环境限制见 tasks.md。
> 日期：2026-11-06。
> 已批准替代 ADR-0062/0064 的生命周期和执行模型。

## 目录组织

任务运行时按职责组织为 `contracts/`（模型、处理器和执行上下文）、`scheduling/`（队列用例、周期、重试与调度引擎）、`execution/`（线程池及线程协议）、`host/`（宿主装配与本机命令桥）、`concurrency/`（网络许可与来源限流）和 `maintenance/`（清理及 SQLite 维护）。根目录只保留公开聚合入口，包导出名称保持稳定。相对导入、线程和维护入口 URL、源码及编译产物导出必须同步迁移。

同轮目录复核将匹配模块根目录的评分规则和模型 Agent 分别归入 `scoring/`、`agents/`，招聘平台连接器按平台及共享浏览器能力归组；仓储、公开契约和端口等职责单一的目录保留原结构。此次仅调整组织及引用，不改变依赖方向、数据所有权或执行机制。

## 线程异常与数据库竞争

线程失败消息仅保留符合 SQLite 驱动格式的错误代码或固定维护标识；宿主重建固定摘要的原因对象，继续使用既有锁忙检测和租约恢复逻辑，不序列化任意异常正文或堆栈。约束等非暂态数据库错误仍按永久错误处理，不能一律重试。招聘用例的同步短事务在读取前使用 `BEGIN IMMEDIATE` 预留写入权，避免读快照建立后被宿主调度连接写入而无法升级为写事务；外部网络、浏览器和模型调用仍在事务外。

## 1. 决策摘要

每个规范化数据目录只允许一个运行宿主，Web 与 CLI 互斥。宿主主线程拥有唯一调度器；所有业务任务 Handler 由有界动态 Worker 线程池执行；每个工作线程通过 async/await 并发执行多个任务。

取消独立常驻任务服务、任务执行进程池和后台自动拉起。宿主停止后不再执行任务；下次启动根据持久队列和检查点恢复。外部浏览器及维护工具仍可使用受生命周期管理的子进程。

线程数、活动任务数、任务类型并发数和网络请求数是四个不同预算，不相互替代。线程扩容只增加执行容量，不放大全局网络许可或业务并发约束。

## 2. 改造前基线与复用机制

- service-entry.ts 通过 detached fork、disconnect 和 unref 启动独立服务，入口退出不等于服务退出。
- 原 ProcessTaskExecutor 按逻辑业务组固定执行进程，进程内保存浏览会话，父进程统一发放网络许可。
- WorkerEngine 已经拥有领取、周期扫描、租约、取消和重试机制；保留这些机制，替换执行适配器并增加领取前容量控制。
- runtime.ts 的 executionOnly 模式可作为工作线程装配的基础，但必须禁止工作线程调度、恢复旧分派或运行迁移。
- Web 外层启动器启动 Next 子进程，页面容器又持有独立数据库连接。不能让 Next 模块热更新重复创建调度器。
- 数据目录排他锁已通过独立 SQLite 数据库的 EXCLUSIVE 事务实现，可改为宿主所有权；不以 PID、文件存在或心跳过期代替锁。

## 3. 宿主与入口

### 3.1 所有权

宿主状态为 starting → running → stopping → stopped，初始化失败进入 failed 并执行逆序清理。只有 running 状态允许接受任务写操作。

1、读取配置并规范化数据目录，获取排他锁。
2、完成存储初始化和必要迁移；仅锁持有者有迁移和恢复权限。
3、创建主线程任务应用、线程池及业务模块公开查询能力。
4、撤销上个宿主的遗留执行权，按既有检查点恢复规则处理任务。
5、等待最小线程数 ready，再启动领取及入口服务。
6、运行期间持续持锁，所有写入者退出后才释放。

竞争失败的第二个宿主直接报错，不自动连接、停止或替换已有宿主。不同数据目录互不影响。帮助和版本命令无需持锁；普通数据命令也必须遵守互斥约定。

### 3.2 Web 进程安排

采用现有外层 Web 启动器作为生命周期宿主：其主线程持锁并运行调度器和 Worker 池；Next 子进程只提供页面及协议入口，不再拥有或自动启动第二个运行时。该安排避免依赖 Next 开发热更新的模块单例实现核心调度生命周期。

Next 与宿主之间保留最小本机命令桥，用于任务提交、查询、取消、重试和启动就绪检查。命令桥没有独立生命周期，不自动启动服务，不允许其他普通 CLI 复用宿主。业务数据和任务发布需要原子提交的路径仍在同一数据库短事务中完成，不能先 RPC 写业务再 RPC 入队。

命令桥仅由宿主创建的 Next 子进程使用，采用每次启动生成的随机凭证、协议版本及宿主代次校验。不得把凭证暴露给浏览器或日志。管道权限继续限制为当前本机用户。

Next 异常退出触发整个宿主停止。启动器强制退出后，调度器和线程自然结束；Next 不拥有执行任务能力。Next 由无业务逻辑的生命周期包装器启动；包装器持有宿主 IPC，断开时回收其创建的 Next 进程树。Windows 使用 taskkill /T，Unix 使用受控进程组；不给 Next CLI 自身添加 IPC，避免触发框架内部 Worker 握手。浏览器和维护子进程按资源所有权回收，不终止用户自行运行的浏览器。

开发热更新只更新页面模块；调度器、任务处理器或配置变更通过完整宿主重启应用。生产和开发使用同一所有权模型。

### 3.3 CLI 模式

CLI 主线程持锁并直接运行同一宿主能力，不经过本机命令桥。普通查询/配置命令不启动任务消费和周期调度；执行型命令只运行本次目标工作流，默认等待其完成后退出。Web 模式消费完整可执行队列并推进周期调度。

取消原有“提交后退出并在后台继续运行”的语义。涉及 --wait 或后台提交选项的命令必须逐项更新帮助和行为，不能静默保留旧语义。

目标工作流必须有明确的根任务和子任务关联。现有 parent_task_id 可准确表达的链路优先复用；缺少关联的链路先补齐领域编排契约，不凭任务类型或创建时间猜测归属。父任务终结但仍有必要子任务运行时，命令继续等待。定时等待中的可重试目标工作流仍属于未完成工作，用户可以 Ctrl+C 中断并保留恢复资格。

## 4. 主线程与工作线程职责

| 执行位置    | 职责                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------- |
| 主线程      | 独占所有权、领取、容量预留、周期触发、租约协调、恢复、取消、全局网络许可、来源节流、诊断 |
| 工作线程    | 校验分派、执行 Handler、业务短事务、检查点、外部调用、会话资源及取消收敛                 |
| apps 组合根 | 显式注入四模块实现及线程入口，不让 common 导入业务实现                                   |

工作线程不扫描队列、不运行周期、不执行迁移、不回收旧宿主任务。每线程独立创建数据库连接和必要模块资源，不共享连接、仓储对象、模型客户端或浏览器实例。业务 Schema、仓储和 Prompt 仍归业务模块。

主线程可为任务元数据、类型注册和周期配置装配必要能力，但不调用业务 Handler，也不初始化工作线程专属浏览器会话。

## 5. 动态线程池

### 5.1 配置初值

| 参数                | 初值   | 含义                               |
| ------------------- | ------ | ---------------------------------- |
| minThreads          | 1      | 最低就绪线程数                     |
| maxThreads          | 4      | 含启动中、运行中、排空中线程的上限 |
| maxTasksPerThread   | 4      | 每线程活动任务容量，异步等待也计入 |
| maxActiveTasks      | 8      | 全局活动任务硬上限                 |
| scaleUpCooldownMs   | 5000   | 两次扩容的最小间隔                 |
| idleTimeoutMs       | 120000 | 空闲线程回收等待时间               |
| startupTimeoutMs    | 90000  | 线程初始化期限                     |
| shutdownGraceMs     | 10000  | 任务协作关闭宽限期                 |
| heartbeatIntervalMs | 5000   | 工作线程存活报告周期               |
| heartbeatTimeoutMs  | 45000  | 工作线程无响应判定期限             |

这些是待验证的默认值，不作为吞吐承诺。校验正整数、min ≤ max、全局与单线程容量关系以及时间参数范围；min=max 时自然成为固定池。保持现有任务类型和网络配置，不重复引入含义相同的字段。

### 5.2 线程状态与扩容

线程状态：starting、ready、draining、terminating、exited。只有完成协议和配置握手、业务能力装配后才进入 ready；启动中的线程不提供执行容量。

1、存在满足 availableAt、类型预算及业务互斥条件的任务时检查执行容量。
2、有 ready 线程容量时优先分配，不因队列总长度盲目扩容。
3、持续存在容量不足的可运行积压，且低于 maxThreads、满足冷却时间时逐个创建线程。
4、网络许可长期饱和、来源节流或数据库锁争用时抑制单纯由积压触发的扩容；压力原因记录为诊断字段。
5、事件循环持续繁忙且存在可迁移的新任务时，可扩容以承接后续任务，不迁移在途任务。

度量使用滚动窗口和滞回，线程上报活动数量、事件循环利用率/延迟及会话固定数量；主线程掌握网络和调度等待指标。启动失败采用有上限退避；连续失败进入明确降级状态，不无限创建线程。低于最低健康线程数且无法恢复时宿主报错并停止，不伪装为可用。

### 5.3 缩容

只有空闲超过 idleTimeout、没有活动任务、没有会话固定和清理工作，且回收后不低于 minThreads 的线程可进入 draining。排空后不再接收任务，执行关闭握手并退出。新负载由其他线程或后续扩容承担；不频繁撤销缩容操作。

达到上限但全部线程被会话固定时，新会话可按容量分配到已有线程；资源不足则明确返回繁忙，不创建超限线程、不偷偷驱逐有效会话。

## 6. 领取、预留与分配

池提供可取消的容量预留，而非在 execute 内无限排队。预留同时占用全局、类型及目标线程预算。

1、主线程公平轮转检查任务类型，并识别必要的会话归属。
2、获得短生命周期容量预留后，在短事务中条件领取任务、生成唯一分派身份。
3、无任务、领取竞争失败、数据库锁忙或停止时立即释放预留。
4、向已就绪线程发送已校验分派；发送失败按分派失败协议处理，释放预算。
5、结果成功、失败或执行权撤销后释放预算；同一预留必须恰好释放一次。

对于必须先查看 payload 才能识别会话的任务，使用只读候选投影得到路由提示，领取时重新验证任务条件；不能先领取再无限等待对应线程。工作线程不拥有待执行持久队列的副本。

任务类型公平轮转结合全局预算；单一积压类型不能饿死其他类型。数据库中现有 concurrency_key 唯一约束继续承担最终业务互斥。同步驱动内部阶段不再重复独立领取；异步父子编排必须在等待子任务时释放执行槽位并保存检查点，避免父任务耗尽容量造成死锁。

## 7. 会话路由

主线程维护不含凭据的 session → workerId + workerGeneration 映射。连接创建、浏览、断开等同会话任务固定在线程内执行，会话内串行约束独立于线程总容量。

路由键从业务模块公开契约取得，common 不硬编码 payload 字段或平台业务。不能沿用原先“整个 recruitment 固定一个执行进程”的粗粒度映射，否则动态池无法有效分配招聘任务。

主线程通过业务 Handler 的公开 affinity 及结果释放契约维护会话固定；有效会话固定线程，禁止空闲缩容。凭据和私有游标只在工作线程内存中。线程退出时映射失效，后续请求要求重新连接，不能重放旧会话任务为新连接。断开操作完成后释放固定计数。

## 8. 跨线程消息和网络控制

消息包括 ready、execute、result、error、abort、alive、acquire、permit、release、shutdown 和 closed。进度/检查点通过受门控的仓储写入，主线程业务注册表提供会话固定及释放契约。具体 Schema 由 common 协议边界定义，业务 payload 仍由所属模块验证。

本机桥校验协议版本及每次宿主启动随机凭证。内部线程使用同一份协议 Schema，由独立 Worker 对象隔离线程代次；任务消息携带 taskId 和分派身份，请求/响应带关联 ID。校验消息来源和关联所有权，拒绝其他线程释放许可或提交结果。限制数据体积、错误摘要和公开进度字段；大正文保存在业务表/文件，不经消息重复传输。

网络许可和来源 Token Bucket 由主线程统一管理。工作线程申请许可，获准后调用外部服务，finally 释放。取消排队移除等待项；线程退出回收其全部许可，重复释放幂等。来源节流在网络许可之前，不占用全局许可等待令牌。不能每线程单独创建同额度限流器。

## 9. 提交、取消、故障与恢复

### 9.1 提交保护

业务结果仍由工作线程仓储在结果事务内验证任务状态、取消状态及有效分派身份。检查点与业务结果能同事务时原子提交。主线程不得收到 result 消息后绕过门控重新覆盖业务事实。

事务提交先于取消则完成获胜；取消或撤销先发生则迟到结果拒绝。保留当前幂等、累计尝试次数、重试日志和租约设计，不因单进程执行而删掉可靠性保护。

### 9.2 用户取消

先持久化取消/撤销条件，再向所属线程发送 abort；线程关联 AbortController 并向网络、模型、浏览器及分批循环传递。正常返回确认后释放容量。超时不响应时撤销执行权并终止整个工作线程；该线程其他任务按中断恢复，会话全部失效。第一版不承诺只硬终止线程中的某一个 Promise。

### 9.3 线程故障

1、冻结失效线程的分配和结果接收，撤销其活动分派。
2、终止并等待线程退出，回收许可、预留和会话映射。
3、交由任务恢复策略处理可恢复工作，不将用户已取消任务复活。
4、按退避策略补充线程；替代线程拥有新代次。

无法确认退出时宿主 fail-stop，不允许旧线程仍可能写入时重新执行同一任务。心跳判定考虑主线程自身事件循环延迟，避免宿主暂停后一次性误杀所有线程。

### 9.4 宿主停止

1、进入 stopping，停止接受任务写操作、周期触发、扩容及新领取。
2、取消所有执行及许可等待，等待宽限期内安全点。
3、撤销剩余执行权，终止未收敛工作线程并等待退出。
4、关闭浏览器、维护子进程和 Next 入口，验证资源回收。
5、关闭业务资源、主线程数据库和日志，最后释放独占锁。

关闭 Promise 必须幂等，多次信号等待同一个完成结果。不能将 Promise.race 超时当作执行已经结束。普通退出保留恢复资格，用户取消则保持 cancelled。宿主强杀不执行清理代码，下次获取锁后先撤销遗留分派再恢复；进程树回收负责外部子进程。

宿主重启中断不会自动重置 attemptCount 或无限扩展 maxAttempts。本次沿用既有尝试预算，明确记录 shutdown/worker_lost 中断原因；若需“中断不消耗失败预算”，另行设计独立失败计数，不能偷偷修改统计含义。

## 10. 周期、存储与旧版本切换

Web 模式拥有周期循环；应用关闭期间不触发周期任务，重启只补最近一次，保留 occurrence 幂等和来源互斥。CLI 模式仍运行必要租约恢复/心跳，但关闭周期发布和非目标任务消费。

优先不改任务表结构，复用已有分派、检查点及父子关联。线程各持独立 SQLite 连接，写事务短小，锁忙异步退避。SQLite 维护保留专用协调及短生命周期受控执行方式，维护时暂停新写入并等待既有写操作收敛。

新版启动检测到旧独立服务仍持锁时明确拒绝启动，提示先停止旧服务；不自动杀未知 PID，不并行运行新旧调度器。移除后台服务的公开 start/stop/restart 语义，文档说明新宿主停止方式。旧管理能力是否保留为一次性升级工具在命令清单中明确，不作为长期运行分支。

不修改用户真实任务和运行数据，不自动运行生产迁移或触发付费模型。若实现发现必须改重要数据，先给出具体变更、备份及恢复方案并征求意见。

工程检查包括受影响文件格式、类型、lint、依赖边界、文档检查及相关单元/集成/端到端测试。新增失败或实现变化后补充针对性验证。

## 13. 已批准的运行约定

1、同一数据目录 Web/CLI 互斥，不自动附着已有宿主。
2、Web 外层启动器主线程拥有调度器，Next 保留受限、随宿主退出的命令桥。
3、所有业务 Handler 在线程池执行，线程内有界异步并发，默认线程数 1～4。
4、动态扩缩容受负载、网络瓶颈和会话固定约束，不保证繁忙时必然增加线程。
5、CLI 执行型命令等待目标工作流，不保留后台继续运行模式。
6、取消超时可终止整个工作线程，其他任务恢复且该线程会话失效。
7、按检查点与既有预算恢复，不承诺外部请求恰好一次，也不承诺本地退出能撤回已发送的远端请求。
