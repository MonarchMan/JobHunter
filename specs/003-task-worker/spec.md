# 003 持久化任务与 Worker 规格

> 状态：Implemented
> 依赖：001, 002

## 目标

可靠执行定时同步、模型调用和单职位匹配，使任务在失败或进程重启后可重试、恢复和审计。

## 功能需求

- **WRK-001**：入队必须校验 task type 与 payload，并使用唯一幂等键。
- **WRK-002**：领取必须原子地设置运行状态、租约、Worker ID 和尝试次数。
- **WRK-003**：任何时刻同一任务最多被一个未过期租约持有。
- **WRK-004**：长任务必须心跳续租；租约过期任务必须恢复或在耗尽次数后失败。
- **WRK-005**：错误必须按可重试、永久、配置、解析变化和取消分类。
- **WRK-006**：重试必须应用上限、指数退避、抖动和可选 Retry-After。
- **WRK-007**：计划必须按时区解释，并在重启后只补最近一次错过的 occurrence。
- **WRK-008**：同一来源不得存在并行同步运行。
- **WRK-009**：关闭时必须停止领取，传递 AbortSignal，并依靠租约恢复不确定任务。
- **WRK-010**：用户必须能查询、重试失败任务和取消 pending/running 任务；成功任务不可取消。running 取消为协作式：若声明了提交门控的 Handler 已在最终事务中确认“任务仍 running 且未请求取消”并发布业务结果，则之后到达的取消视为过晚，Task 必须完成为 succeeded，不能把已可见结果伪装成 cancelled。
- **WRK-011**：每个已注册 task type 必须拥有独立领取循环和逻辑队列；一个类型的积压、慢任务或失败不得阻塞其他类型领取。
- **WRK-012**：每个 task type 的消费并发度必须可独立配置；未显式配置的类型使用并发度 1，配置不得绕过 `concurrency_key` 互斥约束。
- **WRK-013**：`maxConcurrentNetworkTasks` 必须作为 Worker 进程内共享的异步信号量，统一限制来源 HTTP、浏览器采集和模型调用的在途网络操作；等待许可不得阻塞线程，取消后必须及时退出等待队列。
- **WRK-014**：生产 Worker 必须按来源声明的 `requestsPerMinute` 和 `burst` 执行独立 Token Bucket 节流；节流等待不得占用全局网络许可，取消后必须退出等待队列。
- **WRK-015**：生产 Worker 必须周期记录全局网络在途数、排队数和事件循环 P95 延迟，以便在提升并发前识别背压与同步阻塞。
- **WRK-016**：来源同步任务详情必须展示所属公司、招聘渠道、物理来源、触发方式以及对应同步运行的覆盖状态和职位统计；不得暴露原始任务 payload。
- **WRK-017**：诊断任务列表必须将同一来源同步运行派生的 `source.job-detail` 明细任务聚合为一个职位详情同步批次，展示公司和总数、等待、运行、成功、失败、取消统计；明细任务仍须保持独立执行、重试和审计。

## 质量需求

- **WRK-Q01**：空队列时不得高频忙轮询。
- **WRK-Q02**：任务与错误日志不得包含 payload 中的敏感正文。
- **WRK-Q03**：Handler 必须通过注册表接入，Worker 核心不依赖具体业务模块。

## 验收场景

1. 两个并发领取循环针对一条任务，仅一个获得租约。（WRK-002,003）
2. Worker 在 Handler 中退出，租约到期后另一 Worker 领取且幂等完成。（WRK-004）
3. rate_limited 携带 Retry-After 时按其安排，不早于指定时间重试。（WRK-005,006）
4. 同一 occurrence 重复调度只生成一条任务。（WRK-007）
5. 同一来源已有同步任务时，计划任务不重复入队。（WRK-008）
6. SIGTERM 后不再领取任务，在途 Handler 收到取消信号。（WRK-009）
7. permanent 错误不自动重试。（WRK-005）
8. 同时存在多个 task type 的 pending 任务时，各类型均可被独立领取；一个类型的 Handler 阻塞时，其他类型仍可开始执行。（WRK-011）
9. 将某一 task type 的消费并发度配置为 2 时，该类型可同时执行两个无互斥冲突的任务，其他未配置类型仍保持单消费者。（WRK-012）
10. HTTP、浏览器和模型操作竞争同一个容量为 2 的网络信号量时，任意时刻最多两个操作在途；排队操作取消后不再占用队列或许可。（WRK-013）
11. 同一来源突发请求超过 burst 时按声明速率依次放行，不同来源互不阻塞；取消的排队请求不会被执行。（WRK-014）
12. Worker 运行时日志可观察网络在途/排队数量及事件循环 P95 延迟，日志不包含请求内容。（WRK-015, WRK-Q02）
13. 打开来源同步任务详情时，可查看公司和本次发现、新增、更新、未变化、过滤的职位数量；普通任务仍不展示 payload。（WRK-016, WRK-Q02）
14. 美团一次列表同步派生 100 个职位详情任务时，任务列表只出现一条“美团职位详情同步”，批次统计总数为 100；单个详情失败仍可独立重试。（WRK-017）
