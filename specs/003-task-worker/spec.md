# 003 中央调度与持久化任务规格

> 状态：In Progress

> 运行模型已采用 [ADR-0065](../../docs/adr/0065-single-host-dynamic-thread-pool.md)，验证状态见 tasks.md。

手动重试按 ADR-0045 复用原任务 ID；先在同一事务记录失败分类、脱敏摘要和执行时间，再重新入队。相同令牌幂等，非失败任务不能以新令牌重试；保留业务关联和历史任务链。手动重试不得清零累计尝试次数；下一次领取继续加一，并将尝试上限设置为当前累计次数加 Handler 本轮预算，令牌重放不得重复增加预算。不回填历史已重置的次数。（WRK-010）

WRK-009 补充验收：可恢复的数据库锁冲突不得终止领取或调度循环；等待需异步退避，心跳锁忙不得误报执行权已延长。结果提交锁忙时保留检查点恢复路径，不将基础设施繁忙记为业务永久失败。退出信号必须取消周期维护并等待其收敛。

工作线程返回失败时必须保留可校验的数据库锁忙及维护拒写标识，使宿主仍能沿用租约恢复规则；不得仅传递业务包装后的永久失败分类，也不得把原始 SQL、凭据或上游正文放入线程消息。（WRK-009, WRK-028）

> 依赖：001, 002

## 目标

可靠执行定时同步、模型调用和单职位匹配，使任务在失败或进程重启后可重试、恢复和审计。

## 功能需求

- **WRK-001**：入队必须校验 task type 与 payload，并使用唯一幂等键。
- **WRK-002**：中央调度者必须原子设置运行状态、服务代次和唯一分派凭证并递增累计尝试次数；工作线程不能自行领取数据库任务。
- **WRK-003**：同一任务最多有一个有效分派；业务结果、检查点与完成状态的写入必须验证执行权，旧分派不得覆盖新结果。
- **WRK-004**：工作线程报告心跳；中央调度者判断超时并撤销旧分派，按预算恢复或失败。服务重启必须先取得排他所有权再撤销旧分派并恢复。
- **WRK-005**：错误必须按可重试、永久、配置、解析变化和取消分类。
- **WRK-006**：重试必须应用上限、指数退避、抖动和可选 Retry-After。
- **WRK-007**：计划必须按时区解释，并在重启后只补最近一次错过的 occurrence。
- **WRK-008**：同一来源不得存在并行同步运行。
- **WRK-009**：Web/CLI 宿主退出停止领取，传递 AbortSignal，等待工作线程及外部资源回收后释放独占锁；强杀后通过既有分派门控和检查点恢复。
- **WRK-010**：用户必须能查询、重试失败任务和取消 pending/running 任务；成功任务不可取消。running 取消为协作式：若声明了提交门控的 Handler 已在最终事务中确认“任务仍 running、服务代次与分派凭证有效且未请求取消”并发布业务结果，则之后到达的取消视为过晚，Task 必须完成为 succeeded，不能把已可见结果伪装成 cancelled。
- **WRK-011**：中央调度者按 task type 维护独立逻辑队列与并发槽位，慢任务不得阻塞其他类型分派。
- **WRK-012**：每个 task type 的消费并发度必须可独立配置；未显式配置的类型使用并发度 1，配置不得绕过 `concurrency_key` 互斥约束。
- **WRK-013**：maxConcurrentNetworkTasks 必须限制同一服务下所有工作线程的 HTTP、浏览器与模型在途操作总量；许可由中央服务协调，等待可取消且不阻塞线程。
- **WRK-014**：来源 Token Bucket 由中央服务跨线程协调，遵守 requestsPerMinute 与 burst；节流等待不占全局网络许可，取消退出队列。
- **WRK-015**：生产 Worker 必须周期记录全局网络在途数、排队数和事件循环 P95 延迟，以便在提升并发前识别背压与同步阻塞。
- **WRK-016**：来源同步任务详情必须展示所属公司、招聘渠道、物理来源、触发方式以及对应同步运行的覆盖状态和职位统计；不得暴露原始任务 payload。
- **WRK-017**：诊断任务列表必须将同一来源同步运行派生的 `source.job-detail` 明细任务聚合为一个职位详情同步批次，展示公司和总数、等待、运行、成功、失败、取消统计；明细任务仍须保持独立执行、重试和审计。
- **WRK-018**：`source.job-detail` 的来源结构变化必须保留 `parse_changed` 分类和脱敏后的具体解析诊断，并在未耗尽 `maxAttempts` 时按退避策略自动重试；该重试覆盖不得改变其他任务类型对 `parse_changed` 的终止策略。
- **WRK-019**：任务诊断分页必须在一次批次聚合中同时取得当前页和筛选后总数，不得为计数与列表重复执行职位详情重试链、JSON 字段提取和批次分组；越界页仍须回落到最后有效页。

## 质量需求

- **WRK-020**：详情任务的来源、扫描身份与重试关联须提供可索引投影；sync_runs 合并后继续批量读取脱敏任务及来源统计，不要求保留旧表关联列。

- **WRK-Q01**：空队列时不得高频忙轮询。
- **WRK-Q02**：任务与错误日志不得包含 payload 中的敏感正文。
- **WRK-Q03**：Handler 必须通过注册表接入，Worker 核心不依赖具体业务模块。

## 验收场景

1. 中央调度者向多个工作线程分派时，同任务仅一个凭证有效。（WRK-002,003）
2. 工作线程在 Handler 中退出，中央服务撤销分派后重新分派且幂等完成，拒绝旧执行者写入。（WRK-004）
3. rate_limited 携带 Retry-After 时按其安排，不早于指定时间重试。（WRK-005,006）
4. 同一 occurrence 重复调度只生成一条任务。（WRK-007）
5. 同一来源已有同步任务时，计划任务不重复入队。（WRK-008）
6. 中央服务关闭后不再分派，在途 Handler 收到取消；CLI/Web 退出均停止执行，残余任务由租约与检查点在下次启动恢复。（WRK-009）
7. permanent 错误不自动重试。（WRK-005）
8. 同时存在多个 task type 的 pending 任务时，各类型均可被独立分派；一个类型的 Handler 阻塞时，其他类型仍可开始执行。（WRK-011）
9. 将某一 task type 的消费并发度配置为 2 时，该类型可同时执行两个无互斥冲突的任务，其他未配置类型仍保持单消费者。（WRK-012）
10. HTTP、浏览器和模型操作在多个工作线程中竞争容量为 2 的中央网络许可时，任意时刻最多两个操作在途；排队操作取消后不再占用队列或许可。（WRK-013）
11. 同一来源突发请求超过 burst 时按声明速率依次放行，不同来源互不阻塞；取消的排队请求不会被执行。（WRK-014）
12. Worker 运行时日志可观察网络在途/排队数量及事件循环 P95 延迟，日志不包含请求内容。（WRK-015, WRK-Q02）
13. 打开来源同步任务详情时，可查看公司和本次发现、新增、更新、未变化、过滤的职位数量；普通任务仍不展示 payload。（WRK-016, WRK-Q02）
14. 美团一次列表同步派生 100 个职位详情任务时，任务列表只出现一条“美团职位详情同步”，批次统计总数为 100；单个详情失败仍可独立重试。（WRK-017）
15. 任务页读取批次列表时只执行一次详情聚合即可同时返回总数与分页结果；请求越界页时仍回落并展示最后有效页。（WRK-019）

## 未解决问题

无。

## 中央服务补充要求

- **WRK-021**：同一数据目录仅一个 Web/CLI 宿主。主线程拥有调度器和线程池；Next 仅通过受限本机桥访问。锁失败拒绝启动，不自动附着或接管。
- **WRK-022**：移除 schedules 专表，中央周期循环读取业务设置，每个 occurrence 创建独立任务并持久幂等；保留时区、最近错过周期补执行和来源互斥语义。
- **WRK-023**：sync_runs 合并到 tasks，public_state/private_state 分离公开诊断与私有检查点；保留覆盖、扫描身份、统计和阶段恢复，不机械搬迁冗余字段。
- **WRK-024**：运行时随宿主退出，工作线程不得脱离宿主；普通退出及强杀后均无后台任务继续执行。

## 单宿主线程执行

- **WRK-025**：同数据目录 Web/CLI 互斥，主线程唯一调度，禁止后台独立服务。
- **WRK-026**：所有 Handler 在线程池执行；线程有界扩缩容、内部异步并发，领取前预留容量，统一限流。
- **WRK-027**：会话固定线程，禁止缩容回收有会话线程；故障撤销分派并要求重连。
- **WRK-028**：Web 消费全队列并驱动周期；CLI 等待目标工作流。退出停止执行，保留检查点恢复。

以上替代 WRK-009/021/024 中后台独立服务与进程执行约定。
