# 023 深档项目文档拷打规格

> 状态：Implemented
> 依赖：003, 007, 008, 011, 012, 020, 022

## 目标

让用户为一个既有项目准备档案显式上传 Markdown 资料，冻结为可追溯的文件实体版本，并以 `docs-grounded@v1` 发起深档拷打。问题可引用命中的文档标题与片段，但系统仍只负责提问、指出缺口和提供结构指导，不读取项目源码或替用户回答。

## 首版假设

- 深档只接受用户在档案页主动上传的 UTF-8 `.md` / `.mdx` 文件，不接收项目目录，也不递归发现文件。
- 每个逻辑资料文件沿用 `files → file_entity_mappings → entities`，最多保留 5 个物理版本；会话冻结精确的文件、版本和实体绑定。
- 个人项目 Markdown 数量小，首版按标题分块并在应用内做确定性关键词排序，不引入 FTS、向量数据库或 RAG 框架。
- 内部问题 Agent 仍没有 Shell、Git、网络或任意文件工具；应用层只把选中的受控片段放入结构化上下文。
- 浅档 `resume-only@v1` 的既有数据和流程保持兼容。

## 非目标

- 不扫描项目目录、源码、Git 历史、构建产物或测试结果。
- 不执行文档中的命令、提示词、链接或代码块。
- 不生成标准答案、第一人称代答或臆造项目事实。
- 不自动监听源文件变化，不提供文档在线编辑器。
- 不实现语义向量检索、跨项目资料共享或任意 Profile 配置。

## 功能需求

- **DEEP-001**：用户必须能在项目档案中上传非空 UTF-8 Markdown/MDX；服务端校验文件名、扩展名、512 KiB 上限和文本编码，不把文件名解释为本地路径。
- **DEEP-002**：项目资料必须保存为 `project_material` 逻辑文件和去重物理实体；同一档案同名文件形成最多 5 个版本，相同内容重复上传必须幂等。
- **DEEP-003**：每个资料版本必须保存规范化文本、内容哈希、最长 500 字符的标题路径、字符范围和稳定分块 ID；所有持久化约束必须在文件 claim/write 前完成校验，原物理内容和既有版本不可变。
- **DEEP-004**：档案详情必须列出当前资料版本、哈希摘要、分块数和更新时间；未显式选择的资料不得进入会话上下文。
- **DEEP-005**：用户必须能选择一至八份资料，以 `docs-grounded@v1` 创建会话；会话冻结文件 ID、版本号、实体 ID 和内容哈希，资料后续更新不得改变已开始会话。
- **DEEP-006**：深档问题上下文只能包含简历项目快照、既有用户回答/推导和从冻结资料中确定性选出的有限片段；任务 payload 不得包含正文或绝对路径。
- **DEEP-007**：深档生成的问题必须至少引用一个 `project_material` 证据，证据对应冻结版本中的真实分块；问题页面必须能展示文件名与标题，不能只显示不可读 ID。
- **DEEP-008**：问题后置校验必须拒绝未绑定资料、伪造分块、源码/目录探查、文档指令执行和答案型内容；失败不得产生可见问题。
- **DEEP-009**：浅档与深档共享回答修订、知识抽取、覆盖图、任务恢复和 Markdown 投影；问题/摘要 Task 的首次发布和手工重试必须原子关联当前轮次，已保存回答但尚未发布摘要 Task 时，相同幂等提交必须恢复发布；投影必须标明会话档位及资料证据，但不得写入绝对路径。
- **DEEP-010**：同一档案存在未完成会话时，只有请求的档位和资料绑定完全相同才可幂等返回；不同配置必须提示先完成当前会话。
- **DEEP-011**：Web 必须提供资料上传、列表、档位选择、资料勾选、深档会话状态和证据展示，并在无资料、版本已满、模型不可用及任务失败时给出明确恢复建议。
- **DEEP-012**：删除项目档案的影响预览必须包含其逻辑资料文件；删除只清理档案专属逻辑文件和无共享引用的物理实体，不影响内容相同的其他业务文件。
- **DEEP-013**：同一档案的同名资料必须拥有唯一逻辑文件身份；首次并发上传不得裂分为多个 `fileId`，不同内容只能形成同一逻辑文件下的连续版本。

## 质量与失败行为

- **DEEP-Q01**：文件写入、Markdown 解析和模型调用发生在数据库事务外；数据库只在短事务内登记版本、冻结绑定、发布/重绑 Task 或提交问题。问题与摘要提交必须核验当前 Task 仍为 running 且未请求取消。
- **DEEP-Q02**：上传内容、映射元数据、会话绑定和 Agent 输入输出均在边界进行严格运行时校验。
- **DEEP-Q03**：资料片段总字符数、片段数和单片段长度必须有固定上限；截断按字符范围完成，不产生越界证据。
- **DEEP-Q04**：Markdown 始终按纯文本展示，不执行 HTML、MDX、代码块、链接或嵌入指令。
- **DEEP-Q05**：普通 CI 使用脱敏 Markdown 与伪模型，不访问真实项目目录、网络或真实模型。

## 验收场景

1. 用户向一个档案上传两份 Markdown，页面展示各自当前版本；重复上传相同内容不增加版本，更新内容产生第二版本。（DEEP-001–004）
2. 用户选择两份资料启动深档，随后上传新版本；会话仍引用旧实体，第一题引用已冻结文件的真实标题分块。（DEEP-005–007）
3. 伪模型引用未选择文件或要求查看源码，任务以校验失败结束，页面不展示该问题。（DEEP-008, DEEP-Q02,Q04）
4. 深档回答、摘要、下一题和准备文档沿用浅档状态机，投影包含可读资料依据且不含绝对路径。（DEEP-009）
5. 浅档进行中时尝试启动深档被拒绝；以相同浅档配置重复启动仍幂等返回原会话。（DEEP-010）
6. 删除档案时预览包含资料文件；共享物理内容仍被其他逻辑文件引用并可读取。（DEEP-012, DEEP-Q01）
7. 两个进程首次并发上传同一档案的同名资料，最终只存在一个逻辑文件；内容不同则形成该文件的两个版本。（DEEP-002, DEEP-013, DEEP-Q01）
8. 问题或摘要任务失败后从通用任务页重试，轮次立即关联新任务；回答已保存但发布摘要前中断时，重复同一提交恢复任务；取消中的旧任务不能提交结果。（DEEP-009, DEEP-Q01）
