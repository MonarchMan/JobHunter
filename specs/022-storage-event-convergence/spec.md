# 022 存储与事件模型收敛规格

> 状态：In Progress

## 目标

严格审计现有 SQLite 表，删除没有独立查询价值或仅为单一文档类型重复保存元数据的表；以通用事件流和通用文件—实体模型承接仍需保留的数据，并在迁移中无损保留现有本地数据。

## 范围

- 删除 `job_status_events`、`operation_audit_events`、`sync_item_failures`、`agent_tool_calls`，把仍有价值的历史迁入通用 `events`。
- 删除 `file_artifacts`、`resume_documents`、`experience_documents`，以 `files`、`entities`、`file_entity_mappings` 保存逻辑文件、物理内容和最多五个内容版本。
- 删除 `raw_job_records`；职位修订只保留来源内容哈希、来源 URL 和标准化快照，职位观察改为引用当时生效的修订。
- 删除 `jobs_fts`、其内部 shadow tables 和同步触发器；关键词搜索直接查询 `jobs`。
- 删除 `resume_polish_suggestions`；成功结果以既有 `agent_runs.output_json` 为唯一事实，任务保存结果定位信息。
- 调整 Repository、诊断、清理、删除、备份和文档读取链路。

## 非目标

- 不引入完整事件溯源；业务当前态仍保存在领域表中。
- 不让通用事件替代需要外键约束、排序或聚合查询的领域实体。
- 不实现云存储、分片上传、目录树、分享或配额。
- 不读取或分析项目代码；项目准备文档只作为普通逻辑文件保存。

## 功能需求

- **SEC-001**：必须逐表记录保留、合并或删除结论；仅有写入、没有读取且不承担约束的专用表不得保留。
- **SEC-002**：`events` 必须按 `stream_type + stream_id + sequence_no` 唯一、有序且不可变，事件正文使用经边界校验的 JSON。
- **SEC-003**：职位状态变化、同步条目失败、Agent 工具调用和敏感删除审计必须写入 `events`，并保持原有诊断或审计能力。
- **SEC-004**：`files` 表示逻辑文件；`entities` 表示不可变物理内容；同一物理内容可以被多个逻辑文件引用。
- **SEC-005**：`file_entity_mappings` 必须以 `version_no BETWEEN 1 AND 5` 和主键约束保证每个逻辑文件最多五个实体版本，版本号从 1 开始且不能重复。
- **SEC-006**：解析状态、提取文本、规范化文本和解析器版本必须绑定到文件实体版本；文档种类、业务状态和低频元数据保存在逻辑文件。
- **SEC-007**：简历画像版本、项目准备文档和个人面经必须引用逻辑文件，而不是物理实体路径；职位同步不归档完整原始响应。
- **SEC-008**：删除逻辑文件只在最后一个引用消失后隔离物理实体；共享实体不得误删。
- **SEC-009**：迁移必须保留非原始职位文件内容、简历解析、个人面经、项目准备文档、职位标准化修订、职位事件、工具调用、同步失败和删除审计数据。旧原始职位正文明确不保留，只回填来源哈希与 URL。
- **SEC-010**：迁移后不得存在被本规格删除的九张业务表及任何 FTS5 对象，数据库外键检查必须通过。
- **SEC-011**：简历润色状态查询必须从 `tasks` 和 `agent_runs` 恢复成功结果，不再保存第三份结果副本。

## 质量要求

- **SEC-Q01**：迁移采用复制、校验、切换、删除顺序；不得先删除旧表再尝试恢复数据。
- **SEC-Q02**：文件写入和移动不得发生在数据库事务内；数据库事务只登记元数据或切换引用。
- **SEC-Q03**：通用表只提供稳定最小字段；业务字段不得不断提升为通用列。
- **SEC-Q04**：所有新增 JSON 写入在应用边界规范化，所有 JSON 读取在使用边界校验。
- **SEC-Q05**：必须有迁移夹具覆盖共享物理实体、五版本上限和旧表数据转换。

## 验收场景

1. 升级含简历、面经、原始职位和项目笔记的旧数据库后，简历、面经和项目笔记仍可读取，职位修订保留来源哈希与 URL，原始职位正文不再归档。（SEC-004–009）
2. 两个逻辑文件引用同一内容时只存在一个 `entities` 记录；删除其中一个不会隔离实体。（SEC-004,008）
3. 为同一逻辑文件写入第六个实体版本时数据库拒绝；前五个版本仍完整。（SEC-005）
4. 职位状态、同步失败、工具调用和删除审计均能从 `events` 按流查询，旧专用表不存在。（SEC-002,003,009,010）
5. 润色任务成功后 Web 从任务结果定位 `agent_runs.output_json` 并展示建议，数据库不存在 `resume_polish_suggestions`。（SEC-011）
6. 迁移完成后 `PRAGMA foreign_key_check` 为空，清理、备份和 doctor 不再引用旧表。（SEC-008–010）
7. 关键词查询通过 `jobs` 的转义 `LIKE` 返回结果，数据库不存在 `jobs_fts` 及其 shadow tables 和同步触发器。（SEC-010）
