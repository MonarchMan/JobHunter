# 013 简历驱动的异步职位摄取规格

> 状态：Implemented
> 里程碑：R2/R3 增量
> 依赖：007, 009, 011, 012

## 目标

把简历、求职意向、官网来源同步和职位匹配组成一个可重复的异步闭环。系统优先使用确定性关键词完成候选职位缩小，只有需要语义理解时才使用已有 Agent 能力。

## 非目标

- 不在 Web 请求中执行官网网络请求、模型调用或批量匹配。
- 不使用模型替代用户明确的排除词或目标岗位关键词。
- 不在本增量中接入招聘平台或自动投递。

## 功能需求

- **INTAKE-001**：Web 必须支持导入 PDF、DOCX 简历；服务端必须按文件内容和大小上限校验，不能仅信任文件名。
- **INTAKE-002**：Web 简历导入必须保存 Artifact、创建画像导入任务并立即返回任务标识；重复内容必须幂等。
- **INTAKE-003**：项目初始化在默认简历存在时必须幂等导入 `docs/resumes/agent简历 - 新.docx`，并为画像提取和来源职位同步创建后台任务；默认简历不存在时基础初始化仍可完成并给出可诊断状态。
- **INTAKE-004**：初始化必须为启用的官网来源建立每日同步计划；同步任务必须由 Worker 异步执行。
- **INTAKE-005**：Worker 不得在画像版本创建、来源同步或职位理解完成后自动入队批量匹配；只有用户针对具体职位显式操作时才允许创建匹配任务。
- **INTAKE-006**：同步入库前必须根据当前画像的 `targetRoles` 映射出的内部大职位类别过滤职位；默认画像的“大模型算法/大模型应用开发”只允许“研发”进入长期职位表，其他类别不得保存为 Job。
- **INTAKE-007**：职位类别映射和入库过滤必须可解释、大小写和空白不敏感；过滤为空时不得保存无意向职位，也不得调用 LLM。
- **INTAKE-008**：系统必须提供每周清理后台任务，使用既有 dry-run/安全窗口策略清理过期原始记录、观察记录、失败 Agent 运行和孤立 Artifact。
- **INTAKE-009**：Web 和 CLI 必须提供手动刷新来源职位列表的入口；手动操作只入队任务并支持幂等重试。
- **INTAKE-010**：Web 导航和页面标题必须将“我的画像”改为“个人资料”，但保留 `/profile` 路由兼容已有链接。

## 质量与失败行为

- **INTAKE-Q01**：上传、初始化和刷新请求不得等待 Worker 完成；模型未配置时，来源同步和确定性关键词筛选仍可运行。
- **INTAKE-Q02**：任务 payload、文件错误和日志不得包含简历正文、API Key、Cookie 或原始文件路径中的敏感信息。
- **INTAKE-Q03**：重复初始化、重复上传和重复调度不得创建重复 Artifact、画像提取任务或同一来源同一计划实例。
- **INTAKE-Q04**：来源网络失败、解析失败、模型失败和取消必须沿用任务重试/失败状态，不得阻塞其他来源。

## 验收场景

1. Web 上传有效 PDF/DOCX 后立即返回 `resume.profile.extract` 任务，Worker 完成后出现当前个人资料。（INTAKE-001,002,Q01）
2. 从空数据目录执行两次初始化，默认简历只产生一个文档/Artifact，十个启用官网来源各有一条待处理同步任务和每日计划。（INTAKE-003,004,Q03）
3. 画像目标岗位为“大模型算法、大模型应用开发”时，同步只保存映射到“研发”的职位；无意向职位不会写入长期职位表，也不会调用 LLM。（INTAKE-006,007）
4. 画像提取完成和来源新增修订都不会自动生成匹配任务；用户在具体职位详情点击评分后才生成该职位任务。（INTAKE-005）
5. Worker 执行每周清理任务时沿用 24 小时孤立文件安全窗口和既有确认计划校验。（INTAKE-008,Q04）
6. Web 来源页和 CLI 手动刷新只返回任务状态，页面请求不访问官网。（INTAKE-009,Q01）
7. 导航显示“个人资料”，旧 `/profile` 地址仍可打开。（INTAKE-010）
