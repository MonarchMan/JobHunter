# 028 招聘平台按需获取与正式职位管理规格

## Worker 共享 CDP 传输（ADR-0054）

- **PLT-024**：同一 Worker 内，四个平台与多个关键词连接同一 Chrome 端点时共用一个浏览器级 CDP WebSocket，并发初始化只建立一次；不同端点及不同 Worker 隔离。每个平台／关键词仍独占页面、事件、认证、查询、游标和代次，不改变职位传输方式。
- **PLT-025**：单会话取消、命令超时、初始化失败及显式断开只释放自身资源，不关闭共享 Socket 或其他页面。借用页不关闭；已授权且空闲的 Socket 保留至 Worker 退出或真实断线。所有等待者取消时可关闭尚未授权的连接。真实断线通知全部关联会话且不自动重连，后续须由明确连接动作恢复。

验收：并发初始化、同端点跨平台／跨词复用、不同端点隔离、响应和事件分发、局部取消与失败、页面所有权清理、空闲复用、断线广播及退出清理均有回归；不新增浏览器刷新、前台激活、职位重试或凭据日志。

## 目标与范围

BOSS 两种模式按 ADR-0048 共用浏览器就绪与文档生命周期规则；HTTP 只有页面就绪后才读取最小上下文，读取过程中或请求在途发生文档失效不得交付旧响应。仍禁止自动切换传输；browser 完整批次验证通过后才进行限量 HTTP 对照，分别记录真实结果。（PLT-004、PLT-006、PLT-014、PLT-019）

BOSS 初始化生命周期补充：仅 Worker 专用页在首批消费前允许同源自然导航或临时空白，清空旧文档响应；必须在六十秒内同时确认页面正常就绪及取得真实成功列表。页面登录、验证码、访问限制须复核，安全检查 URL 参数本身不是风险结论；不操作验证、不刷新、不自动切前台。跨站或首批开始后的导航终止当前会话。输出固定诊断原因码并拒绝旧文档迟到响应。（PLT-006、PLT-014、PLT-019）

BOSS 日常获取按 ADR-0048 默认使用浏览器辅助模式，CLI／Web／Worker 一致。仅观察正常页面的列表和详情 JSON，不发送独立 HTTP、不读取 Cookie，不在失败后切换传输；允许 Worker 专用页首次正常导航，后续导航使旧批次失效。其他平台保持现有方式。显式 HTTP 仅保留调试兼容；以下 HTTP 恢复要求不适用于日常 browser 模式。（PLT-004、PLT-006、PLT-019）

自动恢复补充：批次详情 37 后上下文暂未更新，不应立即将任务判为失败；在原批次十分钟期限内每五秒只读检查，官网正常更新后自动续跑。除下文 ADR-0049 限定的一次普通会话更新外，不得以职位请求探测、刷新、回灌挑战参数或重连驱动更新。取消／断线／身份变化／上下文读取失败终止检查，已入库职位保留；记录检查状态、次数和原始脱敏请求诊断。未更新检查不消耗五次成功恢复预算，也不延长期限。令牌变化仅为保守前置条件，不能证明 37 根因。（PLT-006、PLT-014、PLT-015）

BOSS 显式 HTTP 模式的详情 37 恢复按 ADR-0049 增加用户授权的官网会话更新：仅 Worker 自有、仍在普通职位页的后台窗口可对本批失败职位执行一次普通链接点击；不主动刷新、不操作验证控件、不执行官网私有安全脚本。官网若自行经过一次安全检查路由并返回正常职位页，可继续只读核验页面和上下文；出现人工验证控件、其他导航或反复检查立即停止。该浏览器请求只更新会话，不作为职位事实；列表和详情必须仍由 Node 独立 HTTP 获取并校验。每次 37 至多一次普通点击，点击后仅在原批次期限内检查认证绑定与安全上下文；未更新或身份变化均停止，不重放必然失败的 HTTP 请求。显式借用用户标签页不自动点击。此能力不构成纯 HTTP、服务端 37 根因或长期稳定性已解决的证据。（PLT-006、PLT-014、PLT-015）

在保留官网同步的基础上接入个人招聘平台，按用户浏览读取职位并进入统一正式职位库。首批实现 BOSS 推荐与详情，再独立接入智联、前程无忧和猎聘。当前已实现 CLI、Web 浏览、CDP 内存连接、受限 HTTP、Worker、正式入库、默认关闭的平台保留清理及多平台隔离基础。恢复后的单批单详情真实隔离 smoke 已通过；观察仍暂停，后续四个平台分别执行 12 小时、每 3 小时一轮的独立观察，某个平台失败不阻止其他平台。不据单轮 smoke 宣称长期稳定或全平台 supported。

不建设账号池、全量平台爬虫、临时职位库、收藏后转正、自动投递或聊天能力。没有平台授权证据时不得宣称官方合作接口；实现遵循平台适用规则与用户授权边界。

智联分阶段验收：允许先验证“已展示的单条校园职位 → 独立 HTTP 详情 → 隔离正式库保存与查询”。这一受限选择集合没有推荐分页语义；公司编号须从详情获取并与已显示公司名称核对，不从名称推测。推荐接口失败时仍登记为未通过，不以选中职位导入成功代替推荐、分页或完整生产装配验收。（PLT-003、PLT-008、PLT-014、PLT-015）

推荐最小闭环验收要求：同次 Worker 运行内实时读取一批推荐，从该批选择一条职位，实时获取详情并校验职位及公司编号，再写入隔离正式库并通过统一查询读取；不得以研究响应重放替代在线验收。单条成功与失败样本同时保留，生产装配、其他详情格式、分页和长期稳定性单独验收。（PLT-008、PLT-009、PLT-014、PLT-015）

## 需求

自动续跑按 ADR-0049（覆盖下文历史的“37 只能显式恢复”限制）：批次详情 37 后立即检查当前上下文，满足既有认证绑定与安全上下文更新条件后，同任务继续尚未提交候选；不等待固定时间、不刷新、不自动重连。自动和显式恢复共享同批五次与十分钟期限，网络重试独立计数。上下文未变时不重发职位请求，保留业务码 37、context_unchanged 原因及未完成集合，等待后续明确操作；其他不安全或失效状态终止恢复。列表错误与非 37 错误不进入此路径。进度提供累计 resumeCount，不保存凭据。（PLT-006、PLT-007、PLT-014、PLT-015）

日常获取按 ADR-0046：职位页选择具体平台后原地获取一批，Worker 自动连接本机 Chrome，在同一默认浏览器配置中为该平台新建独立后台窗口和专用页，共享登录态，不接管已有页面；复用健康会话及其专用页，无需手填路径或页面 ID。监听先于初始导航，后续获取不新建、不刷新。显式断开、替换或初始化失败仅清理自己的页，意外断线不自动重连清理。默认统一账号，不建设多配置选择。冻结会话不自动重连；高级路径及 CLI 显式目标调试兼容保留，借用的调试页不关闭。点击获取明确授权最小上下文读取，组件挂载、轮询、筛选和本地结果刷新不发起采集。完成或部分失败后更新本地职位表，不改变筛选范围。新页查询与页面级状态独立，各平台初始化前置条件仍需满足。（PLT-004、PLT-005、PLT-006、PLT-014、PLT-018）

临时网络重试按 ADR-0049：同批次最多三次额外只读 HTTP 传输重试，与五次显式 37 恢复分别计数；退避 5／10／20 秒，并遵守合法 Retry-After 和原批次期限。不重复已提交职位；37、认证读取失败、身份／解析错误、取消或未知传输错误不进入网络重试。（PLT-006、PLT-007、PLT-014、PLT-015）

批次失败定位（PLT-014、PLT-015）：每条详情请求前，将当前候选的非敏感稳定 `currentExternalJobId` 写入任务进度；详情或保存失败时保留，成功提交职位时与入库计数原子清除，列表失败和正常完成不携带该字段。仅允许有界稳定 ID，禁止 URL、securityId、lid、Cookie 或令牌进入进度。历史任务缺少该字段必须说明无法定位，不从当前推荐排序猜测旧失败职位。该检查点仅用于准确诊断，不表示跨进程恢复私有访问参数，也不自动解冻风控会话。

显式恢复（PLT-006、PLT-007、PLT-014、PLT-015）：按 ADR-0049，仅 BOSS HTTP 同代次批次详情 37 可在原批次十分钟内 resume；命令须指向当前失败任务，且认证绑定不变、安全上下文相对本次失败已更新。`bst` 可随官网正常轮换，但后续请求必须取当前值。恢复在原任务内从未提交候选继续，同批最多五次有效恢复，不重抓已提交详情／列表或自动翻页；上下文未变只读等待，不消耗有效次数。达到上限、过期、取消、断线、换代、重启或非 37 错误均不得继续。这不是服务端 37 根因修复。

平台 UI 收尾：来源页四个平台导航必须有可见且可访问的当前选中状态，窄屏保持完整名称与可操作区域；连接、批次任务和入库结果分区展示，固定错误诊断与长任务编号不得横向撑开页面。连接表单仅在首次或主动断开后默认展开，采集失败不自动展开以遮挡诊断；有明确采集进度时不再提示等待浏览器授权。职位页清除普通筛选、空状态恢复及返回来源时保留当前 provider；切换平台只由显式平台选择发生。仅改善呈现与导航，不更改当前传输默认值、权限、请求策略或数据生命周期。（PLT-016、PLT-018）

平台收尾补充：四个平台的稳定性观察独立指定 provider、代次和轮次，失败、取消或末批仅终止该平台观察，不影响其他平台；按 12 小时／每 3 小时的外部计划运行，本次不恢复调度。每轮只发布 next，检查本批正式入库事实，不重复请求详情；等待受显式 deadline 限制，不使用固定 90 秒整批超时。末批记为 exhausted，不要求凑齐非空数据；官网辅助无新批次时不自动操作网站。现有实验节流不变。（PLT-007、PLT-014、PLT-016）

平台任务在本地持久化脱敏进度：阶段、有效候选总数、已处理数、已入库数、排除数与固定错误分类／业务码／原因码；失败或取消保留已提交统计，历史无进度不推算。来源页展示当前任务统计，不用上一成功批次代替当前部分结果。CDP 意外断线通过本地事件更新当前 provider／generation 的不可用状态，不主动请求平台探活，不自动重连，不把断线等同于账号退出；旧会话事件不得污染新连接。共用平台面板承载上述行为，不新增视觉令牌。（PLT-004、PLT-005、PLT-006、PLT-014、PLT-018）

猎聘生产接入按已验证学生首页推荐能力开放：连接时有界观察一次正常排序切换的 POST 模板，查询固定；首次 HTTP 使用 LOGIN，后续显式批次使用 UP，不自动遍历或虚构总页码。每批自动补齐有效候选详情并逐条正式入库，未知结构／重复批次／认证异常停止，已提交结果保留；匿名公司缺失 ID 排除并计数。CLI、Web、Worker、职位筛选和连接状态均按 liepin 隔离。社招首页、搜索及长期稳定性另行验收。（PLT-004、PLT-005、PLT-007、PLT-008、PLT-009、PLT-015、PLT-016、PLT-018）

猎聘 HTTP 详情收到重定向时不自动跟随、不得向目标转发凭据；诊断仅记录固定原因码，区分登录、验证、职位迁移、站内其他、站外和无效目标，不记录 Location 原值、查询参数或响应正文。一次完整批次遇到 302 仍保留已提交职位并停止，不把未知重定向直接归因为频率限制。四平台请求间隔均可通过运行配置 `platforms.requestIntervalMsByProvider` 分别覆盖；未指定的平台回退至统一 `requestIntervalMs`。本机生产配置设 BOSS／智联／前程无忧为 0 毫秒、猎聘为 1000 毫秒；连接器不得写死平台下限。（PLT-006、PLT-014、PLT-015）

猎聘分阶段接入：先验证当前登录页实际列表协议和一条详情，优先使用独立 HTTP；凭据仅取自已授权浏览器且留内存。以真实列表中的职位／公司身份核对完整正文后，才经应用仓储写隔离正式库并由统一职位查询读取。列表摘要、登录墙或 HTTP 失败不得冒充完整详情；搜索、推荐、翻页和 CLI／Web 生产装配分别验收，不以单条闭环标记全能力 supported。（PLT-004、PLT-005、PLT-008、PLT-009、PLT-010、PLT-015、PLT-016、PLT-018）

猎聘推荐的主列表与补充推荐均参与校验及候选计数，已观察的匿名公司缺失 ID 形态排除并计数；不得用公司名称编造身份。详情可使用独立 HTTP 返回 HTML 内的完整 JobPosting JSON-LD，但必须核对列表与详情的公开 URL、内部职位 ID、公司 ID 和标题；摘要不转为正文，未知结构仍报错。重复请求不视为固定页重放，持续批次能力单独验收。（PLT-003、PLT-008、PLT-009、PLT-010、PLT-015）

前程无忧解析失败须在 `parse_changed` 类别内附带固定阶段码，区分模板、查询变化、响应类型／大小／JSON、信封、职位结构、分页与身份检查；不得包含实际 URL、响应、字段值或认证数据。无法复现的历史失败不以猜测性放宽校验处理。（PLT-014、PLT-015）

智联主站网络失败须保留固定白名单原因码，区分请求超时、连接／响应超时、连接重置／关闭、DNS、拒绝连接和未知传输错误；取消不误报网络故障。不得携带底层异常消息、cause、请求地址或认证数据。停止在线重试后仍可开展本地诊断与回归，未复现的问题不得宣称根因已修复；保留失败冻结及已入库结果。（PLT-014、PLT-015）

- **PLT-016**：平台连接代次、工作集、并发键、幂等键、职位来源与公司身份按 provider 隔离；一个平台断开、失败或重启初始化不得改变其他平台。后续范围为智联、前程无忧（51job）、猎聘，登记身份不等于已实现采集。
- **PLT-017**：站内职位详情实际在可见页面展示后，通过同源 POST 记录平台职位用户交互；GET、预取、隐藏页面和后台任务不记录交互。时间由服务端生成且单调更新，失败可见并允许显式重试。清理状态展示读取真实设置，不能写死停用；默认关闭与预览确认规则不变。
- **PLT-001**：官网同步与平台按需浏览分开编排，共用正式职位、修订、匹配和求职业务。满足质量门槛即入库，不要求收藏；不建立长期临时职位库。
- **PLT-002**：区分来源提供方、招聘公司和个人连接。平台来源跨公司且不参与官网三渠道覆盖；既有官网来源、职位 ID 与映射保持不变。
- **PLT-003**：平台稳定职位 ID 在物理来源内幂等；临时访问参数不得作为身份。同名公司不自动关联，跨来源职位不强行合并；已入库职位仍显示在本次结果中。
- **PLT-004**：用户明确获取时由 Worker 自动连接本机默认 Chrome 配置，同一活动会话复用一次授权的 CDP 连接。BOSS 默认 browser，显式 HTTP 与其余平台按各自协议取得必要上下文；主动断开、替换连接、Worker 退出时关闭 CDP，意外断线不自动重连。禁止磁盘凭据读取、完整存储导出、自动保活和账号池。
- **PLT-005**：凭据与访问参数仅在 Worker 有界内存中存在，不写业务数据库、任务、日志、备份、模型输入或前端。Cookie 请求匹配必须保留域、路径、过期与 Secure 语义，跨域重定向不携带凭据。
- **PLT-006**：认证会话与浏览器连接状态分开。明确认证失效最多重同步一次；验证与限流暂停，未知业务码不得误判登录失败或空结果。断开／切换使代次失效，取消在途请求并阻止旧响应提交；已存职位保留。

- **PLT-019**：BOSS 默认 browser，也可显式选择 HTTP；禁止失败后自动切换传输。browser 仅观察官网正常操作产生的真实 JSON，模式内不发独立 HTTP、不导出 Cookie、不执行安全检查脚本。首次列表及后续页必须实际观察，详情限当前批次对应职位链接；主动操作按可配置间隔节流，错误／取消立即停止，原授权连接保留至显式断开。

BOSS 请求前允许沿用同一授权连接，只读所选同源页面的普通认证 token 与目标端点适用 Cookie；固定列表查询不随页面浏览隐式切换。仅发送已验证的普通认证头，不复制浏览器特征头、不执行检查脚本、不把 HTTP 下发的检查参数写回浏览器。读取失败或取消时不得沿用旧凭据继续 HTTP；37 仍立即冻结，不同步后自动重试。（PLT-004、PLT-005、PLT-006）

BOSS HTTP 的普通缓存时间戳 `_` 在节流等待和认证上下文读取完成之后、实际发送前生成；不能沿用捕获时刻或排队前时刻。该协议一致性检查不等同于安全令牌续期，不作为 37 已解决的依据。（PLT-004、PLT-015）

BOSS 同会话主动请求的五秒最小间隔必须在计时器唤醒后重新核对，提前唤醒时继续等待；等待期间取消或超时不得发出请求。限速边界修正不能作为服务端 37 触发规则的证明。（PLT-006、PLT-015）

显式授权的研究实验可对 HTTP 200／37 使用有界同参数重试，本轮额外重试总预算最多四次，同一失败请求含首次最多五次尝试；其他错误或所选页出现安全检查路由立即停止。重试不得刷新、轮换凭据、处理安全挑战或自动换传输。生产会话仍保持失败冻结，研究恢复不等同生产支持或长期稳定。（PLT-006、PLT-015）

- **PLT-007**：每次用户请求只读取当前一页／一批，仅补齐该批详情，不因自动入库而遍历所有页。用户先在官网设置受支持的搜索条件及排序，查询随连接固定；未支持的条件不得静默忽略，推荐流不冒充搜索排序能力。同浏览会话串行并合并重复请求；查询变更、取消和进程重启均有确定行为，不后台遍历或恢复已丢失的私有游标。未来连续获取须显式设置前 N 页及职位数量上限，本次不实现连续采集。
- **PLT-008**：search、recommend、next、detail 分别声明能力与支持证据。翻页须验证新增稳定 ID，重复页、异常空页不能当作成功末页。
- **PLT-009**：列表先做确定性预筛，每次显式批次读取由 Worker 串行补齐必需详情，逐条自动正式入库，不要求用户点击详情或收藏。列表已有完整正文时复用已校验事实；不保存摘要或占位 JD。失败或取消立即停止后续请求，保留已提交职位及其他职位旧版本，不自动重试。
- **PLT-018**：官网与招聘平台职位统一在“职位”页展示，以来源类型隔离，默认官网；平台可进一步按 provider 筛选，默认全部招聘类别（含未知）。来源页仅管理连接、获取批次和显示任务结果，不保留独立摘要列表。筛选、计数、分页与返回链接使用同一范围；刷新和筛选不访问招聘平台。历史任务无入库计数不冒充已入库。
- **PLT-010**：详情参数须来自可验证的本次列表或协议上下文，核验详情身份、标题及有效正文；HTTP 失败不自动通过浏览器回退规避验证或限流。浏览器辅助能力必须单独验证并显式启用。
- **PLT-011**：平台缺失不推进 missing_count，不执行完整同步下架。明确上游关闭才改变状态；陈旧提示、请求失败、本地保留清理与上游关闭分别表达。
- **PLT-012**：平台职位采用正常保留清理，保留期限与执行频率独立于官网配置。自动删除默认关闭，先 dry-run，再经用户确认策略启用；不因规格发布删除数据。
- **PLT-013**：清理保护收藏、投递、面试准备、笔记和当前任务引用，执行事务内重检引用和活跃时间；依赖删除不破坏历史，清理不生成下架事件。复用既有 SQLite 物理维护。
- **PLT-014**：平台任务由 Worker 执行，网络在事务外；统一职位、修订和观察短事务原子写入。应用声明端口，领域不依赖浏览器，Web 不读取凭据或直接访问平台。
- **PLT-015**：在线门禁限制两至三批列表及少量详情，不跑全量门禁。BOSS 业务码 37 须脱敏分类并验证正确参数关系后才能晋级详情能力；模拟测试与真实验证分开报告。

## 验收场景

四平台任务在任务页使用同一中文名称映射，列表、详情与类型筛选均包含 BOSS、智联、前程无忧、猎聘；智联名称不将主站搜索误标为仅校园。平台 UI 验证使用隔离夹具，不创建真实浏览器连接或上游请求。（PLT-014、PLT-016）

前程无忧首版工程能力为官网辅助搜索批次读取，而非自动翻页：选定 `we.51job.com/pc/search`，同一授权连接仅监听该页实际成功的 `search-pc` 请求；每次用户在官网搜索或翻页后，CLI／Web 的读取动作才用原始模板发起独立 HTTP。不得修改或生成签名、后台遍历、把未观察到新批次当成末页；等待有界、失败冻结。查询变更要求重新连接，最多消费 20 批；原始总数与所选页决定末页。JSON 内完整 `jobDescribe` 可作为同次获取的详情事实，身份及正文校验后经 Worker 正式入库，不声称额外详情 HTTP。浏览器辅助方式须在同意文案中明确，凭据只留有界内存；该能力为 experimental，自动翻页与长期稳定性未验收。（PLT-004、PLT-005、PLT-007、PLT-008、PLT-009、PLT-010、PLT-014、PLT-015、PLT-016）

智联生产入口覆盖校园推荐与主站搜索：CLI 以 `--provider zhilian` 选择，Web 在平台来源内独立切换；所选目标页必须是校园 `/recommend` 或主站 `/jobs`，据此固定协议。校园正常分类切换取得首页 POST；主站在官网设置筛选后正常搜索一次，取得首页搜索及同一目标页面的详情请求模板，限时初始化后停止监听并 detach。不刷新、不自动点击、不导出 Cookie。模板仅在 Worker 内存，后续列表和详情使用受限 JSON HTTP。一次智联连接固定一个查询，官网后续改动不会隐式修改工作集；切换查询须显式重新连接并更新代次。主站搜索可能包含实习，不以主站域名推断全部职位招聘类型。连接失败不冒充未登录，失败冻结而不自动重试。BOSS 默认命令与状态不变，猎聘仅开放学生首页推荐的实验入口，51job 仅按 ADR-0047 的官网辅助实验范围开放。（PLT-004、PLT-005、PLT-007、PLT-014、PLT-016）

智联主站工程化验收：同次会话独立读取搜索、下一批和选中职位详情，详情核对职位编号、标题、公司编号／名称及有效正文后经 Worker 正式入库，CLI 和 Web 复用平台命令；不得以官网自动详情响应重放代替实时详情。请求串行且至少间隔 5 秒（实验策略，不是已证实的接口要求），遇到验证、限流或协议变化冻结。未声明的筛选字段拒绝，不静默丢失筛选；页数上限与上游末页分别表达，达到本地上限不伪造末页。（PLT-007、PLT-008、PLT-009、PLT-010、PLT-014、PLT-015）

1. 同一平台职位重复出现只更新同一正式记录，仍可在不同查询中显示；公司不同名空间不会误合并。（PLT-001、PLT-002、PLT-003）
2. 浏览器同步会话后保留同一 CDP 连接，HTTP 完成两批列表与详情，不因每个动作再次授权；日志、任务和数据库无凭据；未证明必要的数据不扩采。HTTP 失败冻结请求但不自动重连；意外断线终止会话。（PLT-004、PLT-005、PLT-010）
3. 连接失效、验证码、限流、未知码分别显示；切换连接后迟到响应不能提交。（PLT-006）
4. 重复点击只发起一批请求；翻页重复被识别；取消和重启不继续爬取。（PLT-007、PLT-008）
5. 无正文摘要不会冒充已入库职位；详情成功自动入库，失败不污染旧记录；未收藏岗位同样可持久化。（PLT-009、PLT-014）
6. 新推荐没有旧职位时旧状态不变；明确关闭可以更新；本地清理不声称平台下架。（PLT-011）
7. dry-run 不删除，启用后只清理符合策略且无保护引用的职位；执行前新增收藏或交互会阻止删除。（PLT-012、PLT-013）
8. 未解决的详情错误保留 experimental，推荐测试成功不替代详情门禁。（PLT-015）

## 未解决问题

无。平台协议尚待验证的事实作为实现门禁，不用猜测补齐：BOSS 业务码 37、条目级与列表级 lid 对应、最小必要 Cookie、会话失效判据、智联当前协议。验证不通过时能力保持 experimental 或 blocked，不阻止文档架构成立。
