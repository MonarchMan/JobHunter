# 028 招聘平台来源设计

> 状态：In Progress

## 1. 架构依据

前程无忧解析诊断使用连接器内部 `PlatformError` 子类，仍归类 `parse_changed`，仅在错误消息中追加编译期固定阶段码；不传 Zod 原始错误、动态字段值或响应。阶段分开覆盖模板、查询变化、媒体类型、响应体、JSON、信封、职位结构、分页及详情身份，Worker 既有安全错误投影无需新端口或数据库迁移。

前程无忧生产装配见 ADR-0029：观察器仅绑定所选搜索页，最多保留 5 个在途请求和最新一个成功模板；只接受固定只读端点以及已观察字段。HTTP 会话逐批消费模板，原样保留签名，不自行修改页码；新模板最多等待 90 秒，间隔至少 5 秒。查询固定、页码递增、重复页拒绝；公司缺失计数排除，未知结构报错。详情消费同次 JSON 完整正文，正式 URL 去除跟踪参数。Worker／CLI／Web 复用已有 provider 隔离和正式职位生命周期，前端复用 PlatformBrowser、原有表单校验与任务轮询，不改视觉令牌。

研究连接清理约束（PLT-004／PLT-006）：标签页会话寿命短于浏览器 WebSocket，失效标签的 `Network.disable` 拒绝不得结束空闲研究进程；清理失败输出固定脱敏阶段，仍释放内存。显式关闭时，即使 detach 失败也必须关闭连接和输入。离线模拟失效会话复现，不用真实账号反复授权；生产初始化错误仍按 `session_unavailable` 返回，不吞掉初始化失败。

前程无忧接入计划（PLT-T018）：先用既有授权浏览器验证搜索页和当前真实 JSON；若列表 jobDescribe 经边界校验确认为完整正文，可由同一请求的已验证事实完成详情消费与入库，明确不是额外详情 HTTP，不为形式闭环重复请求。若只是摘要，必须验证独立详情协议。取得模板／必要 Cookie 后优先独立 HTTP，不采用 BossHunter 的持续页面 fetch、大批采样或磁盘登录数据。未通过真实协议验证前不注册生产连接器或开放 CLI／Web；网络不可达、登录或风控分别记录，不猜测接口成功。

当前交付 CLI 和 Web 提交操作与现有 Worker 执行，复用现有职位查询查看入库结果；保留清理通过 CLI 预览、确认启用，自动删除默认关闭。最小闭环只实现 BOSS recommend/next/detail，不以此声明 search 或智联受支持。

遵循 [专题架构](../../docs/arch/recruitment-platforms.md) 与 [ADR-0025](../../docs/adr/0025-platform-browsing-and-unified-job-lifecycle.md)。实现包为 platform-core、platform-connectors，应用用例位于 application，Worker 只装配。首版单本机、单 Worker、每平台一个活动连接。

## 2. 目标数据迁移

0035 仅重建连接表的 provider 允许集合，保留已有 BOSS 代次／状态和全部职位身份；不修改已应用的 0034。迁移只在隔离库验证，未接入连接器不因迁移而注册为可用。

迁移 0034 已实现并在临时数据库验证；尚未迁移用户业务数据库。部署前需备份并停止旧 Worker，不重建或改写既有稳定 ID。

## 3. 契约与用例

按 ADR-0027，使用受信任的内置 provider 定义绑定来源 ID、公司命名空间及任务类型，仓储和应用服务每实例只拥有一个平台；保留 BOSS 已发布来源 ID 与任务协议。通用任务工厂及 Web 投影按 provider 区分并发和幂等键，未接入平台不注册生产 handler。四个平台同名／同外部 ID 仍分别保存，事务还需验证任务类型属于该平台。

交互缺口通过可见详情页客户端一次性 POST 补齐；不在服务端 GET 中写库、不轮询触碰。应用端口执行短原子 UPDATE，避免排队期间清理先删掉已浏览职位；仅更新 platform 职位的 last_interacted_at，不修改 last_seen_at 或官网记录。后台详情保存只更新成功核验时间。Web 单独读取保留策略的安全投影（enabled 与 policy），不读取确认令牌，不扫描候选、不发布清理任务；失败显示状态未知。所有自动删除仍走 Worker。

BOSS 真实成功列表可包含 encryptBrandId 为空字符串的匿名公司条目。最小实现排除这类无可靠公司身份的条目，返回 skippedMissingCompanyId 计数，不编造公司 ID；null、缺字段及其他未知类型仍 parse_changed。分页去重和末页判断基于原始条目，不将全部被排除的一批当作末页。

最小实现由 platform-core 声明 PlatformSession（readNext/readDetail/disconnect）及 PlatformSessionProvider（connect）；platform-connectors 实现 BOSS CDP 和 HTTP 会话。输出为白名单候选、稳定身份、下一批信息与脱敏错误，不返回 Cookie。

凭据只供受限传输内部使用，不直接返回给应用。传输按目标 URL 匹配站点 Cookie，禁止重定向泄露。候选访问参数仅在当前连接代次的内存工作集中保存；每次 connect 开始新浏览，不提供并行查询或自动刷新。模型不能获得会话、工具句柄或原始响应。

应用用例：ConnectPlatform、ReadPlatformBatch、ReadPlatformDetail、DisconnectPlatform、PlanJobRetention、ExecuteJobRetention。保存不是用户必须额外触发的动作：批次或详情满足质量要求后内部调用共享的正式职位写入用例。收藏仍是既有业务标记，不负责转正。

列表缺正文时不修改领域模型允许虚假描述，而保留本次请求的摘要状态。用户展开、请求匹配或明确选择获取详情时运行详情短任务，成功自动保存；已有真实正文的列表直接保存。匹配输入始终绑定正式 jobId/revisionId。

## 4. 并发与恢复

按 [ADR-0026](../../docs/adr/0026-platform-cdp-session-lifetime.md)，CDP WebSocket 与活动平台会话同寿命，初始化后 detach 页面但不关闭 WebSocket。授权等待 120 秒，每个 CDP 命令仍为 20 秒；任务完成的取消信号不影响已交接的连接。HTTP 失败冻结请求并保留空闲 CDP，主动断开／替换／Worker 退出才释放；意外断线取消 HTTP，不自动重连。

最小实现使用 platform.boss，action 为 connect/next/detail/disconnect，共用 platform:boss 并发键，最大尝试次数为 1。connect payload 只含用户指定的 DevToolsActivePort 文件路径与 targetId；其他动作含 generation，detail 再含 externalJobId。禁止 Cookie、原始请求 URL、securityId 和私有游标进入任务。一次 CLI 提交产生一个幂等键；重复执行 next 命令属于新的下一批操作。

会话 generation 在持久连接记录中原子递增。断连和重连时更新；提交结果的短事务检查 generation、任务取消状态和租约是否过期。断连动作按队列串行执行，主动取消当前任务由现有任务取消机制处理。断连前成功提交的正式职位保留，迟到响应丢弃。Worker 重启使内存工作集不可恢复，旧浏览动作失败并要求重新连接；旧代次动作不能销毁当前连接。

未分类业务错误按不可自动重试的上游错误展示；先保留非敏感 code、操作类型、字段校验路径，错误文本须脱敏限长。认证明确失效可单次刷新，验证码／限流停止；浏览器读取不是通用错误回退。

## 5. 保留策略与空间

首版清理通过 CLI 发布 `platform.retention` Worker 任务，支持 preview/enable/disable/status；每小时维护计划仅检查已启用策略是否到期。策略存于 application_settings，默认 30 天、6 小时、关闭；preview 保存短期随机确认令牌而不删除职位，enable 必须消费同一策略的未过期令牌，首次删除至少等待一个执行间隔。每次事务最多删除 100 条，重新计算活跃时间与引用。

未启用或尚未到期的维护任务直接返回 skipped，不扫描职位和引用，也不写设置。预览输出必须包含不可撤销删除提示；eligible/protected 是该次事务执行前的候选计数，不代表删除后剩余数量。确认令牌在五分钟后过期，新预览会替换旧令牌。

现有仓库没有独立收藏／投递表；首版保守保护任何非初次观察的职位事件、引用职位／修订的事件和文件元数据、项目快照，以及任何匹配／理解结果。活动任务引用（包括批量匹配任务）同样保护；宁可多保留，不级联回收已参与分析的职位。后续增加收藏／投递等业务表时必须同步扩大保护集合。只删除无关联职位、其观察与修订及初次观察事件，不删除公司、来源、任务或匹配历史，不产生 closed 事件。用户主动查看职位的交互更新另由显式 touch 任务处理，不把后台查询当作活跃。

平台正式职位可通过正常清理删除，非 TTL 缓存淘汰。建议配置初值为 platform.retentionDays=30、platform.cleanupIntervalHours=6、platform.autoDelete=false，首次启用显示 dry-run 并确认；官网策略不变。活跃时间取创建、成功核验、用户交互最大值。用户主动页面展示可更新交互，后台刷新／失败／评分不冒充用户活跃。

保护集合包括收藏、投递、面试准备、笔记及当前任务引用；实现须核对现有表与事件中的业务引用，不能只检查 jobs 一列。分批计划、短事务重检后删除允许回收的推导、观察、修订和职位；受保护版本与历史关联不级联删除。事件仅记录脱敏计数、策略版本和原因，不保留完整被删职位备份。平台清理允许删除陈旧但未证明关闭的无关联记录，不制造 closed 状态。

监测正式职位数、修订／观察增长、数据库与 WAL 大小、清理数量和保护数量。数据库文件不立即缩小属于空闲页复用；按 ADR-0020 做物理维护，禁止每轮清理直接 VACUUM。

## 6. 研究证据与门禁

### 智联接入验证

主站工程化计划：新增 ZhilianSearchHttpSession，严格验证已观察的列表 POST／详情 GET 模板，只允许 `fe-api.zhaopin.com` 的两个固定路径；查询认证字段与正文核对，Cookie 丢弃，不允许任意请求头、重定向或 HTML 回退。CDP 根据明确选中的目标页选择校园／主站实现；主站初始化在同一限时窗口内观察首页搜索和详情模板，再停止监听。仅将详情 number 替换为本次列表中的稳定 ID，其他上下文保留；实际 JSON 的 description 也包含 div，故统一解析 jobDesc，复用有限标签解析器并仅为主站允许已观察的无属性 div，输出纯文本。未知标签／属性与畸形结构仍拒绝。沿用 provider=zhilian、原来源 ID 与已有 Worker／仓储，不新增数据所有权或连接池。

CLI／Web 沿用现有 connect → next → detail 动作；入口文案明确支持两种页面、搜索筛选在官网完成且连接后冻结。改变查询必须重新初始化代次，不在持久任务内存放原始查询模板。生产会话每次显式读取最多一页，最多 20 页；5 秒串行间隔、取消、失败冻结与有界 JSON 校验由连接器承担。先补合成协议／CDP／入库测试，再使用既有授权连接进行限量真实验收，不关闭研究连接、不写生产数据库。

2026-09-20 追加限量验证：校园生产 HTTP 会话取得首页 20 条及末页 15 条（第二页 end=1），35 个唯一职位。主站当前实际搜索为 POST `https://fe-api.zhaopin.com/c/i/search/positions`，platform=13，外层 code／apiCode、data.statusCode／isVerification，分页字段 pageIndex／pageSize、data.count／isEndPage；不能直接复用校园 platform=14 的响应契约。官网 UI 选择 Java、成都（801）、3–5 年经验（0305）后，保留已观察请求模板的独立 HTTP 在第 1／2／19 页返回 20／20／14 条，总数 374，末页显式结束；54 条无重复，公司编号齐全且经验符合筛选。这里只证明该筛选样本的搜索与分页，不证明全量社招分类规则。

主站模板未携带 Cookie 头，但认证／上下文字段仍保留，未完成最小化。列表数据来自 JSON 而非 DOM 抽取；浏览器仅用于正常筛选和获得已授权模板。官网主站自动详情 `/c/i/jobs/position-detailv3` 尚无独立 HTTP 验收；搜索连接器、详情协议、CLI／Web 查询参数与生产入库仍待工程化。校园与主站分别记账，不因本次搜索 smoke 直接扩展生产能力或 supported 状态。详细计数、频次和连接清理见 tasks.md 最新记录。

详情正文修复：已确认 CC130384730J40845557616 的 HTTP／业务码均成功，职位和公司身份无变化；其正文包含 p／ol／li／br，而首版只接受 br，导致误报 parse_changed。只增加已观察的无属性段落和有序列表标签解析，保留段落及条目顺序，嵌套／闭合结构必须合法；未知标签、属性、实体、空正文仍拒绝，不用通用正则删除任意 HTML。以合成同结构回归测试和原失败职位实时 HTTP 复核验收，保持全部身份校验。

最新验证：同次 Worker 中真实推荐 20 条 → 选择该批“云计算研发实习生” → 真实详情 → 隔离库保存／查询成功，未使用响应重放。随后原失败详情的 parse_changed 已定位为 p／ol／li 格式未识别，修复后原职位实时获取、入库及查询通过。完整证据见 tasks.md 的 PLT-T014／PLT-T015；未验证的其他格式及生产装配不因此晋级。以下早期实验记录保留，不作为最新状态。

最小推荐闭环补齐：用真实浏览器观察到的请求模板建立 ZhilianCampusHttpSession，保留已验证 URL 重复参数与正文，移除已确认可省略的 Cookie 头；模板只存内存，URL／头／正文做固定端点和字段白名单校验。推荐动作实时 HTTP 读取摘要，不预取详情；详情动作只接受本代次候选编号，另发实时 HTTP，并核对列表／详情公司编号。实验间隔 30 秒不是官网限流协议。用同一通用 Worker 依次执行连接、推荐、详情、正式入库及查询，不允许使用响应重放作为本轮在线验收。研究用授权 CDP 继续驻留，应用会话断开仅释放本轮凭据，不关闭用户明确要求保留的浏览器连接。生产 CLI／Web 装配和长期观察仍另行验收。

请求精简实验必须先保留浏览器实际 POST 的完整 URL（包括同名重复参数）、应用请求头与原始正文，确认独立 HTTP 成功后再做单变量删减；HTTP/2 伪头、内容长度与压缩协商由 HTTP 客户端负责，不声称复刻 TLS／HTTP 指纹。每次只删除一个字段并记录相对基线的差异，认证和请求值仅留内存。每轮最多三次独立列表请求，间隔至少 30 秒；失败停止，不根据一次非零业务码推断登录失效或风控。列表数量和职位身份交集同时记录，筛选／推荐语义不能因请求成功而默认不变。
