# 006 首批企业官网来源规格

> 状态：In Progress
> 依赖：004, 005
> 调研证据：[research.md](./research.md)

## 目标

为腾讯、阿里巴巴、百度、字节跳动、拼多多、美团、得物、小红书、京东和华为建立统一来源目录与调研记录，并将满足可靠性门禁的公开官方招聘渠道增量接入统一适配器契约。复杂来源可以降级，但不得阻塞数据内核、简历画像、匹配和查询主链路。

## 非目标

- 不使用账号登录、Cookie 复用、验证码规避、风控参数伪造或隐匿自动化身份等对抗手段。
- 不承诺官网接口永远稳定。
- 不在本规格接入聚合招聘平台或自动投递。

## 共同需求

- **FPS-001**：每家公司必须有独立 source slug、官方入口、招聘类型、默认限速和启用配置。
- **FPS-002**：每个来源开发前必须完成 time-boxed Spike，记录稳定 ID、分页、详情、投递 URL、完整性和访问限制。
- **FPS-003**：支持状态只有 `experimental`、`supported`、`blocked`；启停使用独立 enabled，在线运行健康使用独立 health status。没有通过门禁不得标记 supported。
- **FPS-004**：supported 适配器必须匿名发现公开职位并通过公共契约测试。
- **FPS-005**：每个 supported 适配器必须保存脱敏列表、详情、分页边界固定样本；能合法取得时增加 not-found/closed 样本。
- **FPS-006**：普通 HTTP 无法取得公开职位时，可由受控浏览器正常执行官网公开脚本并读取当前匿名会话的渲染结果；不得逆向伪造风控参数。来源出现登录、验证码或持续访问阻断时必须返回 access_blocked，支持状态保持 experimental 或转 blocked，运行健康可以 degraded/unhealthy。
- **FPS-007**：规范职位必须包含 externalJobId、title、description、detailUrl、applyUrl；地点等来源缺失字段允许 null/空集。
- **FPS-008**：适配器必须定义何时可声明 complete；无法证明全集时只能报告 partial/unknown。
- **FPS-009**：在线 Smoke 必须可单独运行且默认离线测试不访问官网。
- **FPS-010**：官网变化导致解析失败时必须保留最后成功数据并停止基于缺失关闭职位。
- **FPS-011**：浏览器采集必须封装在来源基础设施内，具备超时、低并发、资源回收、取消和失败熔断；实现或维护复杂度超过个人使用收益时必须可降级，且不得影响其他来源和 Agent 主链路。

## 单来源交付门禁

每家公司只有同时满足以下条件才能标记 supported：

1. 官方入口和匿名访问经当日复核。
2. 外部 ID 在重复请求中稳定。
3. 分页终止和覆盖度有证据。
4. 列表与详情 Schema 均运行时校验。
5. detail/apply URL 可回到官方域名且无会话标识。
6. 固定样本契约测试通过。
7. 重复同步和 partial 同步集成测试通过。
8. 限速、超时和访问阻断路径通过测试。

## 验收场景

1. 腾讯通过完整端到端同步；其他来源按门禁逐个晋级，不能因目录已建立或页面可见就声明 supported。（FPS-001..009）
2. 任一来源遇到验证码时返回 access_blocked，数据库既有职位不因本次运行关闭。（FPS-006,010）
3. 京东 URL 含会话段时，持久化 URL 被规范化为稳定官方地址。（FPS-007）
4. 任何未完成分页的来源报告 partial。（FPS-008）
5. R1 要求 10 家来源均具有可维护目录、支持状态和调研证据，并至少有一个来源通过 supported 门禁形成可用数据闭环；其余来源增量上线。experimental/blocked 不等价于适配器完成，但不阻塞 Agent 主链路发布。（FPS-001..003,011）
6. 浏览器来源超时、会话失效或触发验证码时，本次同步安全终止并保留既有职位，其他来源仍可继续同步。（FPS-006,010,011）

## 未决问题

无。具体接口字段有意留到各来源 Spike 后写入适配器内设计说明，不属于公共规格未决项。
