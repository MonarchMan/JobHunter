# 020 简历项目浅档拷打规格

> 状态：Implemented
> 里程碑：面试准备 I1
> 依赖：003, 007, 008, 011, 012

## 目标

让用户从已保存的候选人画像中选择一个简历项目，创建独立的项目准备档案，并通过一次一个问题的渐进式拷打补齐项目事实、暴露矛盾和观察准备覆盖度。系统保存用户原始回答和可追溯推导，生成只读 Markdown 准备文档，但不替用户回答。

## 首版假设

- 首版只有内置 `resume-only@v1` 浅档 Profile，只使用创建档案时冻结的简历项目快照、此前用户回答和系统推导。
- 首版采用 Web-first 文本交互；CLI、语音、批量题单不是交付门禁。
- “指导”可以提供回答应覆盖的结构槽位，但不得填入用户尚未提供的事实或形成可直接照读的完整答案。
- 当前画像项目没有稳定业务 ID，因此创建档案时使用 `profileVersionId + projectIndex + projectContentHash` 定位并校验，再生成稳定的 `ProjectDossierId`。

## 非目标

- 不读取项目目录、源码、Git、Shell、任意文件或网络内容。
- 不实现 Markdown 资料快照、深档拷打、个人面经导入、网友面经研究或外部 Agent 执行器。
- 不修改 CandidateProfile、简历项目快照或用户原始回答。
- 不输出评分、标准答案、第一人称代答或真实面试中的实时提词。
- 不开放自定义 Profile、任意 Tool 集或任意 Skill 集。

## 功能需求

- **DRILL-001**：Web 必须列出当前画像中的项目，并使用版本、项目下标和内容哈希创建项目档案；提交时项目已变化或下标越界必须拒绝，重复提交同一快照必须返回同一档案。
- **DRILL-002**：项目档案必须保存不可变的简历项目快照及来源画像版本。画像后续变更不得改写既有档案或会话；来源画像被删除后档案保留快照并标记为来源已分离。
- **DRILL-003**：用户必须能以 `resume-only@v1` 创建、查看、暂停、继续和完成拷打会话。项目档案必须提供全部会话的直接入口；已完成会话仍可恢复为进行中并继续新增问题或修订回答。会话按最后修改时间降序展示，名称统一为“会话 - YYYY-MM-DD HH:mm:ss”，不使用顺序轮次名。Profile 键、版本、定义哈希和能力摘要必须随会话冻结。
- **DRILL-004**：活跃会话必须一次只生成一个主问题。问题必须声明主要覆盖维度、提问意图、允许的回答结构提示和证据引用；证据只能指向简历项目快照、既有用户回答或由回答派生的知识项。
- **DRILL-005**：问题生成必须由 Web 在当前请求内同步调用模型并返回已校验问题，不得创建 Worker Task；接口必须流式发送由真实执行点驱动且不含问题正文的阶段状态，模型调用不得位于数据库事务中，请求取消必须向模型传播。同一会话不得并发生成问题或摘要。
- **DRILL-006**：问题后置校验必须拒绝完整代答、第一人称答案、无效证据引用、源码/目录探查要求和越权工具要求。校验失败不得产生可见问题，页面必须允许直接重试。
- **DRILL-007**：用户可以提交非空回答并在同一题下追加修订。每次修订必须原样保存正文、内容哈希和时间；不得静默覆盖、润色或回写旧修订。
- **DRILL-008**：回答提交后必须异步抽取带原文偏移的项目知识项、歧义和与简历/既有回答的冲突，并更新覆盖图。模型推导必须单独存储，不能冒充用户事实。
- **DRILL-009**：摘要或知识项只能引用当前回答修订中的有效字符区间；新修订完成摘要后，旧修订派生知识项必须标记为已取代，但旧回答和旧问题仍可审计。
- **DRILL-010**：用户必须能跳过待回答问题。只有最新题已完成摘要或已跳过时才能创建下一题；暂停或完成的会话不能直接接收新问题或回答，但完成会话恢复为进行中后可以继续。
- **DRILL-011**：系统必须用固定枚举展示覆盖状态，不计算总分。首版覆盖维度至少包含：背景目标、个人职责、架构设计、关键实现、技术取舍、数据指标、故障调试、协作推进、安全质量、反思演进。
- **DRILL-012**：每个项目档案必须有由 SQLite 权威数据重建的 UTF-8 Markdown 投影，包含项目快照、会话信息、逐题回答修订、结构指导、知识项、冲突/歧义和覆盖图。投影不得包含模型提示词、密钥、绝对路径或任务内部错误堆栈。
- **DRILL-013**：Markdown 投影失败不得回滚已提交问答；失败以可重试 Worker 任务呈现。相同源数据哈希重复生成必须幂等，成功后档案只指向最新投影 Artifact。
- **DRILL-014**：Web 必须提供项目档案列表、创建入口、档案详情、会话交互、任务状态和 Markdown 下载。空画像、无项目、模型未配置、任务失败、取消和来源已分离必须有明确状态。
- **DRILL-015**：删除项目档案必须先生成影响预览和确认令牌，确认时再次校验影响集合；删除档案、会话、回答、推导和仅被该档案引用的投影 Artifact，不得删除 CandidateProfile、简历 Artifact 或共享 AgentRun。

## 质量与失败行为

- **DRILL-Q01**：问题生成允许在 Web 请求中执行模型调用，但不得位于数据库事务中；回答摘要、Markdown 投影和其他长任务继续由 Worker 执行。
- **DRILL-Q02**：所有 Web 输入、任务 payload、Agent 输入输出和数据库 JSON 必须在边界使用 Zod 严格校验；日志和错误摘要不得包含简历正文、回答正文、完整提示词或本地绝对路径。
- **DRILL-Q03**：同一会话的上下文修订号和题序必须使用乐观并发校验。迟到的同步结果、重试任务或已取消任务不得覆盖更新后的会话状态。
- **DRILL-Q04**：内部 Agent 的工具集合必须为空；输入由应用层构造为最小结构化上下文，不向模型暴露 ArtifactStore、数据库、项目目录或任意读取能力。
- **DRILL-Q05**：模型不可用时既有档案、问答和 Markdown 下载仍可读；同步生成操作返回可诊断错误且允许重试，不影响其他会话。
- **DRILL-Q06**：回答属于本地敏感数据；列表只显示截断摘要，页面不得通过 URL、任务 payload、日志或遥测复制正文。

## 验收场景

1. 用户从当前画像选择项目创建档案；重复提交返回同一档案，画像版本变化后旧档案仍展示原快照。（DRILL-001,002）
2. 用户启动浅档会话并请求首题；Web 依次流式返回准备上下文、生成、校验和保存状态，最终返回一个带有效证据和覆盖维度的问题，全程不创建问题 Task。（DRILL-003,004,005）
3. 伪模型返回第一人称完整答案或要求读取源码，同步生成器拒绝结果、清理占位并允许重试，页面不展示该内容。（DRILL-006, DRILL-Q03, DRILL-Q04）
4. 用户回答后提交一次修订；两版原文都存在，新版知识项有合法偏移，旧知识项被标记为已取代。（DRILL-007,008,009）
5. 最新题摘要完成后可以生成下一题；待处理、暂停或完成状态下的非法操作被拒绝。跳过后可以继续且覆盖图不计分。（DRILL-010,011）
6. Worker 根据已提交数据生成 Markdown；重复渲染不产生不同内容，渲染失败不丢失问答，成功后可从 Web 下载。（DRILL-012,013,014）
7. 模型未配置时档案和历史问答仍可查看，同步生成直接失败并提供配置指引，其他会话不受影响。（DRILL-014, DRILL-Q05）
8. 用户完成一个会话并开始另一个会话后，可从档案顶部按最后修改时间找到旧会话；点击“继续此会话”后旧会话恢复为进行中，原进行中会话自动暂停，随后可修订旧回答或生成下一题。（DRILL-003,007,010,014）
9. 删除预览后档案发生变化，旧确认令牌失效；重新预览并确认后只删除该档案拥有的数据和未共享投影。（DRILL-015）
